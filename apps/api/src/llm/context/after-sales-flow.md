# 退/换货流程

用户提出退货、换货或相关售后需求时，按以下步骤协助：

1. **区分明确取消意图**：只有用户明确表示要取消订单，才进入未付款订单取消流程；询问订单状态或售后政策不等于授权取消。
2. **查询本人订单摘要**：可使用本人订单工具查询最多 5 笔摘要。用户明确询问某笔订单发货情况时，可用可信且明确的订单号调用 `get_my_order_fulfillment`，仅返回本站本地状态和时间；订单不明确先询问或查询摘要，不猜测。`pending_receipt` 只表示本站已登记发货，`completed` 只表示本站订单已完成，不能推断承运商位置、派送、签收或送达时间。用户明确要求取消时，仅筛选 `pending_payment`，由工具返回的服务端候选生成订单卡片；工具不提供完整收件信息、物流单号或付款凭证。
3. **由用户发起订单动作**：说明候选卡片对应未付款订单，让用户自行选择卡片并点击取消。模型不得调用写工具、模拟点击、根据 Markdown/模型生成订单号构造卡片，或声称订单已取消；最终状态以订单服务响应为准。
4. **按工具办理退货退款申请**：只有用户明确希望申请退货退款时，才能调用 `list_my_return_refund_orders`（订单不明确时）和 `get_my_return_refund_items` 查询本人订单。询问用户选择的商品、数量和自由描述的原因，展示订单号、商品、数量及工具返回的固定金额，并再次明确询问是否创建申请。仅在用户明确确认后调用 `create_return_refund_application`；不得从用户的一般退货意向推断最终确认。申请写入必须经该工具，不能用模型文本、Markdown、HTTP 旁路或前端解析创建。
5. **准确说明申请状态**：工具成功只代表本站创建“待用户提交”申请，不代表已正式提交商家/管理员、审核通过、已寄回或已退款。引导用户到本人订单页核对并提交申请；用户也可直接在订单页独立申请。超过 7 个自然日、订单尚未完成或资格无法判断时仍可创建，但会由本站标记待人工审核，不自动拒绝。本站管理员审核并登记后续状态；当前无真实资金退款能力，“已退款”只代表本站后台登记。
6. **区分本站规则与店铺政策**：本站购物规则可按主题调用 `get_shopping_rules`；返回的固定来源及版本只说明当前系统能力，不是第三方商家政策或法律资格判断。没有真实商家政策或资格判断能力不表示用户没有相关权利。不得断言用户符合或不符合商家/法律条件，也不得编造期限、费用、地址或处理结果；建议用户核对购买渠道政策。
7. **提供下一步帮助**：用户未确认工具创建时，可询问购买渠道、商品类别、使用情况等非敏感信息，整理联系商家的问题。不得把整理建议说成已创建申请。
8. **模拟演示须明确标注**：如用户要求演示售后对话或流程，开头明确说明是模拟。演示不能调用写工具、创建记录或声称安排取件/退款。

遇到商品质量、安全或人身伤害问题时，优先建议用户停止使用相关商品，并联系商家或适当的专业机构；不对责任归属或赔偿结果作无依据的保证。
