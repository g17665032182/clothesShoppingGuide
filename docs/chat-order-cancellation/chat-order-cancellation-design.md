# 聊天订单取消设计

## 状态与上下文

- 状态：已确认。
- 业务目的：用户明确提出取消订单时，在聊天中列出其当前可取消的订单，并由用户在对应订单卡片上触发取消。
- 所属应用：`apps/api`、`apps/web`；订单状态规则归属 `orders`，聊天展示归属聊天模块。
- 最后更新：2026-11-10。
- 依据：现有订单契约、本人订单工具、聊天结构化展示和本人取消接口；用户已确认沿用既有订单取消规则。

## 范围

- 只在用户明确表达取消订单的意图后查询，不因一般询问订单、退款、退货或换货而触发取消卡片。
- 使用服务端绑定当前账号的本人订单查询工具，展示尚未过期且状态为 `pending_payment` 的订单。
- 每张订单以服务端确认的结构化卡片呈现，至少包含订单号、商品及规格摘要、金额、创建时间和可取消状态。
- 用户点击某张卡片的“取消订单”按钮后，调用现有本人取消接口；取消是否成功以接口响应为准。
- 多笔符合条件的订单分别展示，由用户选择具体订单；没有符合条件的订单时明确告知，不提供取消动作。
- 继续复用现有取消确认交互，卡片按钮先进入确认步骤，用户确认后才提交取消请求。

## 用户与权限

| 角色             | 能力                                                       |
| ---------------- | ---------------------------------------------------------- |
| 启用账号用户     | 查询和取消本人符合条件的订单                               |
| 管理员           | 与普通用户相同，仅处理本人订单；不因管理角色获得代取消权限 |
| 聊天助手         | 在明确取消意图后查询本人订单并解释结果；不能执行取消写操作 |
| 未登录或禁用账号 | 不可访问聊天订单或取消接口                                 |

用户归属始终由认证上下文绑定。模型参数和客户端均不得指定 `userId`。服务端仍对取消请求执行本人归属和订单状态校验。

## 核心流程

1. 用户明确表示要取消订单。
2. 助手调用本人订单查询工具，限定查询可取消订单；工具只返回安全的订单摘要和订单标识。
3. 服务端从经过校验的工具结果生成结构化订单卡片；模型文本、Markdown 或伪造工具 JSON 不得生成可执行卡片。
4. 前端展示所有本次查询到的可取消订单。用户可选择对应订单卡片上的取消操作。
5. 复用现有取消确认弹框；用户确认后调用 `POST /api/orders/:id/cancel`。
6. 成功后按接口返回状态更新卡片并提示取消成功；冲突、失败或结果未知时重新读取本人订单状态，不显示虚假的成功状态。

查询工具当前最多返回 5 笔订单，因此聊天卡片最多显示 5 笔。用户可通过订单号或“我的订单”页面继续查找。

## 数据与状态规则

- 仅 `pending_payment` 且服务端判定未到期的本人订单可显示取消按钮。
- 已过期订单必须先按现有订单逻辑关闭并释放预占，不得继续展示为可取消订单。
- `pending_shipment`、`pending_receipt`、`completed`、`closed` 均不提供取消按钮。
- 该功能不改变订单状态机、库存释放、取消 API、幂等和事务语义。
- 取消接口冲突或读取到状态变化时，使用服务端最新状态移除取消动作并显示实际状态。
- 断网、取消请求或超时造成结果未知时，不重复创建新动作，不乐观标记已取消；通过读取最新本人订单状态恢复。

## 隐私与安全

- 工具及卡片不得包含收件人姓名、手机号、完整地址、物流单号、凭据或内部用户资料。
- 模型只可查询和说明订单；订单 ID 可作为受限引用供服务端投影及前端调用现有本人 API，不能把模型输出的 ID 直接当成授权凭据。
- 卡片数据由服务端白名单投影产生，并绑定当前账号和对应 assistant 展示消息；客户端只消费该投影。
- 订单取消成功状态只能来自取消 API 响应或后续本人订单读取结果。
- 更新 LLM 退/换货流程和系统上下文，区分“本人未支付订单取消”与未接入的退款、退货、换货及已付款取消。

## 模块边界与兼容性

- `orders` 继续拥有订单数据、本人查询、状态转换和取消业务规则。
- `chat-records`/`llm` 负责安全工具结果、可信聊天展示投影及对话边界，不直接操作订单 Entity。
- `web` 复用现有聊天订单详情、取消确认和订单 API 适配器。
- 不新增数据库实体、字段、迁移、运行时依赖或公开 HTTP 路由。
- 保持既有订单 API、我的订单页面、历史聊天展示与购买流程兼容。

## 非目标

- 已付款订单取消、退款、退货、换货或第三方售后申请。
- 助手自动取消订单、模型取消工具、管理员代用户取消。
- 按会话、商品名称或时间推测并取消订单。
- 扩大本人订单工具现有分页上限或新增跨账号检索。

## 验收清单

- [ ] 只有用户明确表示需要取消订单时，助手才查询可取消订单。
- [ ] 查询范围只能是当前登录用户；模型不能指定用户 ID。
- [ ] 仅未过期的 `pending_payment` 订单显示可操作卡片，最多 5 笔。
- [ ] 无可取消订单时不显示取消按钮，并准确说明结果。
- [ ] 模型文本或伪造工具输出不能构造订单卡片或按钮。
- [ ] 用户选择具体卡片并通过现有确认步骤后，才调用本人取消 API。
- [ ] 取消成功、冲突、过期、越权、失败和未知结果均展示真实服务端状态。
- [ ] 卡片、LLM 工具结果及专属 trace 不包含订单收件信息或物流单号。
- [ ] 原有订单取消、库存释放、聊天购买、订单页面及历史消息行为无回归。
