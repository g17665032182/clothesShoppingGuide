# 流式聊天模块设计文档

## 状态与上下文

- 状态：已确认（review 修订项全部确认）
- 业务目的：让聊天页面逐步展示大模型回复，并完成与现有聊天记录接口的前后端联调。
- 所属应用：`apps/api`、`apps/web`
- 关联模块：`chat-records`、`llm`、`auth`
- 最后更新：2026-10-28

## 范围

### 包含

- 新增 `POST /api/llm/chat/stream` 流式接口，逐段返回 assistant 回复；保留现有 `POST /api/llm/chat` JSON 接口，避免破坏仍使用旧协议的客户端。
- 前端接入真实会话列表、会话历史和流式发送，移除聊天页面的模拟数据与定时模拟回复。
- 沿用现有登录认证、聊天 DTO、会话归属和聊天记录持久化规则。
- 支持前端中止流式请求，并在页面中呈现发送中和错误状态。

### 不包含

- 不新增或修改数据库表、字段和迁移。
- 不改变会话列表、历史详情、删除和管理员查询接口的权限或分页行为。
- 不新增模型供应商、模型选择、工具调用或多模态能力。
- 不实现断线续传、后台任务、流重放或持久化部分生成内容。
- 不新增前端测试基础设施；前端以类型检查、构建和手工联调验证，自动化测试基础设施另行确认。

## 用户角色与权限

| 角色       | 权限                               |
| ---------- | ---------------------------------- |
| 已登录用户 | 发送聊天请求，查看和继续自己的会话 |
| 未登录用户 | 无权发送聊天请求或读取会话         |

继续使用现有 Bearer JWT、全局 JWT Guard 和聊天会话归属校验，不建立新的认证或授权机制。

## API 或事件契约草案

### 请求

- 新增路由 `POST /api/llm/chat/stream`；原有 `POST /api/llm/chat` 和 JSON 响应保持不变。
- 请求体沿用现有聊天 DTO，包括 `messages` 和可选 `conversationId`。
- 请求使用 Bearer JWT。

### 响应传输

- 成功请求使用 UTF-8 `text/event-stream`，按标准 SSE 帧逐段传输。
- 因请求需要 POST JSON body 和 Authorization Header，浏览器端使用 Axios Fetch adapter 的 `responseType: 'stream'` 读取，不使用原生 `EventSource`。
- Axios 请求通过现有 API 请求层发送，以复用 Bearer Token、401 刷新和统一错误处理；SSE 帧解析封装在聊天 API 模块，不放在页面组件中。
- 事件载荷草案：

| 事件    | 数据                                                                     | 用途                             |
| ------- | ------------------------------------------------------------------------ | -------------------------------- |
| `start` | `{"conversationId":"uuid","title":"标题"}`                               | 模型调用前返回本轮目标会话元数据 |
| `delta` | `{"content":"增量文本"}`                                                 | 按顺序追加 assistant 回复        |
| `done`  | `{"conversationId":"uuid","title":"标题","model":"模型名","usage":null}` | 表示生成和记录保存均已完成       |
| `error` | `{"message":"可公开的错误信息"}`                                         | 响应开始后报告可恢复展示的错误   |

- `start` 对新会话只预生成并返回 ID 和标题，不提前创建数据库记录；已存在会话返回其现有元数据。
- `done` 中的 `usage` 保留现有响应语义，模型未提供用量时为 `null`。
- 认证、DTO 校验、会话归属检查和其他可在生成前完成的业务校验必须在发送响应头和 `start` 事件前完成；错误继续使用 HTTP 状态码及现有 JSON 错误格式。
- 响应开始后无法再更改 HTTP 状态码；错误通过 `error` 事件报告，不暴露上游原始异常、密钥、Prompt 或数据库详情。

### 失败、取消和持久化

- 模型生成期间，已收到的增量内容只在前端临时展示，不写入数据库。
- 模型完整生成后，在一个事务中保存本轮 user/assistant 消息；事务成功后才发送 `done`。
- 模型调用失败或在持久化事务开始前观察到取消时，不保存本轮 user/assistant 消息。
- 保存失败时发送 `error`，不得发送 `done`；前端应将本轮标记为未成功保存。
- 事务开始后若客户端断开，数据库提交与网络断开可能竞速；服务端不承诺断连必然回滚已开始的事务。若事务已经提交但客户端未收到 `done`，客户端将结果标记为“状态未知”，不得自动重发；通过 `start` 返回的会话 ID 重新读取历史以核实结果。
- 客户端中止请求时，服务端尽可能中止模型生成；供应商是否即时停止处理或计费取决于其能力。

## 前端行为

- 页面加载时请求当前用户的会话列表；选择会话时请求真实历史消息。
- 新建会话时清空当前消息；首条消息成功后以服务端返回的 ID 和标题更新页面及侧栏。
- 发送消息时立即展示用户消息和空 assistant 占位，收到 `delta` 后持续更新占位内容。
- 收到 `done` 后将 assistant 消息标记完成并刷新或更新会话列表。
- 收到 `error`、HTTP 错误或网络中断时保留已收到文本作为未完成的临时展示，不将其合并进后续请求历史或正式消息缓存。
- 持久化开始后的断连若未收到 `done`，标记为“状态未知”，不自动重发；使用 `start` 提供的会话 ID 刷新详情，确认本轮是否已保存后再允许继续。
- 用户切换会话或离开页面时取消仍在进行的请求，避免旧响应写入新会话。
- Axios 流式请求沿用 API 请求层已有的认证刷新行为。
- API 层字符串 UUID 和 ISO 8601 时间通过显式映射适配页面视图模型；不把现有 mock 的数字 ID 或展示用时间字段当作服务端类型。

## 模块边界

- `LlmModule` 负责复用现有模型配置并提供增量生成能力，不访问聊天记录数据库。
- `ChatRecordsModule` 继续负责上下文准备、会话归属、完整成功后的记录保存和响应元数据。
- 前端 `src/api/modules/` 负责聊天 REST 与流式 API 适配；页面级状态留在 `src/pages/chat/page.ts`。
- 流式传输不引入新的 Entity、DTO 所有权或共享全局状态。

## 验收清单

- [ ] 新流式接口与旧 JSON 接口并存，旧接口响应不变。
- [ ] 用户回复以增量形式显示，而不是等待完整模型响应。
- [ ] 真实会话列表和历史消息可加载、选择和继续对话。
- [ ] 新建会话在首轮成功后正确获得服务端 ID 和标题。
- [ ] 流正常结束后，用户消息和 assistant 完整回复均可从历史接口读取。
- [ ] 校验、认证和越权错误保持现有 HTTP 行为；流开始后的错误按事件契约展示。
- [ ] 持久化事务开始前取消不会写入；事务已提交但 `done` 未送达时可通过会话 ID 核实结果，且不会自动重复发送。
- [ ] 请求取消后旧流不会继续修改当前页面状态；未完成文本不会进入下一轮上下文。
- [ ] 前端 UUID 与 ISO 时间字段通过页面适配层转换。
- [ ] 不新增数据库迁移，原聊天记录及管理员接口行为不变。
- [x] 不引入未确认的前端测试基础设施；已完成类型检查和构建，手工联调结果记录在实施文档。
