## 目标

统一对话、消息和输入体验，让用户能查看本轮工具执行过程、公开推理摘要、上下文用量及回答来源。展示必须依赖真实数据，并保留现有会话管理、权限、流式回复、Markdown 和异常处理能力。

主要用户是使用穿搭顾问的登录用户。管理员继续沿用已有聊天记录只读权限，本期不新增管理员调试页面。

## 页面与交互

### 页面布局

- 保留会话侧栏、对话标题和底部输入区，整理其桌面与移动端布局。
- 消息区域采用 Chat 模式，用户消息使用 Message + Bubble，助手消息使用 Message。
- AI 回复按“执行过程、正文、来源、生成用时”组织；没有数据的区域隐藏。
- 输入框底部工具栏放置 Context 和发送/停止按钮；Context 不等同于用户偏好或 Markdown 记忆。
- 不将工具活动、来源和消息正文分别重复渲染为多份内容。

### 消息与输入

- 回复按收到的文本增量追加，保持顺序；工具参数和推理摘要不得混入正文。
- 保留安全 Markdown 渲染、表格和代码块；长表格、长链接和代码在窄屏下不能撑破布局。
- Enter 发送，Shift+Enter 换行；中文输入法候选词确认时不误发送。
- 输入框保留现有字数限制与重复提交保护；生成期间提供明确的停止按钮。
- 用户停留在最新位置时跟随回复；向上阅读时保持阅读位置，提供回到最新消息的按钮。
- 时间分隔和生成用时继续展示，生成总耗时不标为“思考用时”。

### Context

- 以最近一轮最终模型调用的输入与输出 Token 为统计口径，不累计历次请求或工具循环内的多次模型调用。
- 窗口上限来自该轮服务端配置，不在前端猜测；历史记录恢复该轮保存的上限。
- 输入和输出 Token 均已知时计算总用量和占用百分比；缺失字段显示“暂无数据”，不替换为零。
- 当前轮生成时保留最近已完成轮次的统计，明确其归属；收到当前轮完成数据后再更新。
- 支持桌面悬停、键盘操作和手机点击查看详情，不能依赖鼠标悬停作为唯一入口。
- 没有历史用量时使用“上下文用量暂无数据”状态；模型窗口未知时不展示百分比。
- 此数值代表最近模型调用的用量，不承诺精确预测下一轮输入，也不与费用统计混用。

### Tool 与 Chain of Thought

- Chain of Thought 展示本轮实际发生的步骤数量及整体状态，展开后查看 Tool 或公开推理摘要。
- 工具调用与结果通过稳定调用 ID 关联，结果更新原步骤，不重复新增“完成”步骤。
- 工具项显示名称、执行中/成功/失败/未完成状态，展开查看安全参数和结果。
- 工具详情采用显式展示白名单；未配置展示规则的工具仅展示安全名称、状态和占位提示。
- 工具失败显示可公开的错误摘要，完整堆栈留在服务端日志。
- 过程总览在步骤执行期间默认展开、结束后默认收起；用户手动设置的展开状态优先保留。
- 取消、断流或本轮失败后，仍在运行的步骤变为未完成状态，不能永久显示执行中或误标成功。
- 无工具和公开推理摘要时隐藏总览；等待回复的普通加载提示不计为真实执行步骤。

### Reasoning

- 只接入供应商明确给出的公开 reasoning summary，支持同一摘要的后续更新。
- 不要求模型生成额外“思考过程”，不提取原始 `reasoning_content`，不根据正文编造步骤或推理摘要。
- 有摘要才展示，并作为过程总览中的可折叠步骤；无摘要不显示空面板。
- 尚未确认供应商是否支持公开摘要，技术阶段核验；不支持时隐藏此区域，其他对话功能正常。

### Sources

- 放在对应 AI 回复下方，以可折叠列表展示来源标题、网站和外部链接。
- 来源由工具的真实检索结果或供应商结构化引用提供，并归属于本轮回复。
- 不把正文中的任意链接自动解释为已参考来源，不从普通文本中生成或猜测来源。
- 同一轮的相同有效 URL 去重；按首次出现顺序展示。稳定来源 ID 用于后续更新与历史恢复。
- 服务端仅接收合法的 HTTP/HTTPS 外部链接，拒绝其他协议和包含用户名密码的 URL。
- 链接在新页面打开，并提供外链提示；Sources 不自动抓取或预览链接内容。
- 没有真实来源时隐藏整个区域。模拟商品和虚拟操作不能包装为真实商品来源。
- 本期不增加正文中的行内引用标记或引用编号映射。

## 状态、取消与恢复

| 状态               | 用户看到的内容与可执行操作                           |
| ------------------ | ---------------------------------------------------- |
| 新会话空数据       | 穿搭主题空状态与可用输入框                           |
| 历史加载中         | 明确的加载状态，阻止重复发送                         |
| 历史加载失败       | 错误提示和重试入口                                   |
| 已发送、尚无回复   | 等待提示、生成用时和停止按钮                         |
| 正文或过程生成中   | 按顺序更新本轮正文、活动与来源，保持可阅读的滚动位置 |
| 成功保存           | 完成本轮，恢复发送，历史可恢复相同的展示数据         |
| 模型或工具失败     | 保留已收到内容作为临时展示，显示失败并结束运行状态   |
| 用户停止           | 中止请求并标记未完成，提示核实保存状态               |
| 断连且保存状态未知 | 提供刷新核实，不自动重发，核实前阻止继续发送         |

- 切换会话、新建会话和卸载页面时取消当前请求，忽略旧请求后续返回的数据。
- 正式保存以服务端事务提交为准，唯一 `done` 事件在提交成功后发送。
- 未完成的正文、活动与来源只用于当前页临时展示，不作为成功记录或下一轮正式上下文。
- 旧历史没有新增元数据时，正常展示原正文，不生成虚假的过程、来源或百分比。

## API 与数据边界

- 继续使用现有聊天路由、请求体、JWT 认证和 Axios 请求底座；不新增客户端系统指令或工具执行参数。
- 复用 SSE 的 `start`、`delta`、`done` 和 `error`，拟增加结构化 `activity`、`sources` 事件及上下文元数据。
- `activity` 以稳定 ID 更新单条工具/公开摘要；`sources` 发送本轮来源列表完整快照，前端替换该轮列表。
- `start` 提供服务端窗口上限，`done` 提供当前轮最终调用的上下文用量。
- 历史消息拟增加 `activities`、`sources` 和 `context`，与已保存的 assistant 消息 ID 绑定。
- 拟复用最后一条模型 trace 的 `payload.publicDisplay` 保存独立展示元数据，与消息同事务提交，不直接公开内部 trace。
- 复用现有存储的容量、字段关联和查询可行性在技术阶段验证；若必须改 Entity 或 Migration，先回到设计和契约确认，不在实现中临时扩展。
- 普通用户只能读取自己的会话；管理员沿用原只读权限。越权或不存在统一返回 404。
- 历史读取先验证会话权限，再为当前页消息读取并过滤展示元数据；用户消息和旧记录使用空活动、空来源及 null 上下文。
- 系统指令、记忆全文、密钥、内部错误及供应商原始响应均不得公开；实时和历史使用同一套公开展示规则。

## 模块职责

- 前端页面组合 AI Elements，负责页面状态、展示和基础交互，不解析供应商原始对象。
- 前端 API 模块负责请求、SSE 解析和响应类型，保留既有认证与重试规则。
- LLM 模块负责模型与工具运行事件、文本增量及供应商数据标准化，不访问页面状态或数据库。
- 聊天记录模块负责会话归属、公开展示投影、消息与元数据事务保存及历史读取。
- 优先复用本地依赖和官方组件；具体组件安装、类型和目录拆分留在技术文档中确定。

## 验收清单

- [ ] 对话、消息和输入区域按本设计迁移，现有会话操作正常。
- [ ] 文本是真实增量输出，正文不会混入工具参数或原始推理内容。
- [ ] Enter、Shift+Enter、中文输入法、字数限制和重复提交保护正常。
- [ ] 流式跟随、向上阅读与回到最新消息在桌面和手机上正常。
- [ ] Context 使用最终一次模型调用口径，正确处理缺失用量、真实零值及历史窗口上限。
- [ ] Tool 状态和结果按同一 ID 更新；失败、取消及断流后没有残留运行状态。
- [ ] Chain of Thought 仅统计真实步骤，不与 Tool 和 Reasoning 重复展示。
- [ ] Reasoning 有公开摘要时展示，无数据时隐藏，生成耗时命名准确。
- [ ] Sources 只使用真实结构化来源，支持去重、合法链接、外链提示和无数据隐藏。
- [ ] 成功消息能恢复活动、来源和上下文；旧记录及用户消息兼容新增字段。
- [ ] 已完成回复和临时失败内容的状态明确，未知保存状态不会触发自动重发。
- [ ] 旧请求不能覆盖切换后的会话；取消时清理请求、监听器和定时器。
- [ ] 普通用户、管理员及越权边界保持原约定；实时和历史展示均不泄露内部信息。
- [ ] 桌面、移动端、键盘及基础无障碍验证通过，Markdown、长表格和代码无布局溢出。
- [ ] 实现阶段完成针对性后端测试、仓库检查和浏览器验证，如实记录限制。
