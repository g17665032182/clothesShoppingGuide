## 开发流程总览

按“前端公开数据需求确定接口边界，后端提供真实事件与历史，主代理完成联调”的顺序实施：

1. 核对当前工作区、依赖、文档审批与验证基线。
2. 主代理确定模块公开类型、组件输入输出和文件所有权。
3. 先验证模型流背压、JSON 查询和事务绑定可行性，补齐必要 UI 基础组件。
4. 三组子代理分别实现模型流、公开投影与存储、前端展示。
5. 主代理接入 SSE、消息事务、历史查询及页面状态。
6. 完成针对性测试、仓库检查、数据库验证和浏览器联调。
7. 按实际证据更新验收与交付记录，报告未验证事项。

不改变已确认范围：纳入 Chat、Message、Prompt Input、Context、Tool、Chain of Thought，以及有真实数据才展示的 Reasoning、Sources。Confirmation、Plan、Stack Trace 不纳入；不新增模型选择、搜索服务、工具审批、附件、语音或真实购买。

普通用户仅访问自己的会话，管理员沿用只读权限。复用现有 JWT、角色控制、Axios 认证底座、Zod schema 与 Nest 标准校验 Pipe。静默记忆提取及其他业务保持原有职责。

## 阶段一：基线、接口与可行性

负责人为主代理；必要的模型流、存储验证可在分配明确测试文件后交给 A、B。

- 保存 `git status` 和相关文件差异基线，区分已有变更与本次变更；不改无关内容。
- 核对现有脚本，运行后端测试、前后端类型检查与构建基线，记录原有失败。
- 确定公开 ChatActivity、ChatSource、ChatContextUsage 与内部 LLM 运行事件；内部结果须能定位本轮最终 model_response，不能暴露原始 Graph state。
- 确定页面 ChatMessage 视图类型、生成终态、组件 Props/Emits，确保活动和来源可先于正文到达。
- 对 LangGraph 慢消费者场景设计受控测试，确认积压受限、取消可停止上游；不能以 HTTP drain 通过代替队列有界证据。
- 在受控本地/测试数据库核验嵌套 JSON 条件、字段投影、最终 trace 行锁和同事务回滚；不执行 migration:fresh。
- 核对当前供应商已验证的公开摘要和引用结构。没有证据时记录“不支持或未验证”，保持隐藏，不通过更换模型 API 或添加检索工具补齐。

本阶段出口：类型和组件边界明确，背压及无迁移存储方案具备实施证据。若关键可行性不成立，暂停依赖它的接线，按停止条件修订方案；不得绕过约束继续完成表面 UI。

## 阶段三：分组开发与交接

以下三组在类型边界和所需基础组件准备好后可并行。子代理完成一个可集成结果后立即报告，不等待全组结束才发现接口不一致。

### A：模型流

- 保留现有 Graph 拓扑、ToolNode 和 trace 顺序，新增类型化流入口，旧字符串包装与 JSON invoke 调用继续可用。
- 模型正文使用真实 chunk；只接收明确的正文内容块，不将工具参数、未知 text 属性或原始 reasoning 作为正文。
- 完整工具调用 trace 成功写入后才能报告 running、执行工具；结果 trace 保存后更新同 ID 活动。
- 工具失败结束本轮，未完成步骤统一 interrupted，不误发 done。
- 返回最终调用 usage 和准确 trace 标识；不回退到工具循环中早先的用量。
- 流式展示正文严格等于所有 delta 拼接，包含工具调用前的可展示引导文本；最终消息不重复发送。
- 证明第一片正文先于模型结束到达，并覆盖工具循环、异常、取消、慢消费者及旧调用入口回归。

交给主代理：内部事件和结果类型、运行时顺序、背压与取消证据、已验证供应商能力清单。

### B：公开投影、存储与历史

- 在 display 能力中提供统一实时/历史投影；未知工具和本地回显工具不公开原始入参及结果。
- Sources 只接受真实结构化候选，校验 URL、去重并保留稳定 ID；不从正文提取、不抓取网页。
- 仅接受明确公开 summary 的受支持结构，没有适配证据时返回空活动。
- 验证 16,384 字节 publicDisplay 预算，以及合并后 payload 的 32,768 字节上限；超限安全失败，不静默丢弃历史。
- 提供接收事务 EntityManager 的绑定能力，禁止内部另开与消息脱离的事务。绑定至准确最终 trace，保留 LangChain messageId。
- 调整幂等比较，仅隔离 model_response 的自有 publicDisplay，其他字段仍严格比较；重复绑定一致则幂等，不一致则冲突。
- 提供限定当前会话和当前页 assistant ID 的批量 reader；无效或旧元数据降级，不能回传任意 payload。
- 证明元数据不会进入模型历史，覆盖权限接线预期、绑定冲突、回滚、预算和查询条件。

交给主代理：投影/容量检查入口、事务绑定方法、批量读取方法、错误行为、SQL 与测试证据。权限检查仍由 ChatRecordsService 在读取前执行。

### C：前端展示

- 使用 Message Scroller 统一滚动，移除重复 scrollIntoView；用户向上阅读时保持位置，支持回到最新与向前分页保位。
- 助手消息按执行过程、正文、来源、用时组合；步骤只渲染一次，无数据区隐藏。
- Tool/Reasoning 组成 Chain of Thought，总览与内部展开状态保留用户选择；失败与 interrupted 有明确文字。
- Prompt Input 使用 InputGroupTextarea，保留 2000 字限制、Enter/Shift+Enter、IME 和发送/停止。
- Context 使用共用详情的 Hover Card/Popover，支持悬停、点击、键盘与触屏；null 不当作零，显示统计归属。
- 来源使用安全外链和纯文本标题；代码、表格及长 URL 不撑破窄屏。
- 组件显式声明 TypeScript Props/Emits，不修改 Props，不自行请求 API，不把局部展开状态放到全局。

交给主代理：组件接口及组合说明、响应式/键盘检查结果、需要页面提供的状态。示例数据只用于受控验证，不进入正式页面数据源。

## 阶段四：主代理集成

主代理按依赖顺序完成以下接线：

1. 注册 display 相关能力，将 LLM 内部流接入 chat-records，不引入反向业务依赖。
2. prepare 固定本轮窗口快照；把规范化运行事件交给投影器，经安全和预算检查后生成公开 SSE 事件。
3. 改造控制器的事件序列化，完整覆盖 start/delta/activity/sources/done/error；保留预校验、背压、取消及监听器清理。
4. 将消息、publicDisplay 绑定和记忆任务沿用同一消息事务；事务成功后才发送唯一 done，提交后断连不误删。
5. 历史先检查会话权限，再查询消息和当前页展示投影；旧记录、用户消息与无效元数据正常降级。
6. 更新 Axios API 模块的运行时解析、兼容旧字段、分页参数与 signal；保留既有认证刷新机制，不自动重试未核实的 POST。
7. 更新 `page.ts`、`chat-turn.ts` 和 `index.vue`，衔接临时占位、同 ID 替换、sources 快照、统一终态和计时清理。
8. 将请求版本保护覆盖主流、历史、分页及 `refreshUncertainTurn` 的回调、catch、finally；旧请求不得修改新会话。
9. 加载最新消息页并支持向前增量加载，验证超过 100 条历史、跨页一轮和页数变化；done 后刷新失败仍保留成功状态。
10. 更新 Swagger 的响应说明和事件样例，校验现有请求 schema 与 HTTP 错误行为；不放宽角色、字段和长度限制。

Context 只采用最终模型调用及该轮保存的窗口。生成中保留上个已完成轮次并注明归属，不能跨会话残留。

停止或断流未收到 done 时进入待核实。发现确切已保存结果才恢复历史；空结果或同文本不能单独证明运行状态。缺少可靠关联证据时保留待核实，不新增状态路由、自动重发或轮询来隐式扩大范围。

## 阶段五：测试与真实路径验证

先完成对应风险的定向测试，再运行全量检查；无代码变化、失败或新增疑点时不重复执行相同全量检查。

### 自动化与数据库

- 运行 A、B 的模块测试及主代理的服务/HTTP 测试，覆盖实际 Nest schema 绑定、400 边界、401/403/404、标准异常和安全输出。
- 覆盖 SSE 分帧、唯一 done、error 终止、未提交不成功、提交与断连竞速，以及真实增量正文和存储正文一致性。
- 使用受控事务数据验证消息与 publicDisplay 原子性，绑定失败时无半成品消息，既有内部 trace 按契约保留。
- 检查分页 JSON 查询生成 SQL、返回字段与查询次数；用大样本执行计划判断是否存在不可接受扫描。需要新索引时回设计审批。
- 使用确定性的 Fake Model 和工具验证完整 HTTP/数据库路径；覆盖工具调用、trace、结果反馈、公开活动、历史恢复和下一轮模型历史重建。
- 覆盖多字节预算边界、工具详情脱敏、公开摘要过滤、Sources URL 与稳定 ID，以及 Context 的 null/零值/最终调用口径。

数据库验证仅使用受控本地/测试环境及专用测试记录，不清空用户数据库。若数据库不可用，明确标记阻塞，不能把纯测试替身结果当作真实事务验证。

### 浏览器联调

使用现有浏览器能力或人工联调，不安装 Vitest、Vue Test Utils、Playwright，也不新增前端测试脚本。开发服务优先复用已运行且健康的实例；确需启动时检查端口，使用空闲端口并报告地址，不终止无关进程。

| ------------------------- | ------------------------------------------------------------------ |
| 新会话、会话切换与删除    | 空/加载/失败状态完整；侧栏分页正常；无旧响应污染                   |

## 风险与停止条件

| 条件                                              | 处理要求                                                                                 |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Graph custom 流在慢消费者下持续无界积压或无法取消 | 停止流接线，核验库的等价流能力；涉及方案变化先更新技术文档，不能只靠 HTTP drain 宣称解决 |
| 现有 JSON 存储无法保证绑定、事务或查询成本        | 停止存储接线；需要 Entity/索引/Migration 时回设计及契约审批                              |
