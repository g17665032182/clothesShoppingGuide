## 角色与权限

| 操作                             | 启用管理员                  | 启用普通用户       | 禁用账号/访客 |
| -------------------------------- | --------------------------- | ------------------ | ------------- |
| 查看商品管理页                   | 允许                        | 不允许             | 不允许        |
| 查看商品精确库存                 | 允许                        | 不允许             | 不允许        |
| 查看全部订单                     | 允许                        | 不允许             | 不允许        |
| 查看订单收货/物流详情            | 允许                        | 仅本人订单接口允许 | 不允许        |
| 整单发货                         | 允许，仅 `pending_shipment` | 不允许             | 不允许        |
| 改价、取消、代付、退款、商品写入 | 不提供                      | 不提供             | 不提供        |

复用现有 JWT Guard、`adminOnly` 路由 meta、后端 `RolesGuard` 和 `@Roles(UserRole.ADMIN)`。前端路由拦截只改善体验，后端权限仍是最终边界。

## 页面结构

### 管理员布局

管理员专用布局 `/admin` 复用现有应用外壳，并提供管理导航，包含：

- 用户管理
- 商品目录
- 订单履约

不把用户、商品、订单三类数据混成一个大型首页；每个领域保持独立页面和独立 `page.ts`。

### 商品页

- 顶部标题、当前结果数量和刷新按钮。
- 筛选栏：关键字、分类、商品状态、库存状态、分页。
- 表格：商品名称、外部 ID、品牌、分类、SKU 数量、最低价、库存概览、状态、查看详情。
- 详情侧栏或对话框：商品描述、链接、全部 SKU 的颜色、尺码、价格、精确实物库存、可售状态和 SKU 启用状态。
- 商品页只读，不渲染编辑、上下架或库存写入按钮。

### 订单页

- 顶部标题、结果数量和刷新按钮。
- 筛选栏：订单号、用户 UUID、订单状态、分页。
- 表格：订单号、买家 ID、状态、金额、商品数量、创建时间、支付/发货时间。
- 详情侧栏或对话框：商品快照、数量、收货信息、物流信息、金额和状态时间线。
- `pending_shipment` 订单显示“整单发货”按钮；其他状态只显示只读信息。
- 发货表单使用快递公司和运单号两个字段，沿用现有 Zod 契约，提交时显示 Spinner 并禁用重复提交。

## API 设计

订单页面复用现有接口：

- `GET /api/admin/orders`
- `GET /api/admin/orders/:id`
- `POST /api/admin/orders/:id/ship`

商品页面需要新增只读管理员接口：

- `GET /api/admin/product-catalog/products`
- `GET /api/admin/product-catalog/products/:id`

商品管理员接口返回精确库存；普通商品查询和 SKU 查询接口继续保持不公开精确库存的规则。新增接口不改变商品导入 CLI、聊天查询和订单库存协作。

## 数据与状态

- 页面请求状态分别维护 `idle`、`loading`、`success`、`empty`、`error`。
- 发货动作另维护 `submitting`、`success`、`error`，成功后重新读取当前详情和列表。
- 切换筛选或分页时，旧请求不能覆盖新请求；页面卸载时取消或忽略过期响应。
- URL 查询参数保存当前列表筛选和分页，刷新页面后可恢复视图。
- API 响应类型放在 `apps/web/src/api/types/`，请求封装放在 `apps/web/src/api/modules/`。

## 组件与交互约定

- 页面主文件只组合结构和事件绑定；请求、筛选、分页、详情和发货逻辑放在 `page.ts`。
- 页面私有组件放在各自 `components/` 目录。
- 表格、Badge、Button、Dialog/Sheet、Pagination、Alert、Empty、Skeleton 复用现有 shadcn-vue 组件。
- 操作按钮使用语义化 Button 和 lucide 图标；发货是明确的文字+图标操作，刷新使用图标按钮并提供 tooltip。
- 详情弹层必须包含可访问标题；表格提供 caption 和键盘可达操作。

## 非目标与兼容性

- 不新增数据库表或商品实体字段。
- 不修改订单状态机；发货仍由后端事务完成库存扣减和状态转换。
- 不把管理员页面接入 LLM、聊天工具或真实支付。
- 不在前端直接读取后端 Entity，所有字段通过 API 类型投影维护。
