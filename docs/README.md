# 项目文档

项目文档统一收纳在 `docs/`，按五类组织。环境准备与启动见[项目 README](../README.md)，仓库开发约定见 [AGENTS.md](../AGENTS.md)。

Agent 首次接手先读 [Agent 项目速读](./development/agent-guide.md)：项目链路、任务对应源码、业务边界和验证证据入口。需要追溯方案时再展开下方业务阶段文档。

```text
docs/
  README.md       文档总入口
  product/        产品级需求
  modules/        全部业务模块的需求、设计、技术、实施与相关素材
  contracts/      API、字段、权限与兼容契约
  development/    前端、后端、安全与验证规范
  testing/        跨模块验证计划及执行记录
```

## 阅读与维护

- 同一业务的 PRD、设计、技术和实施记录集中在 `docs/modules/<业务名>/`，相关测试素材随业务保留；资源契约和跨模块规范统一放在对应分类目录。
- PRD 记录需求范围，`*-design.md` 记录业务设计，`*-technical.md` 记录技术方案，`*-implementation.md` 记录实施安排及实际交付证据。目录中存在文件不表示已审批、已实现或已验证。
- 先读当前契约和对应增量，再结合源码、实施记录及带日期的复测结果判断状态。历史 PRD、设计和旧检查清单不能单独作为当前完成度依据。
- 保留历史审批、失败及受阻记录；后续复测按日期追加证据，不将局部通过改写为全量验收通过。
- 新增或迁移文件时，同步维护所属分类索引和仓库内引用；业务阶段文档通过业务模块索引查找。
