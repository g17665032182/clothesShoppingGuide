# 长期背景与偏好维护边界设计

## 状态

- 状态：需求、设计和技术方案已确认；实施文档待确认，尚未实施。
- 关联契约：[用户记忆](../contracts/user-memory-crud-contract.md)、[用户偏好](../contracts/user-preferences-crud-contract.md)。
- 确认记录：用户于 2026-11-05 回复“确认”批准设计规则，随后回复“可以”批准技术方案；当前实现尚未变更。

## 目标与范围

- 结构化偏好仅由用户本人维护，LLM 仅在聊天时读取并参考，不从对话自动新增、修改或删除结构化偏好。
- 长期记忆仍是独立、开放的 Markdown 文档，不依赖结构化偏好类别；允许从对话提取与服装选择有关的长期背景，包括时间或时段规律、季节、地点或气候、爱好和活动等，不限于这些例子。
- 用户仍可独立查看、编辑或清空自己的记忆；记忆提取不写入结构化偏好，用户管理偏好不自动改写记忆。
- 用户当前明确需求优先于长期信息；不得将助手猜测、设备/IP 位置或未经用户明确表达的信息当作用户事实。既有敏感信息限制保持。

## 已确认规则

1. 只把用户明确表达且长期或反复适用的信息写入长期记忆；单次出行地点、日期、天气和活动只作为当前对话条件。
2. 保留已有结构化偏好和来源，不再产生新的自动偏好任务；尚未完成或正在执行的旧任务停止写入，历史任务保留用于兼容和排查。
3. 保留偏好开关，将其作用调整为仅控制聊天时是否注入用户维护的偏好；关闭不删除数据，也不阻止用户手动维护。

## 验收方向

- 用户手动维护偏好后，可在开启偏好参考时用于后续聊天；聊天和后台任务不得改写结构化偏好。
- 明确、长期或反复适用的穿衣相关背景可以进入自由 Markdown 记忆，不要求映射到固定偏好类别；不凭提示词测试单独宣称真实模型提取成功。
- 长期记忆和结构化偏好各自遵守其独立设置、用户隔离与管理权限；不删除历史偏好或聊天记录。
- 历史和并发任务、现有接口兼容、前端开关语义和相关测试在技术与实施阶段明确。
