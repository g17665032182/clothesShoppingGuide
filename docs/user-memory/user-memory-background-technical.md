# 长期背景与偏好维护边界技术方案

## 状态与范围

- 状态：技术方案已确认；实施文档待确认，尚未实施。
- 依据：[设计](./user-memory-background-design.md)、[记忆契约](../contracts/user-memory-crud-contract.md)、[偏好契约](../contracts/user-preferences-crud-contract.md)。
- 确认记录：用户于 2026-11-05 回复“可以”批准本方案。
- 不新增类别、API、数据库字段或依赖；保留当前用户隔离、授权和两个独立开关。
- 范围包括停止自动偏好写入、让手动偏好可作为聊天参考、扩充长期记忆提取提示及验证其读取。历史聊天不自动重放，不保证模型一定生成候选。

## 本地基线与参考

- `ChatRecordsService.persistChat` 当前分别登记偏好与记忆任务；偏好调度器每秒领取任务，调用模型并写入 `user_preferences`。
- `UserPreferenceReaderService` 当前读取用户偏好并受设置控制；前端开关仍显示“自动偏好”。
- `UserMemoryExtractorService` 使用现有生成端口、Zod 补丁 schema 和 Markdown 文档；`section=clothing/other` 仅是内部追加位置，不是用户偏好类别。
- `UserMemoryReaderService` 当前只做文本字面匹配；中文整句搜索和地点/爱好与“推荐衣服”缺少共同词时可能不返回相关背景。
- 复用 NestJS 12.2、MikroORM 7.2.5、PostgreSQL 17、Zod 及现有 API 与测试栈。已核对 PostgreSQL 17 锁文档和 Nest 生命周期文档；Nest 信号关闭钩子依赖启动时启用，不能只凭进程发信号推定任务已停止。
- 参考：`https://www.postgresql.org/docs/17/explicit-locking.html`、`https://docs.nestjs.com/fundamentals/lifecycle-events`。

## 偏好写入与切换

1. 聊天持久化只登记记忆任务，移除偏好任务的公开入队端口和注入；不影响记忆任务失败隔离。
2. 偏好模块不再注册自动提取调度器和执行器，不领取、恢复、重试或应用旧偏好任务；手动 CRUD 和偏好读取继续使用原有领域锁。保留历史任务、结果实体及表，不新增迁移或改变既有状态，不将历史 `pending` 标成已完成。
3. 调整删除全部偏好的实现，不再删除未完成的历史任务；保留用户偏好本身的既有删除语义及所有任务记录。来源会话删除仍沿用原有偏好来源状态处理。
4. 切换必须先停掉所有旧版 API/worker 并确认其进程和数据库中偏好写入事务均已结束，再启动新版；旧实例与新版不得混跑。新版本启用后旧任务不再运行，但若重新启动旧版仍可能写入，因此回滚必须保持旧版 worker 停用或先实施经过验证的独立写入阻断方案。本方案不声称通过部署新代码即可阻止仍在运行的旧进程。
5. 任何偏好在切换完成之前由旧进程提交的写入不自动回滚；历史偏好、来源、任务和结果保留。停机窗口或部署失败时不启动混合版本；不执行 `migration:fresh`。

## 开关与接口

- 原 `GET/PATCH /api/preferences/settings` 路由、认证、响应及 `enabled` 字段保持；`enabled` 只控制偏好上下文注入，手动 CRUD 不受开关影响，旧值沿用，不重新开启用户设置。
- `updatePreferenceSettingsSchema` 继续使用 `z.strictObject({ enabled: z.boolean() })`，输入与输出均为布尔值；缺失、非布尔或未知字段由现有 Nest `StandardSchemaValidationPipe` 返回 400，DTO 只负责 Swagger 文档。其余偏好 CRUD schema、权限与错误约定不变。
- 前端将“自动偏好”调整为“参考我的偏好”，保留现有加载、失败及提交状态；“自动记忆”及其设置不变。
- 历史来源字段继续展示；聊天中自然语言只修改 Markdown 记忆，不写结构化偏好。当前消息优先于结构化偏好，结构化偏好优先于 Markdown 记忆。

## 记忆提取与读取

- 更新记忆提取系统提示：开放文本可记录明确且长期或反复适用、影响服装选择的时间规律、季节、城市/地区和气候、活动与爱好等，不需要映射到结构化偏好类别；可以记述与偏好内容重合的自然语言事实，但不能输出结构化偏好操作或直接修改偏好。
- 单次事件、临时地点和天气不得升级成长期事实；助手和模型推断、设备/IP 位置不作为用户事实。仅允许粗粒度城市/地区；现有敏感信息过滤继续拒绝详细地址及其他敏感信息，不放宽安全 schema。
- 保留 `append/replace/delete`、幂等、用户编辑、generation、租约、安全校验、七牛存储及 5 分钟/离页 flush 语义，不更改候选格式或记忆 API。
- 当前仅按消息原词命中 Markdown 的实现不足以保证背景被参考。拟在 `UserMemoryReaderService` 中，对明确的服装/穿搭/购物推荐意图，增加有限的穿着背景线索匹配：在已有段落中识别地点、气候、季节、时段、活动和爱好等描述并参与相关性排序；普通非穿搭请求不启用此补充。保持仅选择相关段落，不全量注入文档，沿用字数上限、顺序和聊天整体 token 预算。具体规则必须提供正反例并限制误召回；固定线索不能保证任意自由表达都被识别，不能宣称语义检索。
- 已成功完成的历史记忆任务不自动重新提取；新规则仅对部署后领取、尚未生成候选的任务及后续聊天生效；已缓存候选按既有幂等重试规则处理。

## 验证方案

- 偏好：手动创建、编辑、删除、关闭参考后仍可管理；开启时读取，关闭时不注入；聊天成功后只创建记忆任务，偏好任务数不增加，模拟模型输出不得修改偏好。
- 部署：专用 PostgreSQL 测试创建 pending、failed、processing 和已有结果；确认新实例不领取、不恢复、不更改且不删除历史任务；验证旧 worker 停止/旧事务结束后切换，拒绝混跑与不安全回滚；手动编辑及删除全部不清理历史任务。
- 记忆：生成端口 fake 验证提示与批次输入、时间地点爱好候选成功应用、重复及敏感内容过滤、旧候选重试和关闭/清空保护；提示测试不能证明模型语义可靠。
- 读取：记忆启用且明确询问服装推荐时，覆盖常住城市/气候、季节和长期爱好的相关背景；无关非穿搭提问不触发背景补充；测试安全上限、非全文注入、顺序及独立开关。记录自由表达可能漏召回的限制。
- HTTP 验证 settings 与 CRUD 的认证、权限、未知字段和 400 行为；验证前端开关文字及状态，必要时做浏览器 smoke。
- 执行定向测试、API 全量测试、`pnpm format:check`、API typecheck/build、`pnpm check` 和 `git diff --check`；可控 fake 测试不依赖真实模型或第三方密钥。真实模型与七牛 smoke 仅在可用且用户允许时执行，不把未执行的项目写成通过。
