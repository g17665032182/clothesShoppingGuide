- 所属应用：`apps/api`，前端管理页面归属当前产品前端应用。

现有结构化服装偏好继续作为独立能力保留，不再代表全部长期记忆。新增的 Markdown 记忆按用户隔离，每位用户一份服务端权威文档，可由用户直接编辑，也可由聊天后的静默提取更新。聊天会话摘要、`chat_messages` 和 `chat_trace_events` 仍不作为长期记忆存储。

## 目标

1. 保留已有的结构化服装偏好及其管理能力。
2. 让用户以 Markdown 查看、编辑自己的长期记忆文档，不受固定偏好类别限制。
3. 以服装和购物相关信息为主，允许记录对个性化协作有帮助的其他长期背景。
4. 聊天静默提取可更新 Markdown 文档，并在后续相关聊天中使用受长度限制的记忆内容。
5. 保持用户隔离；提取或存储失败不得阻断当前聊天；管理员和客服默认不能读取记忆原文。

## 范围

### 包含

- 已有结构化服装偏好及其当前管理能力，继续保留为“用户偏好”。
- 每位登录用户一份自由 Markdown 长期记忆文档，服务端作为权威副本。
- 用户在管理页面查看和编辑整份 Markdown 文档。
- 文本聊天中的静默提取，优先更新服装与购物相关长期信息，其他有助于个性化协作的信息为辅。
- 后续相关聊天中读取 Markdown 记忆；当前消息仍优先于长期记忆。
- 用户清空或删除 Markdown 文档时，不影响结构化偏好或聊天记录。
- 异步、可重试且幂等的记忆更新。
- 真实 HTTP、模型和持久化链路验证。

### 不包含

- 游客的跨会话长期记忆。
- 图片、语音、上传文件或商品点击行为的记忆提取。
- 密码、Token、API Key 等认证凭据。
- 商品排序、广告、营销推送和管理员分析使用用户长期记忆。
- 向量数据库、Embedding 检索。
- 用户自行恢复任意历史版本。
- 记忆跨账号共享或转移。
- 本阶段的商品库、推荐排序和真实购买操作。
- 健康、身份、财务等敏感个人信息不得写入 Markdown 文档。

## 用户角色与权限

| 角色           | 权限                                                                 |
| -------------- | -------------------------------------------------------------------- |
| 登录用户       | 查看和编辑自己的 Markdown 文档；管理自己的结构化偏好；使用自己的记忆 |
| 游客           | 可以使用允许游客访问的产品能力，但不建立跨会话长期记忆               |
| 管理员         | 不能通过普通产品接口读取或修改用户记忆原文                           |
| 客服或运营人员 | 默认不能读取用户记忆原文；授权支持流程待确认                         |

继续复用现有 JWT、当前用户和角色权限机制，不新增独立的认证体系。

## 记忆内容与业务规则

### 用户偏好

当前已实现的尺码、风格、颜色、场景、预算等结构化服装偏好继续保留，按现有管理和读写流程维护；本次不把这些字段迁入 Markdown 文档。

### Markdown 长期记忆

- 每位用户拥有一份 Markdown 文档，可自由组织标题、段落和列表，不限制为预设类别。
- 内容以服装、穿搭、购物相关的稳定背景为主；工作、学习、习惯、目标等其他长期背景仅在有助于后续个性化协作时作为补充。
- 用户可直接查看和编辑整份文档；聊天静默提取可以更新同一份文档。
- 用户编辑与后台提取并发时的冲突处理、版本记录和来源标注待技术设计确认。
- 文件由服务端的持久化存储承载；具体介质、路径、备份和多实例部署方式待技术设计确认。

### 形成与使用规则

- 只有用户明确表达且具有长期语义的内容才进入记忆；优先提取服装和购物信息，其他内容仅作辅助。
- “这次”“今天”“临时”等表达只影响当前会话，不更新长期记忆。
- 模型推测、低置信度或不适合长期保存的内容不写入。
- 推荐时遵循以下优先级：

```text
当前消息明确要求 > 用户长期记忆 > 系统默认规则
```

- 仅向模型提供与当前问题相关且受长度上限约束的文档内容，不因单条无关记忆突破上下文预算。
- 用户在聊天中的明确修改或遗忘指令应更新文档；直接编辑文档也可修正模型提取结果。

### 设置与生命周期

- 现有记忆开关同时控制结构化用户偏好与 Markdown 文档的提取和注入。
- 关闭记忆开关不删除已有内容。
- 清空/删除 Markdown 文档时，必须取消或阻止未完成的提取任务将旧内容重新写回。
- 结构化偏好与 Markdown 文档分别清空、删除，避免误删另一类数据。
- 删除账号时同步清理该账号的两类记忆。
- Markdown 文档默认长期保留；是否需要版本恢复待确认。

## 处理流程

### 读取与注入

```text
登录用户发起聊天
  -> 校验用户与会话归属
  -> 读取相关的结构化偏好和 Markdown 记忆
  -> 按优先级和长度限制生成模型上下文
  -> 调用模型并完成当前回复
```

### 静默提取

```text
当前回复完成
  -> 异步提交本轮记忆提取任务
  -> 生成服装相关为主、其他长期背景为辅的更新候选
  -> 校验用户明确性、长期性、安全性和文档格式
  -> 处理并发、幂等和用户清空后的任务状态
  -> 更新 Markdown 文档或记录可重试失败
```

提取任务不得阻塞当前聊天。模型或持久化失败时，当前聊天仍按原有链路完成。

## API 或事件契约草案

具体路由命名和响应包装在技术文档阶段确定。

| 操作               | 方法与路由草案        | 权限             |
| ------------------ | --------------------- | ---------------- |
| 查询结构化偏好     | 沿用现有偏好 API      | 登录用户，仅本人 |
| 查询 Markdown 文档 | Markdown 文档读取 API | 登录用户，仅本人 |
| 更新 Markdown 文档 | 整份文档更新 API      | 登录用户，仅本人 |
| 清空 Markdown 文档 | 文档清空/删除 API     | 登录用户，仅本人 |
| 修改记忆设置       | 沿用现有记忆设置 API  | 登录用户，仅本人 |

静默提取通过聊天成功后的异步任务触发，不向客户端暴露模型原始输出、内部候选理由或供应商错误。

## 模块边界

### 用户长期记忆模块负责

- 结构化偏好原有领域规则及公开入口。
- Markdown 文档的用户归属、读取、更新、清空和生命周期。
- 提取候选到 Markdown 文档的安全校验、冲突处理和持久化。
- 为聊天模块提供受限的相关记忆读取入口。

### 聊天和大模型模块负责

- 在模型调用前请求受限的相关记忆，不直接访问记忆持久化实现。
- 在当前回复完成后提交记忆提取任务。
- 保持现有聊天消息、会话摘要和内部 trace 的职责不变。

### 禁止耦合

- 记忆模块不得直接依赖聊天模块的私有 Entity、Controller 或页面状态。
- 聊天模块不得绕过记忆模块直接写入记忆。
- 记忆模块不得把完整聊天原文复制为长期记忆。
- 管理员查询聊天记录不得隐式获得用户长期记忆。

## 数据与隐私原则

- 记忆按用户隔离，所有读取和写入都必须校验当前用户归属。
- 对外返回响应对象，不直接返回数据库 Entity 或服务端文件路径。
- 不保存密码、Token、API Key、数据库连接信息或供应商原始响应。
- 管理员、客服和运营能力默认不读取记忆原文。
- 新增持久化结构、索引、关联和迁移必须在技术设计确认后再实施。

## 待确认项

1. 静默提取的文档更新是否需要展示来源、更新时间或变更记录。
2. 用户手动编辑与后台提取发生并发时的交互语义。
3. 管理员脱敏统计和用户授权客服流程是否进入后续范围。
4. 文件存储介质、路径、备份、并发写入和多实例部署由技术文档确认。

## 验收清单

- [ ] 现有结构化服装偏好功能保留且不被 Markdown 文档覆盖。
- [ ] 登录用户可以查看和编辑自己的整份 Markdown 文档。
- [ ] 每位用户的文档相互隔离，游客和其他用户不能读取或修改。
- [ ] Markdown 内容以服装和购物为主，其他长期背景仅作辅助。
- [ ] 临时意图和低置信度推测不会写入文档。
- [ ] 相关记忆可用于后续聊天，当前消息优先且上下文长度受限。
- [ ] 文档清空后，旧提取任务不能重新写回复活内容。
- [ ] 文档写入失败、模型超时和任务重试不会阻断当前聊天或产生重复更新。
- [ ] 清空 Markdown 文档不会删除结构化偏好或聊天记录。
- [ ] 真实 HTTP、模型和持久化链路覆盖核心行为。
