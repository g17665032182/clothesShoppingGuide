# 用户长期记忆设计文档

## 状态与上下文

- 状态：已确认，进入技术设计
- 业务目的：让登录用户在跨会话使用服装导购时获得稳定、可控的个性化建议。
- 所属应用：`apps/api`，前端管理页面归属当前产品前端应用。
- 关联模块：`llm`、`chat-records`、`auth`、用户权限基础设施。
- 设计阶段：需求、设计、技术和实施文档均已确认，功能实施中。
- 最后更新：2026-11-03

现有聊天会话摘要只服务单个会话，聊天可见消息与内部 trace 也分别存储。用户长期记忆是跨会话的独立业务数据，不把会话摘要、`chat_messages` 或 `chat_trace_events` 直接当作长期记忆。

## 目标

1. 记住与服装导购直接相关、相对稳定且由用户明确表达的偏好。
2. 在后续服装导购聊天中使用这些偏好，提高建议的连续性和相关性。
3. 让用户能够查看、修改、删除和关闭记忆功能。
4. 让记忆提取失败、模型不可用或异步任务重试不会阻断当前聊天。
5. 保持用户隔离、最小化数据使用，并禁止管理员或客服默认读取记忆原文。

## 范围

### 包含

- 登录用户的跨会话服装偏好记忆。
- 文本聊天中的静默提取。
- 用户在聊天中用自然语言修改或删除记忆。
- “我的记忆”页面中的结构化查看、手动新增、编辑、删除和启停控制。
- 当前消息、长期记忆和系统默认规则的优先级处理。
- 记忆来源会话、更新时间和删除来源后的可追溯状态。
- 异步、可重试且幂等的记忆更新。
- 真实 HTTP、模型和数据库链路验证。

### 不包含

- 游客的跨会话长期记忆。
- 图片、语音、上传文件或商品点击行为的记忆提取。
- 健康、身份、财务和其他与服装导购无直接关系的敏感画像。
- 商品列表排序、广告、营销推送和管理员分析使用用户长期记忆。
- 向量数据库、Embedding 检索和自由文本画像。
- 用户自行恢复任意历史版本。
- 记忆跨账号导出、转移或共享。
- 本阶段的商品库、推荐排序和真实购买操作。

## 用户角色与权限

| 角色           | 权限                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| 登录用户       | 查看、创建、修改、删除自己的记忆；开启或关闭自己的记忆；在导购聊天中使用自己的记忆 |
| 游客           | 可以使用允许游客访问的产品能力，但不建立跨会话长期记忆                             |
| 管理员         | 不能通过普通产品接口读取或修改用户记忆原文；仅保留后续确认的脱敏运维能力           |
| 客服或运营人员 | 默认不能读取用户记忆原文；授权支持流程待确认                                       |

继续复用现有 JWT、当前用户和角色权限机制，不新增独立的认证体系。

## 记忆内容与业务规则

### 第一版类别

- 尺码。
- 鞋码。
- 体型或版型需求，例如“肩宽”“喜欢宽松版”。
- 风格，例如通勤、简约、街头。
- 颜色偏好或忌讳。
- 穿着场景。
- 预算或预算范围。
- 服装购买偏好和明确避讳。

“体型或版型需求”只保存用户主动用于服装选择的描述，不保存医学诊断或健康推断。

### 形成规则

- 只有用户明确表达、与服装直接相关且具有长期语义的内容才进入长期记忆。
- “这次”“今天”“临时”“帮我找一件”等表达只影响当前会话，不更新长期记忆。
- 模型推测但用户未明确表达的内容不保存。
- 低置信度、无法归类、敏感或违反字段规则的候选直接丢弃。
- 提取结果必须经过结构化字段校验、敏感字段过滤和冲突规则处理后才能持久化。

### 使用规则

推荐时遵循以下优先级：

```text
当前消息明确要求 > 用户长期记忆 > 系统默认规则
```

当前消息对本轮的临时覆盖不自动修改长期记忆。用户明确表达长期变化时，才更新当前有效记忆。

长期记忆默认用于该用户的所有服装导购会话，只向模型注入与当前问题相关且受长度上限约束的记忆摘要。

### 更新与删除规则

- 同一类别可以保存多个值或范围；用户可以标记主要偏好。
- 新的明确长期表达覆盖当前有效值，并保留必要的变更审计记录。
- 用户可以在聊天中说“忘记我穿 L 码”或“以后不要推荐荧光色”来删除或修改记忆。
- 删除全部记忆时同时取消尚未完成的提取任务，避免旧聊天任务在删除后重新生成记忆。
- 用户删除来源聊天后，长期记忆不自动删除；来源在记忆页面显示为“原聊天已删除”。
- 关闭记忆功能会停止新的提取和注入，但不删除已有记忆。
- “删除全部记忆”是独立操作。
- 删除账号时同步删除该账号的全部长期记忆。
- 记忆默认长期保留，暂不按时间自动过期。

## 处理流程

### 读取与注入

```text
登录用户发起导购聊天
  -> 校验用户与会话归属
  -> 读取当前用户的相关长期记忆
  -> 按优先级和长度限制生成模型上下文
  -> 调用模型并完成当前回复
```

### 静默提取

```text
当前回复完成
  -> 异步提交本轮记忆提取任务
  -> 模型返回新增、修改、删除候选
  -> 结构化校验与敏感过滤
  -> 应用冲突、优先级和幂等规则
  -> 持久化成功或记录可重试失败
```

提取任务不得阻塞当前聊天。模型、数据库或任务调度失败时，当前聊天仍按原有链路完成。

## API 或事件契约草案

以下路由和事件名称是产品层草案，具体命名、分页形式和内部事件载体在技术文档阶段确认：

| 操作         | 草案方法与路由                 | 权限               |
| ------------ | ------------------------------ | ------------------ |
| 查询我的记忆 | `GET /api/memories`            | 登录用户           |
| 手动新增记忆 | `POST /api/memories`           | 登录用户           |
| 修改单条记忆 | `PATCH /api/memories/:id`      | 登录用户且仅限本人 |
| 删除单条记忆 | `DELETE /api/memories/:id`     | 登录用户且仅限本人 |
| 删除全部记忆 | `DELETE /api/memories`         | 登录用户           |
| 修改记忆开关 | `PATCH /api/memories/settings` | 登录用户           |

静默提取通过聊天成功后的异步任务触发，不向客户端暴露模型原始输出、内部候选理由或供应商错误。

## 模块边界

### 用户长期记忆模块负责

- 记忆资源的领域规则、归属校验、增删改查和生命周期。
- 记忆结构化数据与来源关联。
- 记忆开关、删除全部和账号删除时的清理。
- 为聊天模块提供受限的相关记忆读取入口。
- 接收结构化提取候选并执行校验、冲突和幂等处理。

### 聊天和大模型模块负责

- 在模型调用前请求相关记忆，不直接访问记忆实体或数据库。
- 在当前回复完成后提交记忆提取任务。
- 保持现有聊天消息、会话摘要和内部 trace 的职责不变。

### 禁止耦合

- 记忆模块不得直接依赖聊天模块的私有 Entity、Controller 或页面状态。
- 聊天模块不得绕过记忆模块直接写入记忆表。
- 记忆模块不得把完整聊天原文复制为长期记忆。
- 管理员查询聊天记录不得隐式获得用户长期记忆。

## 数据与隐私原则

- 记忆按用户隔离，所有读取和写入都必须校验当前用户归属。
- 对外返回响应对象，不直接返回数据库 Entity。
- 不保存密码、Token、API Key、数据库连接信息或供应商原始响应。
- 来源只保存必要的会话关联和时间信息，不复制被删除聊天的原文快照。
- 管理员、客服和运营能力默认不读取记忆原文。
- 新增字段、索引、关联和迁移必须在技术设计确认后再实施。

## 技术阶段待确认项

以下内容不影响已确认的产品方向，由技术文档给出实现选择；技术文档仍需用户确认后才能实施：

1. 记忆类别的最终字段类型、枚举值、长度和多值/范围表达。
2. 记忆页面的具体前端应用位置、路由和空态交互。
3. 记忆 API 的最终路由命名、分页和响应包装。
4. 异步任务使用现有进程任务、数据库任务表还是项目内已安装的队列能力。
5. 提取模型是否复用当前聊天供应商，以及超时、重试次数和失败记录方式。
6. 记忆来源会话是否允许跳转到已删除或无权访问的会话。
7. 管理员脱敏统计和用户授权客服流程是否进入后续范围。

## 验收清单

- [ ] 登录用户可以跨会话读取自己的相关记忆。
- [ ] 游客不产生跨会话长期记忆。
- [ ] 只有明确、稳定、服装相关的文本表达会进入提取候选。
- [ ] 临时意图和低置信度推测不会污染长期记忆。
- [ ] 当前消息可以覆盖长期记忆，但不会无意中修改长期值。
- [ ] 用户可以通过聊天和管理页面修改、删除记忆。
- [ ] 关闭功能后停止提取和注入，已有数据仍可单独删除。
- [ ] 删除来源聊天不会隐式删除长期记忆。
- [ ] 账号删除会清理全部长期记忆。
- [ ] 提取失败、模型超时和任务重试不会阻断当前聊天或产生重复记录。
- [ ] 越权读取、修改和删除均被拒绝。
- [ ] 真实 HTTP、模型和数据库链路覆盖核心行为。
