## 阶段 2：登录态浏览器验收

在可用的本地 API/Web 与合成测试账号下串行验收。先核对端口和现有进程；不得覆盖无关服务、用户环境配置或已有数据。模拟支付只验证应用状态，不产生真实扣款。

关键路径：

- 登录并访问商品目录，检查加载、筛选、分页和商品详情。
- 地址页及购买弹框：检查本人地址展示、选择后写入购买草稿、新地址只有显式保存才加入地址簿。
- 购买与订单：完成草稿、用户确认下单、模拟支付及本人订单查询；检查重复提交、冲突和结果未知后的恢复入口。
- 聊天取消：仅选择本人未过期待付款订单，并验证二次确认后才提交。
- 管理员运营：验证管理员可查询商品/订单并完成整单发货；普通用户无权访问管理员操作。
- 虚拟试穿：仅使用登记的公开/合成测试图，检查当前商品资格、上传、任务状态、结果归属和删除。
- 桌面与窄屏：检查键盘操作、弹框、加载/空/失败/重试状态、Toast，以及账号或会话切换时的状态隔离。

若没有已认证浏览器会话，先使用项目允许的开发测试账号准备流程；无法安全取得会话时记录为未执行，不伪称通过。当前仓库没有 Web Playwright 测试脚本；本阶段按人工 Smoke Test 记录，不在本计划中安装测试框架。

验收标准：为每条路径记录实际操作、结果、浏览器/视口和缺陷；覆盖不到的路径明确列为未执行。若后续要建设自动化浏览器测试，另行评估并审批测试基础设施。

## 阶段 3：虚拟试穿供应商准入

生产真实人像流程继续关闭，直到取得并审查书面依据，至少覆盖：

- 输入照片和生成结果是否留存、各自留存期限及删除保障。
- 数据处理与存储地区、数据流向及其适用隐私条款。
- 是否用于模型训练或其他二次用途，以及可执行的禁止/退出保障。
- 用户告知、明确同意、撤回和数据删除责任。
- 凭据、日志、重试和失败路径不会泄漏照片、Base64、对象键或签名 URL。

书面材料和业务批准齐备后，再单独安排受控的供应商 Smoke Test：使用公开/合成图、独立开发凭据和经确认的请求目的地；记录请求、响应、耗时和数据清理证据。不得上传真实用户人像或将一次成功调用表述为稳定 SLA、视觉质量或生产隐私验收。

如果任一关键保障无法确认，记录阻塞项并保持真实人像入口关闭；不以技术测试通过替代隐私审批。

## 阶段 4：产品指标定义

先在产品文档中确认指标用途和口径，再决定是否实现埋点。候选指标可包括商品浏览至购买转化、订单支付完成率、试穿任务成功率与耗时、聊天推荐后的商品交互率。

每项需明确事件定义、分母/分子、统计窗口、去重方式、按用户还是会话聚合、失败与取消如何处理，以及是否涉及个人数据。优先评估仅使用聚合或去标识化数据能否满足目的。未确认数据保留、用户告知和访问权限前，不新增用户级追踪。

验收标准：`docs/product/prd.md` 中待确认指标形成已确认定义或明确维持待确认；如需新增数据采集、API、存储或第三方分析服务，先更新对应契约与隐私边界并单独审批。
