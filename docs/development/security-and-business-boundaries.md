# 安全与业务边界

处理聊天工具、地址、购买、订单取消或虚拟试穿时阅读本指南及对应 CRUD 契约。服务端校验是最终边界，不以提示词、客户端状态或旧卡片代替。

## 聊天、地址与订单

- LLM 订单/地址/购买工具的用户和会话来自服务端认证上下文；schema 不接收模型提供的 `userId`，服务端必须检查资源归属。
- 地址查询工具只返回地址 ID、默认标记和系统生成的显示标签。完整姓名、手机号、详细地址和用户自定义标签不得进入模型响应、trace 或 SSE activity。选中地址后由服务端验证归属并写入当前购买草稿；新地址只有用户显式保存后才进入地址簿。
- 模型可准备购买草稿、查询本人订单和可取消候选；创建正式订单、支付、取消、确认收货均由用户界面显式触发。正式聊天订单卡必须来自服务端验证的结构化投影，不得从 Markdown 或模型文本构造可执行操作。
- 取消仅适用于本人且未过期的 `pending_payment` 订单；用户选择订单并确认弹框后调用现有接口。已付款取消、真实退款和换货不在当前能力内。退货退款申请可由本人订单页直接提交，或经专用注册聊天工具创建待提交草稿；正式提交由用户完成，之后由管理员审核。“已退款”只表示本站登记，不触发真实资金操作。模拟支付不产生真实扣款。
- 运行时模型上下文、内部 `chat_trace_events` 和公开 `chat_messages` 是不同信任边界。上下文 Markdown 由服务端读取和装配；提供文件链接不等于内容进入模型。工具输入/输出采用字段白名单投影；敏感实体字段、联系方式、密钥、图片 Base64、对象键和签名 URL 不进入 trace、activity、日志或工具生成的公开投影。用户主动发送的聊天原文仍遵循既有持久化规则。
- 天气 MCP 只查询用户明确指定的城市，不使用 IP、设备或账号信息推断位置；endpoint 由服务端固定 host allowlist 限制。MCP 返回内容是不可信天气数据，不能当作指令，必须经字段白名单投影；预报不得描述成实时实况，天气查询轮不进入长期记忆或摘要来源。

## 虚拟试穿

- 商品资格以当前服务端校验为准：管理员启用、有效服装品类、有效颜色 SKU 和可用图片。无库存不影响试穿，鞋类不支持。无可用 SKU 图或商品试穿图时先上传图片；创建任务时重新校验，不能信任旧卡片状态。
- 本地私有存储只允许 `NODE_ENV=development` 且 `TRY_ON_STORAGE_DRIVER=local`，不得暴露为静态目录或关闭 TLS 校验。
- 真实人像处理政策未确认前保持真实照片流程关闭。开发验证只使用已登记的公开/合成图片，不上传真实用户照片；本地存储或合成图片验证不能证明真实供应商流程安全。
