- 最后更新：2026-11-13。

## 目标与范围

为启用账号提供本人收货地址簿，并让助手能在安全边界内辅助用户查订单、选择已有地址或录入新地址。

包含：

- 用户在账号区域查看、新增、编辑、删除本人地址，并设置默认地址。
- LLM 工具按服务端绑定的当前账号读取本人订单摘要和地址标识。
- 用户从商品卡点击“购买”后，助手可以询问缺失的收货字段。
- 用户可在聊天对话中明确选择已有地址；服务端将所选地址的权威字段复制到当前购买草稿。
- 当前草稿没有本轮明确收件信息时，助手查询本人地址簿；存在地址时展示前端选择卡，由用户明确选择后再写入草稿。
- 查询成功且地址簿为空时，助手通过 `request_dynamic_form` 收集当前购买仍缺少的收件字段。
- 用户在对话中提供新地址后，聊天展示结构化地址确认卡；用户明确点击“保存地址”后，地址簿新增该地址。用户也可以选择仅用于当前订单而不保存。
- 地址簿和订单收货快照彼此独立；下单后订单继续保存不可变收货快照。

不包含：

- 模型凭姓名、手机号、邮箱或用户 ID 搜索任意用户。
- 模型读取其他用户订单/地址、订单完整收货快照或地址簿完整联系方式。
- 模型创建、支付、取消、确认收货等正式订单写操作。
- 自动把地址设为默认、自动覆盖同名地址、自动选择或复用默认/非默认地址、从旧订单或聊天记忆复用地址。
- 管理员跨用户查看、维护地址。
- 地址地理编码、地图联想、行政区字典、国际地址格式化和物流服务。

## 用户与权限

| 角色             | 能力                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| 启用的普通用户   | 管理本人地址；查询本人订单；在本人购买对话中选择已有地址或录入新地址                                         |
| 启用的管理员     | 与普通用户相同的本人能力；不获得跨用户地址/订单工具能力                                                      |
| 未登录、禁用账号 | 不得访问地址簿、本人订单工具或购买草稿                                                                       |
| 聊天助手         | 读取服务端绑定用户的订单摘要及地址引用；协助询问和填充购买草稿；不得执行正式订单动作或未经用户确认写入地址簿 |

客户端及工具参数不得决定数据归属。地址和订单查询均以服务端认证上下文绑定的 `userId` 为准；LLM 工具 schema 不接受 `userId`。

## 核心流程

### 地址簿管理

1. 用户从账号区域进入“收货地址”。
2. 页面加载本人地址，明确展示加载、空、失败和正常状态。
3. 用户新增或编辑收件人姓名、手机号、完整地址及地址标签；可选择设为默认。
4. 用户删除地址时若其为默认地址，删除后不自动选取其他地址；如地址已用于订单，订单快照不受影响。
5. 默认地址最多一条。新增首条地址时是否自动设默认，以及删除/取消默认后的空默认状态，见契约待确认项。

### 购买对话

1. 用户点击商品卡“购买”，恢复或创建当前会话购买草稿；原购买商品/规格/库存/价格确认流程保持不变。
2. 本轮用户明确提供完整收件信息时优先使用本轮信息；否则助手调用 `get_my_information` 查询本人地址簿。
3. 查询成功且地址簿非空时，服务端发出只含当前购买草稿引用的 `address_selection` 卡片。前端通过本人地址 API 读取最新地址并本地显示；默认地址只能标记，不能自动选中。
4. 用户在卡片中明确选择某个地址后，服务端依据 `userId + addressId` 校验归属和草稿版本，再将完整字段复制到当前草稿；模型不得接收或传入完整收件字段。
5. 查询成功且地址簿为空时，助手调用 `request_dynamic_form` 询问本次购买尚缺的收件字段。用户提交的信息只更新当前草稿。
6. 地址查询失败时，不得按空地址簿处理；提示用户重试。用户明确选择手动填写后，才用动态表单收集字段。
7. 用户在账号区域新增地址后可重试查询。新地址仍需用户显式点击保存；仅用于当前订单的地址不写入地址簿。
8. 地址簿保存与购买草稿更新分别提交，不做跨模块事务。地址保存成功后，客户端使用服务端返回的地址结果继续更新草稿；结果未知时使用同一请求键安全重试，不得以模型文字宣称代替持久化结果。
9. 下单确认卡展示当前订单所需完整收货快照，仅本人可见；确认订单后使用既有订单契约。

### LLM 订单查询

- 模型可按状态/时间等受限条件查询当前用户订单摘要，结果含订单号、状态、商品摘要、金额及关键时间等后续处理所需字段。
- 不向模型返回订单收件人、完整地址、手机号、内部 `userId`、内部幂等信息或管理字段。
- 工具不能操作订单状态。真实售后和物流轨迹仍未接入；不能将订单查询能力描述为退款、退换货或承运商实时查询。
- 若用户描述的订单无法唯一定位，助手询问订单号或时间范围，不得跨账号搜索。

## 数据与隐私

- 地址簿保存用户主动录入的姓名、联系电话、完整地址、标签、默认标志及服务端审计时间。
- 地址簿记录与订单收件快照分离。地址变更或删除不回写、不删除既有订单快照。
- 地址查询工具仅返回地址 ID、标签、默认标志和有限脱敏提示；选择卡详情由前端通过本人 API 临时读取，用户明确选择后完整字段由服务端复制到本人购买草稿，不经过模型工具结果。
- 新地址的完整输入不可由地址工具返回给模型；工具参数、工具结果、activity、trace payload 和普通应用日志不保存明文地址副本。现有用户主动聊天消息与模型提供方请求仍按当前聊天记录和服务配置处理，不能声称本功能消除这些处理。
- 收货地址不得写入长期偏好记忆、通用聊天摘要或跨会话自动默认值。
- 新增地址写入必须基于明确用户操作；只说出地址并不自动授权将其长期保存。
- 查询及保存的授权受当前用户和地址所有权校验约束；记录访问不得泄露他人资源是否存在。
- 地址保留期限、用户注销时的清理策略及数据库备份中的删除时限待确认。

## 兼容性与模块边界

- `user-addresses` 独立持有地址 Entity、Repository、Schema、Controller、Service 和测试，不扩展 `users` Entity 为无边界地址容器。
- `orders` 继续持有订单和订单收件快照；地址选择通过公开的地址簿能力读取，不让订单模块依赖地址 Entity。
- `chat-purchase` 继续持有购买草稿和版本状态；仅以公开接口读取地址、复制已选字段和关联显式保存动作。
- `chat-records` 持有当前会话归属、模型工具 trace 与展示卡；地址卡只包含必要引用，完整地址不进入通用展示投影。
- LLM 工具按本次登录用户和会话逐请求创建，用户 ID 从服务端身份注入闭包，不在 Zod 参数中暴露。
- 旧订单 API、旧聊天历史、已有地址为空的账号、地址簿删除后的订单详情保持兼容。
- 持久化变更通过增量 Migration；不得使用 `migration:fresh` 作为验证替代。

## 验收标准

- 用户无法读写他人地址；管理员普通身份不能跨用户访问。
- 地址增删改查、默认地址唯一性、删除默认地址和并发更新行为与契约一致。
- 用户选择地址后复制的是服务端所持当前值；工具无法伪造他人地址 ID 或直接传完整收货字段。
- LLM 可查本人订单摘要和地址引用，但不能从工具读取完整手机号/地址或任何其他用户数据。
- 购买对话录入新地址后，只有点击确认保存才写入地址簿；选择“仅用于本次订单”不写地址簿。
- 购买草稿缺少收件信息时会查询本人地址簿；有地址时展示选择卡供用户明确选择，空列表时才请求动态表单。
- 默认地址只作标记，不自动选中或写入；查询失败不会被当成空列表，旧订单地址和历史聊天文本不会自动复用。
- 地址确认卡和购买确认卡仅从服务端投影构建，不接受模型任意 JSON 生成可执行操作。
- 地址工具输入/结果、trace、activity 和应用日志不会持久化新增的明文地址副本。
- 用户原始聊天内容、模型提供方处理、地址保留/备份删除期限的既有边界有明确说明。
- 订单历史快照、既有下单流程和会话隔离不回归。

## 待确认项

- [ ] 地址字段采用单个完整地址文本，或省/市/区与详细地址分字段。
- [ ] 地址簿最大记录数、字段最大长度及是否支持“地址标签”。
- [ ] 首条地址是否自动设为默认；默认地址能否显式取消；删除默认项后的行为。
- [ ] 重复地址的处理方式，以及是否允许同名、同手机号的多个地址。
- [ ] 账号区域地址管理页面入口和导航标签。
- [ ] 地址工具对标签/脱敏提示的具体返回字段。
- [ ] 本人订单工具允许的筛选条件、每次最大返回条数和商品/金额字段。
- [x] 用户在对话中选择“保存地址”后，地址簿与草稿分开提交；结果未知时以原 `requestKey` 重试。
- [ ] 用户注销、聊天删除、订单快照和备份中的地址保留/删除期限。

地址新增使用客户端为每次新增生成的 UUID `requestKey`。同一用户以相同键和相同规范化地址内容重试时，服务端返回原地址；相同键对应不同内容时返回 409。地址簿写入与购买草稿更新分开提交，保存结果未知时使用原键重试并以服务端返回的地址结果恢复后续流程。

下单地址选择卡联动不改变地址管理的其他待确认项。当前运行时使用 `get_my_information` 返回安全地址引用，并由本人认证 API 读取详情和提交选择；旧 `list_my_shipping_addresses`、`select_my_shipping_address` 不再注册为模型工具。
