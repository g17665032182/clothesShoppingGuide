# 聊天用户信息查询工具设计文档

## 状态与上下文

- 状态：用户已于 2026-11-13 确认并实施；自动化验证已完成，登录态浏览器验收未执行，详见[实施记录](./chat-user-information-implementation.md)。
- 业务目的：允许聊天助手在当前已登录用户授权范围内查询有限的个人信息摘要，为后续回答、地址选择和历史图片相关操作提供服务端事实来源。
- 所属应用：`apps/api`、`apps/web`。
- 所属模块：`llm` 负责工具调用；用户地址、订单和虚拟试穿模块负责各自数据查询；`chat-records` 负责工具结果的安全投影和历史边界。
- 最后更新：2026-11-13。
- 关联文档：[安全与业务边界](../../development/security-and-business-boundaries.md)、[用户地址契约](../../contracts/user-address-crud-contract.md)、[订单契约](../../contracts/order-crud-contract.md)、[聊天卡片展示契约](../../contracts/chat-card-display-crud-contract.md)。

## 目标与范围

目标流程：

1. 用户在已认证聊天会话中提出“查看我的地址、订单或已记录图片”等请求。
2. 助手调用 `get_my_information` 工具，工具参数只声明需要查询的 section 和有界筛选条件。
3. 服务端从当前认证用户上下文绑定 `userId`，调用地址、订单和已保存试穿图片的公开查询能力。
4. 服务端按 section 白名单生成模型可读的安全摘要；必要时同时生成只读前端展示引用。
5. 助手基于安全摘要回答用户，不能把完整个人信息、原图或内部对象引用带入模型上下文之外的公开链路。

首版 section：

- `addresses`：地址簿摘要，包括地址引用、是否默认和稳定显示标签。
- `orders`：本人订单摘要，包括订单号、状态、金额、商品摘要和时间。
- `photos`：用户已保存且仍有效的图片元数据，包括图片引用、类型、尺寸、大小和创建时间。

## 下单流程集成

用户发起下单且当前购买草稿尚无收件信息时，助手调用本工具查询本人地址簿的 `addresses` section。该查询是下单流程的一部分，不要求用户先单独提出“查看地址”。

1. 本轮用户明确提供了完整收件信息时，优先使用本轮信息，不重复询问。
2. 否则调用 `get_my_information`，只请求 `addresses`，由服务端身份绑定查询本人地址。
3. 查询成功且地址簿非空时，服务端发出只含当前购买草稿引用的 `address_selection` 卡片。卡片在前端调用本人地址 API 获取最新地址列表，并在页面本地呈现；默认地址可以标记出来，但不能自动选中或写入草稿。
4. 用户在卡片中明确选择某个地址后，前端通过认证的地址选择操作提交 `addressId`、草稿 ID 和预期版本。服务端重新校验地址归属和当前草稿版本，再将完整收件信息复制到购买草稿；完整值不进入模型、聊天历史、trace、activity 或 `publicDisplay`。
5. 查询成功且地址簿为空时，助手调用 `request_dynamic_form`，通过已注册的 `purchase_recipient` 表单询问尚缺的下单收件字段。表单提交只更新当前本人购买草稿，不创建正式订单。
6. 地址查询失败时，不得将其当作“地址簿为空”并立即请求表单；应说明无法读取地址、提供重试，用户明确选择手工填写后再使用动态表单。

卡片只作为当前购买草稿的地址选择入口，不代表用户已选中默认地址或确认下单。地址详情只能由前端使用当前认证身份从本人地址 API 临时读取；点击行为不得依赖模型解释普通文本。正式订单仍只能由用户在购买界面显式确认。

## 用户与权限

| 角色       | 能力                                                             |
| ---------- | ---------------------------------------------------------------- |
| 已登录用户 | 查询本人地址簿、本人订单和本人已保存图片的安全摘要               |
| 聊天助手   | 代表当前用户请求查询；不能指定其他用户、读取原文或执行写操作     |
| 前端       | 可展示服务端确认的只读摘要；地址选择等后续操作仍调用现有本人 API |
| 领域模块   | 验证资源归属、状态和公开字段，并返回独立安全 DTO                 |

`userId`、会话 ID 和权限范围均由服务端闭包或聊天编排上下文绑定，不能出现在模型工具参数中。管理员接口和跨用户查询不属于本工具。

## 工具输入设计

工具名暂定为 `get_my_information`。

```json
{
  "sections": ["addresses", "orders", "photos"],
  "orderNo": "可选的精确订单号",
  "status": "可选的订单状态",
  "page": 1
}
```

输入规则：

- `sections` 为 1–3 个去重枚举；省略时默认查询三个 section。
- `orderNo` 最多 100 个字符，只用于本人订单精确筛选。
- `status` 只能使用现有订单状态枚举。
- `page` 为 1–10 的整数；服务端为每个 section 设置固定最大条数。
- 不接受 `userId`、地址完整内容、订单 ID、图片 URL、对象存储键、任意 SQL/表达式或业务写操作参数。

## 安全结果设计

### 地址簿

模型结果只允许：

```json
{
  "addressId": "uuid",
  "isDefault": true,
  "displayName": "默认地址"
}
```

不返回收件人姓名、手机号、详细地址、用户标签原文或地址实体。下单选择卡由前端通过认证的本人地址 API 读取并临时显示完整值；用户明确选择后，服务端才将地址写入当前购买草稿。

### 订单

模型结果只允许订单安全摘要：

```json
{
  "orderNo": "订单号",
  "status": "pending_payment",
  "closeReason": null,
  "itemsAmount": "100.00",
  "payableAmount": "100.00",
  "itemCount": 1,
  "createdAt": "2026-11-13T00:00:00.000Z",
  "paidAt": null,
  "shippedAt": null,
  "completedAt": null,
  "items": [
    {
      "productName": "商品名",
      "color": "黑色",
      "size": "M",
      "quantity": 1
    }
  ]
}
```

不返回收件信息、手机号、详细地址、物流单号、支付凭据、内部订单 ID、SKU ID、商品图片 URL 或 Entity。

### 已保存图片

图片结果只允许元数据：

```json
{
  "photoId": "uuid",
  "kind": "person",
  "mimeType": "image/jpeg",
  "byteSize": 123456,
  "width": 1200,
  "height": 1600,
  "createdAt": "2026-11-13T00:00:00.000Z",
  "availability": "saved"
}
```

仅查询虚拟试穿模块中状态为 `saved` 且 `active` 的图片。不得返回原图、Base64、Buffer、对象存储键、签名 URL、缩略图 URL 或临时上传图片。

## 前端展示边界

本工具不新增任意个人信息卡片，也不让模型直接生成可执行操作。已实现的 `address_selection` 仅用于当前购买草稿：卡片只携带草稿引用，前端从本人地址 API 临时读取最新地址，默认地址不预选，用户确认选择后由购买 API 更新草稿。

- 订单结果仍以安全摘要供助手回答；不新增订单操作卡或支付/取消/确认收货权限。
- 图片结果仅为已保存图片元数据；不生成图片卡片或图片内容 URL。
- 地址选择卡由服务端根据当前草稿及地址查询结果生成，不能从 Markdown 或模型 JSON 直接构造。

## 数据、隐私与日志

- 工具结果必须经过 section 级白名单投影，依赖失败只返回固定 `unavailable` 状态，不泄露内部异常。
- 地址完整值、订单收件信息和图片内容不得进入模型 trace、tool activity、公开聊天历史、普通日志、长期记忆或下一轮上下文。
- 工具调用只读，不创建订单、不修改地址、不取消订单、不上传/删除图片、不触发试穿。
- 现有聊天记录查询能力不作为用户图片或个人资料来源，避免把聊天全文暴露给模型。
- 若工具结果需要前端展示，展示引用与模型结果分离，并绑定当前 assistant 消息和会话。

## 模块边界

- `llm`：定义工具 schema 和调用协议，不依赖业务 Entity/Repository。
- `user-addresses`：提供本人地址摘要查询 Port；保留完整地址读取和写入边界。
- `orders`：提供本人订单安全摘要查询能力；复用现有 `listForUser` 及安全投影。
- `virtual-try-on`：提供已保存图片元数据查询 Port；不暴露对象存储。
- `chat-records`：负责 trace、activity、历史和卡片展示的脱敏投影。
- `apps/web`：只渲染公开摘要和现有操作，不保存敏感查询结果到 Pinia/localStorage。

## 非目标

- 不提供跨用户、管理员或客服查询。
- 不返回完整地址、手机号、用户画像全文、聊天全文或原始图片。
- 不提供任意字段选择、任意数据库查询、任意对象存储访问或 URL 代理。
- 不通过工具执行地址、订单或图片写操作。
- 不新增长期“用户资料”聚合表；首版实时读取已有领域数据。
- 不在未确认卡片协议前新增地址/图片前端卡片。

## 已确认决策

- 工具名为 `get_my_information`；省略 `sections` 时查询三个 section，每个 section 固定最多返回 5 条。
- 地址详情由前端通过本人地址 API 临时读取，卡片只保存购买草稿引用；默认地址仅标记，不自动选择。
- 图片首版只返回已保存图片元数据，不生成图片卡片、不提供图片内容或 URL。
- 单个 section 故障采用部分成功结果与固定错误码，不丢弃其他 section 的成功结果。
