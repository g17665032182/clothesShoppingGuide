# 聊天后台生成

## 范围与设计

2026-11-05 用户明确要求：切换聊天记录和站内路由时不中断回复，在对应历史记录处显示加载状态，后台继续获取 LLM 回答。本次扩展既有前端聊天能力，不新增后端模块、接口、数据库结构或持久化任务。

本说明取代此前设计、技术和实施文档中“切换会话或卸载页面取消生成”的约定，其余保存成功、主动停止、真实断流与待核实规则继续遵守[流式聊天契约](../../contracts/chat-streaming-crud-contract.md)。

- 生成任务归属于会话，页面只负责选择会话、草稿和交互绑定。
- 每个会话最多运行一个生成任务；不同会话可以分别生成。
- 首轮尚未收到 `start` 时使用本地稳定标识，收到服务端 ID 后关联原会话，不抢占用户已经切换的页面。
- 展开和折叠的聊天导航都在生成中的会话处显示 Spinner；生成及保存后历史刷新结束后移除。
- 切回运行中的会话使用已有消息和增量；后台失败仅改变所属会话的状态。
- 主动停止只取消当前会话；退出登录或认证身份变化取消全部任务并清除旧用户缓存。
- 后台任务只在当前浏览器文档内存活，不保证刷新、关闭页面后的生成或恢复。

## 技术边界

- 使用 Pinia Setup Store，注册在应用入口；跨路由任务放在 `src/stores/chat/`。
- Store 管理每个会话的消息、状态、分页位置、生成耗时及独立 AbortController；控制器和计时器不作为可序列化业务状态。
- 使用 shallowRef 与不可变快照更新递归工具数据，避免深层响应式类型展开及跨会话对象污染。
- `pages/chat/page.ts` 保留页面草稿、键盘处理和页面可见性绑定；导航折叠与弹窗仍是私有组件局部状态。
- 复用现有 Axios SSE 适配器及 shadcn-vue Spinner，不改基础 UI 组件或新增测试框架。
- 后台完成后仍读取历史核实服务端消息 ID；失败时保留已由 `done` 确认的成功内容。
- 当前用户身份变化使旧请求失效；Token 正常刷新不取消同一用户的任务。
- 离开会话时仍触发既有记忆提取；运行中的会话延迟到后台完成后触发，避免提前提取半轮消息。

- [Pinia Store](https://pinia.vuejs.org/core-concepts/)
- [Pinia 安装](https://pinia.vuejs.org/getting-started.html)
- [shadcn-vue Spinner](https://shadcn-vue.com/docs/components/spinner)

## 实施与验收

本次由主代理集中实现同一前端状态边界，避免拆分紧密关联的任务状态迁移。

1. 引入 Pinia，抽离会话状态、生成任务和历史适配。
2. 页面接入 Store，侧栏按会话显示生成状态并限制删除运行中的会话。
3. 修正公共导航高度变化后聊天区的剩余高度计算。
4. 使用受控 SSE/API 替身验证切换、并发、路由卸载、主动停止、后台失败及退出登录隔离；不调用真实模型或外部服务。
5. 执行 `pnpm check`，并检查浏览器布局和导航。

验证结果在完成实现后记录，不以计划代替已通过的检查。
