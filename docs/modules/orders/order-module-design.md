## 目标与范围

实现本站持久化订单，支持多 SKU 直接下单、模拟支付、本人取消、超时关闭、管理员整单发货、本人确认收货及分页查询。

补齐商品规格查询、库存预占/释放/发货扣减能力，并同步商品推荐、导入和测试 Seeder 的库存规则。模拟支付不会真实收款，但订单库存变更会实际写入本地数据库。

明确排除前端页面、聊天下单、真实支付、购物车、地址簿、优惠和运费模板、订单编辑/删除、拆单、售后、物流轨迹及自动收货。

## 角色与权限

| 能力                                     | 启用的普通用户 | 启用的管理员 | 禁用账号/访客 |
| ---------------------------------------- | -------------- | ------------ | ------------- |
| 查询可选规格                             | 允许           | 允许         | 不允许        |
| 创建订单、模拟支付、取消、确认收货       | 仅本人         | 仅本人       | 不允许        |
| 查询本人订单                             | 允许           | 允许         | 不允许        |
| 查询全部订单、查看管理详情               | 不允许         | 允许         | 不允许        |
| 管理员整单发货                           | 不允许         | 允许         | 不允许        |
| 任意改价、修改状态、删除订单、代买家操作 | 不提供         | 不提供       | 不提供        |

复用当前 JWT Guard、当前用户上下文与角色授权能力。客户端不能指定订单归属；订单创建与重试均绑定当前用户。本人接口访问其他用户订单与不存在订单统一返回 404，管理接口的非管理员请求返回 403。

禁用不触发订单删除、退款或自动取消已支付订单；未支付订单按原期限关闭，已支付订单可由管理员继续发货。禁用期间用户不能确认收货；恢复账号后继续允许的操作，不由管理员代收货。

## 状态与动作

以下状态枚举已获用户确认：

| 状态               | 含义                       | 允许的下一步                               |
| ------------------ | -------------------------- | ------------------------------------------ |
| `pending_payment`  | 待支付，订单已预占库存     | 本人模拟支付；本人取消；系统超时或下架关闭 |
| `pending_shipment` | 已模拟支付，继续预占库存   | 管理员整单发货                             |
| `pending_receipt`  | 已发货，实物库存已扣减     | 本人确认收货                               |
| `completed`        | 用户已确认收货             | 只读及成功动作的安全重试                   |
| `closed`           | 未支付订单终止，预占已释放 | 只读及本人取消成功动作的安全重试           |

关闭原因区分 `user_cancelled`、`payment_expired`、`product_unavailable`，不将已支付订单转成关闭。

- 订单创建时间、30 分钟支付截止时间和各动作时间由服务端维护。
- `服务端当前时间 >= expiresAt` 即不可支付；支付和关闭并发时只能成功完成一个有效状态转换。
- 自动关闭不得依赖浏览器访问或前端定时器；进程重启后仍能识别并处理数据库中到期的订单。
- 后台处理延迟不延长支付期限；任何支付入口都必须检查截止时间。
- 同一订单重复支付、发货、确认收货不能再次扣库存或改写已完成的动作时间。
- 未支付订单下架关闭后重新上架也不能恢复，买家需新建订单。

## 价格与快照

客户端下单只提供 SKU、数量、收货信息和本次提交的幂等标识。商品归属、名称、规格、单价、币种和库存以服务端当前目录为准，服务端生成订单号并计算行金额及总金额。

价格采用精确十进制语义，对外以两位小数金额字符串表示，禁止用浮点金额累计。币种固定 `CNY`，运费为 `0.00`，优惠为 `0.00`，实付金额等于商品总价。

订单保存名称、商品外部标识、SKU 标识、颜色、尺码、单价、数量、图片和收货信息快照。后续导入修改商品名称、颜色、尺码、价格、图片或启用状态，不修改订单快照。

下单后的 30 分钟内使用订单锁定价格；超时重下使用最新价格。订单内容不提供 PATCH 接口；未支付时取消后重新下单，已支付后不支持编辑。

模拟支付明确记录 `paymentMode: "simulated"` 和支付时间，不生成或伪造真实支付平台流水号。

## 库存与一致性

### 库存口径

每个 SKU 的实物库存为当前 `stock`；预占数量为有效待支付和待发货订单占用的合计；可售数量等于两者之差。必须始终满足：

```text
实物库存 >= 预占数量 >= 0
可售数量 = 实物库存 - 预占数量 >= 0
```

| 动作                           | 实物库存               | 预占数量                       |
| ------------------------------ | ---------------------- | ------------------------------ |
| 创建订单                       | 不变                   | 增加订单数量                   |
| 模拟支付                       | 不变                   | 不变                           |
| 取消、超时关闭、未支付下架关闭 | 不变                   | 释放整单数量                   |
| 整单发货                       | 扣减整单数量           | 同时解除整单预占               |
| 确认收货                       | 不变                   | 不变                           |
| 导入库存                       | 按文件设为新的实物库存 | 不得随导入重置，按订单动作维护 |

库存不足、SKU 不存在或已下架时，整单创建失败，不留下部分写入。相同 SKU 的重复行拒绝，不隐式叠加数量。

商品搜索、分页、软匹配中的有货标签、规格查询及订单创建统一基于可售数量；对外仍只展示有货/无货。查询响应是快照，不能代替下单时的原子库存检查。

### 导入与下架

导入继续保留现有文件全量校验和整批事务语义。对已有 SKU 导入的库存是当前实物库存，不是增量补货，也不是可售数量；导入者不能传入或覆盖预占量。

商品或 SKU 停用时，关闭所有包含该商品/SKU 的未支付订单，释放这些订单全部明细的预占。已支付订单保留预占并继续履约，即使商品已下架也允许管理员发货。

在同一批导入的一致性边界内，先计算待下架商品引起的整单关闭及释放结果，再校验每项导入库存是否不小于剩余预占量。校验失败则整批商品变更、订单关闭和预占释放全部回滚；报告对应商品和 SKU，不输出收货信息。

并发导入、下单、模拟支付、发货、取消及超时处理必须共同遵循这些不变量。商品测试 Seeder 同样不能绕过保护或清零已有预占，具体共用入口在技术阶段确定。

## API 行为

完整字段、校验、成功状态码和错误见 [CRUD 契约](../../contracts/order-crud-contract.md)。已确认路由如下：

| 方法   | 路由                               | 业务用途                       |
| ------ | ---------------------------------- | ------------------------------ |
| `GET`  | `/api/product-catalog/skus`        | 按商品外部标识分页查询有效规格 |
| `POST` | `/api/orders`                      | 多 SKU 直接下单，整单预占      |
| `GET`  | `/api/orders`                      | 本人订单列表                   |
| `GET`  | `/api/orders/:id`                  | 本人订单详情                   |
| `POST` | `/api/orders/:id/simulate-payment` | 本人模拟支付                   |
| `POST` | `/api/orders/:id/cancel`           | 本人取消未支付订单             |
| `POST` | `/api/orders/:id/confirm-receipt`  | 本人确认收货                   |
| `GET`  | `/api/admin/orders`                | 管理员订单列表                 |
| `GET`  | `/api/admin/orders/:id`            | 管理员订单详情                 |
| `POST` | `/api/admin/orders/:id/ship`       | 管理员填写物流并整单发货       |

列表不返回完整地址和手机号，详情只向本人或管理员返回收货快照。规格 API 以独立投影返回 SKU 标识，不把旧聊天商品响应改造成下单请求；不新增聊天工具或自动购买动作。

## 幂等与重试

- 同一用户、同一下单幂等键、同一规范化输入：返回原订单及其当前状态，不重新计时、锁价或占库存。
- 同一用户、相同键、不同输入：返回 409；相同键不能在订单终止后复用。
- 不同用户可以使用相同键，但不能读取彼此的订单；主动再次购买必须使用新键。
- 模拟支付成功后的重试返回当前订单，不使已发货或已完成订单回退。
- 相同物流信息的成功发货重试返回当前订单；试图覆盖已保存物流信息返回 409。
- 本人取消成功后的同动作重试、本人确认收货成功后的同动作重试安全返回当前结果。
- 因超时或下架关闭后再请求支付/取消，以及不满足当前状态的其他动作，返回 409。

具体键字段与规范化规则见已确认契约；并发实现方式见技术文档。

## 模块边界

- `orders`：订单、明细和收货/价格快照、状态流转、幂等、本人及管理查询、超时关闭和物流快照。
- `product-catalog`：商品及 SKU 的持久化、规格投影、真实库存口径和预占/释放/扣减的公开能力、导入校验。
- 订单通过商品模块公开入口请求规格及库存操作，不导入商品私有 Entity、Repository 或内部 DTO。
- 商品下架涉及订单关闭，通过明确的公开协作边界完成；不能在导入脚本直接操作订单 Entity，也不能通过两个独立提交造成部分成功。
- 认证/授权沿用当前模块；订单不复制密码、Token 或用户认证实现。
- 聊天模块保持当前查询和展示能力，不调用订单写入口。

预占记录的具体归属、跨能力事务接口和避免循环依赖的接线方式在技术文档中明确，本阶段不提前创建文件结构、Entity 或 Migration。

## 迁移与兼容性

新增订单持久化、明细、幂等约束及预占支持时，必须保留既有用户、商品 UUID、SKU UUID、商品价格、导入标识和聊天快照。

历史商品在没有订单时预占量为零，可售数量等于现有库存。不得把现有库存再次扣除或按历史聊天消息生成订单。具体表、约束、索引、回滚限制和数据验证由技术文档说明，并在实施阶段审查迁移。

商品目录原契约中的“不支持库存预占/扣减”描述适用于订单增量实现前；当前可售库存和订单协作规则见商品目录契约的已确认增量。
