## 开发流程总览

```text
商品卡点击试穿
  -> Web 选择颜色和本人照片，完成本次处理同意
  -> 聊天请求提交严格校验的 tryOnAction
  -> API 从认证上下文取用户，确定性调用聊天试穿工具
  -> 工具经 virtual-try-on 公开 Port 校验并创建现有异步任务
  -> 现有 worker 和图像供应商生成试穿结果
  -> 工具取得本人任务的受检结果图，作为临时多模态输入交给聊天模型
  -> 聊天模型生成文字；响应附带不含图片地址的 taskId 引用
  -> Web 通过本人任务结果 API 加载并渲染图片
```

API 与 Web 子代理已按下表并行实现各自文件；主代理完成协议协调、集成审阅和最终自动化验证。共享构建目录和数据库验证按约定串行执行。

不改变商品卡资格来源、虚拟试穿任务语义、用户数据隔离、成功额度、重试和照片删除规则；不新增供应商、依赖、HTTP 路由、Entity、Migration 或环境变量。供应商审查完成前生产真实人像处理继续关闭。

## 子代理开始前检查

- 主代理已复核 `git status` 并向子代理说明现存改动；每个代理先读设计、技术、契约及相关模块文档。
- API 子代理确认 `chatSchema` 和 Controller 的 `StandardSchemaValidationPipe` 绑定方式、LangGraph trace 序号/消息顺序、现有 Chat Model 图片块支持，以及 `TryOnTaskService` 的任务创建/结果下载边界。
- API 子代理通过 `VirtualTryOnModule` 导出的公开 Port 获取任务状态与本人结果字节；不得从聊天模块导入试穿 Entity、Repository、对象键或私有存储实现。
- Web 子代理复用现有聊天 SSE/API 客户端、试穿照片 API、固定结果结构和认证流程。检查照片组件及同意文案的现有 props/event，不得把原始图片、Base64、照片内容或同意内容放入 `messages[].content`。
- 两个代理先对齐 `tryOnAction` 输入、SSE/最终消息中的 `tryOnResult` 结构、稳定错误码及进行中状态；只允许按已确认技术文档实现，不得各自扩展协议。
- 自动化测试使用 Fake Model、Fake 任务/图像供应商和合成标记图；不依赖真实用户照片或真实供应商凭据。
- 如需 PostgreSQL 用例，先核查测试源码的门控变量、实际数据库名及清理范围；只能使用具名可销毁隔离库，并与其他数据库任务串行。

## 主代理集成任务

- 对照技术文档检查 API、Web 输入/输出字段和状态一致；严格验证 `tryOnAction`、`tryOnResult` 与错误结构，未知字段不得静默接受。
- 确认当前用户始终来自认证上下文，商品资格从当前 `ProductCatalogTryOnPort` 重查，照片归属/状态/同意由服务端验证，工具只调用一次且不能接受任意用户、商品事实或供应商参数。
- 确认图像生成只由既有异步 worker 和 provider 执行；聊天工具只等待、读取已成功且属于当前用户的任务结果，不绕过额度、活动任务、供应商开关或结果访问权限。
- 检查图片字节只在本轮模型调用中暂存；不会进入 LangGraph 持久化消息、普通 trace、activity、日志、公开聊天内容或历史 envelope。最终回复仅携带任务引用，Web 通过本人结果 API 取图。
- 检查断连只停止聊天轮询/模型调用，不伪造取消后台任务；等待超时不重复创建任务；模型不支持图片时已有任务仍可由本人查看。
- 检查旧聊天历史、商品搜索/购买/订单展示、原“我的试穿”流程与任务下载行为兼容。
- 审阅所有新增注释是否为必要的中文业务/安全说明；确认没有无关格式、依赖、配置、数据库结构或文档改动。

## 按顺序排列的实施阶段

### 阶段一：前置检查与接口冻结

- 主代理检查工作区差异和当前实现入口，确认子代理文件所有权未与现存用户修改冲突。
- API、Web 子代理依据已确认技术文档冻结结构化动作、成功附件、处理中/失败状态及 SSE/历史表示；任何无法兼容的差异先报告，不自行修改契约。

### 阶段二：API 与 Web 并行实现

- API：扩展聊天 Body 的 Zod schema 和 DTO 文档；在服务端将结构化动作绑定到当前认证用户并确定性调用试穿工具；通过试穿公开 Port 建立/等待现有任务；将受检成功图作为临时模型输入；把安全任务摘要绑定到助手展示结构；补齐 trace/history 隐私、失败、超时、断连和兼容测试。
- Web：把已开启商品卡的“试穿”改为聊天内操作；复用现有颜色、照片、上传和同意能力；提交 `tryOnAction`；处理生成进度和稳定错误；严格解析最终及历史 `tryOnResult`，经本人任务接口取图并渲染。不得从助手 Markdown 或任意工具输出提取图片地址。
- 两代理仅分别操作 `apps/api` 与 `apps/web`，接口问题提交主代理协调；不共享编辑文件。

### 阶段三：子代理自检与主代理集成审阅

- API 子代理先运行相关单测和 API typecheck；Web 子代理运行 Web typecheck/build。两侧报告完整修改清单和结果。
- 主代理审查实际差异、确认模块依赖方向及协议一致性；先处理跨端偏差，再执行全量验证。
- 不新增数据库结构。若实际需要 Entity、Migration、路由、依赖、供应商政策或结果生命周期变更，立即停止并回到设计/技术审批，不在当前批准范围内实现。

### 阶段四：自动化、数据库与构建验证

- 先运行新增/受影响 API 单元测试，覆盖 Zod 边界、唯一调用、工具/任务失败、结果归属、模型图像输入、trace/history 隔离和旧聊天兼容；默认测试使用 fake，不访问真实凭据。
- 再按顺序运行 API typecheck、API 全量测试和 API build；运行 Web typecheck 与 build；最后运行仓库 `pnpm check`、格式检查及 `git diff --check`。有共享输出目录的命令串行运行。
- 如需真实 PostgreSQL 展示/流式持久化验收，使用 `RUN_CHAT_DISPLAY_POSTGRES_SMOKE=1` 和测试源码要求的 `DB_NAME=clothes_guide_chat_display_test_<唯一后缀>`；核实配置最终解析到该隔离库，串行运行并确认只清理本次创建的数据。门控条件或目标库不清楚时跳过并报告，禁止对默认 `clothes_guide` 或未核验数据库运行 `migration:fresh`。
- 只有在实现确实触及数据库行为且既有 PostgreSQL Smoke 无法覆盖时，才提出新增数据库测试门控；先确认测试库名、初始化、清理和串行策略，不因本功能预先运行无关迁移测试。

### 阶段五：浏览器和合成图片模型 Smoke

- 在本地开发环境用测试账号走完整界面：打开符合资格的商品卡、选择颜色、选择或上传合成照片、明确同意、查看生成状态、加载结果和历史恢复；检查断连/失败提示、下载过期或任务删除、未登录跳转及窄屏布局。
- 使用合成/公开测试照片与实际配置的 OpenAI-compatible 图像生成及聊天模型验证图片块兼容性。该外部 Smoke 与自动化测试分开串行执行，不上传真实用户照片；无凭据、环境开关关闭或供应商未审查时明确标记未执行。
- 生产真实人像处理仍关闭。开发 Smoke 不能替代供应商留存、处理地区、禁止训练和删除保障审查，也不能据此启用生产真实照片功能。

## 验收标准

- 商品卡点击在用户选定照片并明确同意后，通过结构化动作确定性调用聊天试穿工具；普通文本聊天不意外启动试穿。
- 服务端重新查询商品并校验认证用户、照片、同意、额度和活动任务；任何校验失败都不调用图像供应商。
- 生图复用现有任务、worker、provider 和私有存储；成功图片只作为受检的本轮临时多模态输入进入聊天模型。
- 最终聊天回复以受控任务引用交付，前端只通过当前用户权限 API 获取结果并渲染；不在普通消息、trace、activity、日志或历史中保存图片字节和私有 URL。
- 超时和断连不会重复建任务或伪造任务取消；模型失败后已生成结果仍可通过本人任务页读取。
- 自动化验证覆盖安全边界和兼容路径；数据库、浏览器及外部模型/图像供应商 Smoke 的执行与跳过情况如实记录。
- 没有新增依赖、API 路由、Entity、Migration、环境变量或未经批准的真实人像处理。

## 实现协议

- SSE 过程事件 `try-on-status` 仅承载 `{ taskId, status }`，其中 `status` 为 `queued` 或 `processing`。
- 成功结果只通过 `done.tryOnResult`、普通聊天响应顶层 `tryOnResult` 和助手历史展示 envelope 返回；结构固定为任务 ID、商品摘要及图片 MIME/尺寸，不含图片地址。
- 失败或等待超时通过 `done.tryOnStatus`、普通聊天响应顶层 `tryOnStatus` 和助手历史展示 envelope 返回，状态为 `failed` 或 `timed_out`，附稳定错误码及可选任务 ID。
- 生图成功但聊天模型调用失败时，保存固定的服务端降级文案和成功结果附件；最终 trace 标记 `status: failed`，并只记录固定的 fallback 来源与错误码，不伪装成模型成功，也不保存图片内容。

## 风险和停止条件

- 真实照片供应商审查或生产开关状态不符合现有契约：停止真实人像处理验证，不通过配置或测试绕过。
- LangChain/OpenAI-compatible 模型不能接收合成图像块，或图片会被持久化：停止集成，不退化为将 Base64、签名 URL 或对象键写入工具文本。
- `virtual-try-on` 无法在不暴露 Entity、存储键和私有实现的情况下提供本人任务状态/结果字节：停止并重新评审模块 Port，不从聊天模块直连存储。
- SSE、反向代理或供应商时限无法支持任务等待：停止同步模型链路实现并提交边界与超时数据，重新审批后续方案。
- PostgreSQL 测试目标不是明确的具名可销毁隔离库，或测试清理范围不能证明安全：跳过该测试并报告，不尝试默认库或破坏性迁移命令。
- 子代理发现契约矛盾、既有未提交改动冲突、需要更改公共 API/数据权限或超出所有权文件时：停止相关修改，保留当前工作并交由主代理处理。
