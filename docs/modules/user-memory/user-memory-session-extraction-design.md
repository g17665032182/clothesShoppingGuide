# 用户记忆会话批量提取设计

## 状态与审批边界

- 状态：已确认。
- 日期：2026-11-05。
- 确认记录：用户回复“可以”，批准 5 分钟空闲合并、离开聊天页尽力 flush，以及浏览器关闭通知仅作尽力补充的设计方向。
- 技术文档于 2026-11-05 获用户“确认”；实施文档也已确认并进入实施。
- 背景：当前每个成功保存的聊天轮次都会立即登记一个独立记忆任务，后台每秒轮询并逐任务调用模型；连续聊天可能产生多次重复提取。
- 所属模块：`apps/api/src/user-memory/`；聊天模块只通过记忆公开端口登记或释放任务。
- 相关契约：[用户记忆 CRUD 契约](../../contracts/user-memory-crud-contract.md)。

## 目标

- 合并同一会话中短时间连续完成的聊天轮次，减少模型提取调用。
- 用户离开聊天页时，尽量立即处理当前会话尚未开始的记忆任务。
- 离页通知未送达时，服务端仍能在安静一段时间后自动处理。
- 保留记忆开关、来源用户校验、敏感信息过滤、候选缓存、租约、重试及文档 generation 保护。

## 用户可见行为

1. 每轮聊天成功持久化后，记忆模块登记该轮来源，并把该会话的待处理任务安排在最后一轮持久化完成后的 5 分钟。
2. 5 分钟内同一会话继续聊天时，待处理轮次合并为一次提取；超时后进入后台队列，不阻塞聊天响应。
3. 用户通过应用内导航离开聊天页或切换会话时，前端尽力请求后端立即释放该会话待处理任务。请求失败不影响导航。
4. 关闭或崩溃浏览器时的通知只能尽力发送，不作为可靠触发条件；5 分钟空闲调度是兜底。
5. 正在处理的任务不被离页请求中断；离页请求只提前释放尚未开始的任务。
6. 记忆开关关闭时不登记新来源，已排队任务仍须遵循现有设置检查，不能在关闭后写入。
7. 提取模型仍只保存明确、稳定且符合安全规则的长期记忆；批量输入不得保存整段聊天记录。

## 范围

- 将一轮一任务调整为同会话待处理轮次可合并的任务输入；模型一次接收该批次中经过来源校验的用户/助手消息对。
- 同会话在后台任务已开始后产生的新轮次进入后续任务，不修改已领取任务的租约或候选。
- 增加认证接口 `POST /api/memories/tasks/flush`，请求为 strict Zod 对象 `{ conversationId: UUID }`，仅释放当前用户该会话中可领取的待处理任务；成功返回 `204`。用户无权访问的会话按 `404` 处理。
- 聊天页通过页面路由离开钩子触发 flush；页面卸载/浏览器关闭通知仅作为尽力补充，不等待其完成。
- 增加任务批次来源引用的持久化及对应 migration；数据库中只存消息 ID，不复制聊天正文。
- 补充任务合并、空闲重置、显式 flush、并发领取、重试候选复用、开关关闭、清空 generation 竞争和越权测试。

## 非目标

- 不在每条消息上立即生成用户记忆。
- 不要求浏览器关闭通知必定送达，不阻塞页面卸载等待提取完成。
- 不改变用户偏好提取频率或偏好任务生命周期。
- 不改变记忆文档 API、Markdown 格式、模型供应商、提示安全边界或 512 token 聊天上下文预算。
- 不因会话删除而清空已经形成的长期记忆。
- 不把整段聊天历史或模型原始输出持久化到记忆任务。

## 权限与错误

- flush 使用现有 JWT Guard 和 `@CurrentUser()`；请求中不接受 userId。
- conversationId 使用 `z.strictObject` 和 UUID 校验，拒绝额外字段。
- 不存在或不属于当前用户的会话统一返回 `404`。
- flush 对已处理、正在处理或不存在的待处理任务保持幂等并返回 `204`。
- flush 的数据库错误使用现有 Nest 错误映射；浏览器触发失败只记录安全错误，不阻止导航。
- 模型、数据库或对象存储失败沿用记忆任务重试与安全错误码，不影响聊天已保存结果。

## 数据与兼容性

- 新任务需要表达同一会话的一批来源消息对，仍只引用 `chat_messages` 中的 ID。
- 已有单轮任务必须能继续按单轮来源读取和重试；迁移不得丢失候选、尝试次数、租约、任务状态或文档 generation。
- 正在处理的任务不可被新的聊天轮次或 flush 改写。
- 技术文档阶段明确批次字段、唯一性策略、事务/锁顺序、任务合并边界及历史任务迁移方式。
- 不执行 `migration:fresh`；保留数据迁移须经专用数据库测试。日常 fresh 约定不替代兼容性验证。

## 验收标准

- 连续聊天期间，同一会话待处理轮次只产生合并后的模型提取批次；超过 5 分钟无新轮次后自动可领取。
- 切换会话或离开聊天页时，当前用户会话中尚未领取的任务立即可领取。
- 浏览器通知丢失、离线或请求失败时，5 分钟兜底仍能处理任务。
- 新轮次与正在处理任务并发时，不丢来源、不覆盖候选、不破坏租约；新轮次最终进入后续批次。
- 重试复用相同候选，重复运行不重复应用文档补丁。
- 关闭开关、清空文档、账号停用、跨用户会话、历史单轮任务和存储故障行为保持正确。
- API schema、认证、权限、HTTP 状态、migration、后端测试、类型检查、构建和 `pnpm check` 均通过。
