# 聊天天气查询设计文档

## 状态与上下文

- 状态：天气查询基础能力已实现；供应商按用户指示切换为高德本地 stdio MCP，见技术与实施文档。
- 业务目的：让聊天助手能查询用户明确指定城市的近 3 天天气预报，为当轮穿搭建议提供天气参考。
- 所属应用和负责人：`apps/api` 的 `chat-records` 负责聊天工具装配，LLM/MCP 适配由 `llm` 基础设施提供。
- 最后更新：2026-11-19

## 范围

- 包含：新增普通聊天工具 `get_weather_forecast`；用户提供城市名称，工具通过高德地图 MCP Server 查询近 3 天逐日天气。
- 结果只允许包含服务端白名单字段：地点、预报日期、日间/夜间天气、最高/最低温、降水、风向、风速、风级、湿度及数据更新时间。
- 天气查询仅供当前对话使用，不保存为用户偏好、长期记忆或摘要来源。
- 明确不包含：自动定位、读取 IP/设备位置、超过 3 天的预报、当前实况、空气质量、天气预警、地图/任意 URL 查询、穿搭自动执行及前端页面改动。
- 用户角色和权限：已登录的普通聊天用户；仅查询其明确输入的城市，不接受用户 ID 或坐标作为身份信息。

## API 或事件契约

- 不新增公开 HTTP API；复用现有 JSON 与 SSE 聊天入口以及 LangGraph `ToolNode`。
- 模型工具输入为单个城市名称，服务端执行严格 schema 校验和长度限制。
- 成功输出为经过白名单转换的近 3 天预报 JSON；不把 MCP 原始响应或调试信息暴露给模型。
- 服务不可用、超时、无结果或响应不符合预期时统一返回安全失败结果；助手不得猜测天气。
- MCP 工具只在高德 API Key 配置完整且远程工具开关开启时注册；通过本地 stdio 调用 `maps_weather({ city })`。

## 数据和行为

- 不新增数据库实体、迁移或用户资料字段。
- 天气来源是高德地图及其上游数据提供方；近 3 天数据是预报参考，不得表述为实时观测或官方气象预警。
- 高德 API Key 仅传给 MCP 子进程。天气工具输入/输出不记录于日志、activity 或后续模型历史；trace 只保存成功状态和预报天数。
- 最终自然语言聊天回答沿用现有消息持久化规则。
- 每轮最多调用天气工具一次，避免重复外部请求。
- MCP 断连或上游错误不得阻断普通聊天中不需要天气工具的请求；明确查询天气但调用失败时应如实告知暂时无法查询。

## 模块边界

- `chat-records` 负责天气工具按轮装配及该类查询的记忆/摘要来源隔离。
- `llm` 负责复用现有官方 LangChain MCP 适配器并管理 MCP 工具生命周期/注册。
- 不让聊天业务模块依赖 MCP Client 私有实现；使用稳定的适配器或窄 Port。
- 不让 MCP 服务决定聊天用户身份、权限、持久化策略或公开工具输出结构。
