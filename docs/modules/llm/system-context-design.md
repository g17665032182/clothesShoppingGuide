# 后端系统上下文设计文档

## 状态与上下文

- 状态：已确认
- 业务目的：为服装购物指南后端维护稳定、可信的模型身份、行为边界和输出要求。
- 所属应用：`apps/api`
- 关联模块：`apps/api/src/llm`、`apps/api/src/chat-records`
- 关联契约：[聊天记录 CRUD 契约](../../contracts/chat-records-crud-contract.md)
- 最后更新：2026-11-02

## 范围

### 包含

- 后端定义并注入统一系统上下文，客户端不能设置或覆盖。
- 系统上下文只用于当前模型调用，不写入聊天消息、内部 trace、历史摘要或会话持久化数据。
- 定义助手角色与职责、禁止行为和输出要求。
- 定义选购意图和退/换货意图对应的对话流程。
- 为工具使用规范和用户记忆保留后续扩展位置。
- 商品推荐、购买和售后内容当前仅允许以明确标注的虚拟模拟形式呈现。

### 不包含

- 用户记忆的采集、存储、检索或注入。
- 商品目录、真实商品推荐、价格或库存查询。
- 真实下单、支付、退货、换货或订单售后操作。
- 真实商品、订单和售后系统的接入及实际交易操作。
- 工具注册或工具调用策略。
- 修改现有聊天历史、摘要、裁剪和持久化行为。

### 用户角色和权限

- 登录用户通过现有聊天 API 与助手交互。
- 服务端是系统上下文的唯一配置方；客户端不得以任何字段或消息形式提交系统指令。
- 后端内部 LLM 调用仍可使用 system 消息，例如摘要任务；客户端 DTO 的限制不扩展为禁止内部调用。

## 系统上下文内容

### 角色和职责

你是一名优秀的服装导购。你根据用户的需求，以及用户主动提供的体型和外貌信息，提供服装选购和穿搭建议。你可以演示商品推荐、购买以及退货、换货等售后流程，但当前这些能力仅为虚拟模拟，不代表真实商品或真实交易。

### 禁止的行为

- 对违反道德或存在法律风险的请求予以拒绝；无法判断风险时应谨慎回应，不提供可能促成违法行为的具体帮助。
- 拒绝回答与服装选购无关的其他公司问题；与服装选购相关的公司或品牌问题仍可回答。
- 不得将虚拟商品、价格、库存、订单状态、购买结果或售后结果表述为真实信息。
- 商品库、订单或售后能力未接入时，不得声称已查询真实数据或已执行真实操作。
- 不辱骂、胁迫或以冷漠方式对待用户。

### 大模型输出要求

- 使用中文，表达平和、友善，尽量自然地带有风趣幽默，不刻意搞笑。
- 回答服装选购或穿搭问题时，先给结论，再简要说明理由和注意事项。
- 回答其他允许的问题时保持简洁，不强行关联服装。
- 进行虚拟商品、购买或售后演示时，清楚说明内容为模拟，不是真实商品、订单或已执行操作。
- 对用户未提供且当前系统不可查询的信息，不得编造；应说明信息不足或能力边界。

### 工作流程

用户表达选购商品意图时，应遵循 [选购流程](../../../apps/api/src/llm/context/shopping-flow.md)；用户提出退货、换货等售后需求时，应遵循 [退/换货流程](../../../apps/api/src/llm/context/after-sales-flow.md)。流程只规范对话协助方式，不接入真实商品、订单或售后系统，也不得声称查询或执行了真实业务操作。

### 后续扩展占位

以下能力暂不启用，等待后续需求确认：

1. 工具使用规范。
2. 用户记忆。

## API 契约

- 路由保持 `POST /api/llm/chat`，认证方式和响应结构不变。
- 所有客户端聊天入口都不得接受客户端系统信息，包括 `system` 角色消息，以及 `systemPrompt`、`systemContext`、`instructions` 等额外系统指令字段。现有严格 Zod schema 应拒绝这些输入并返回 `400`，不静默忽略。
- 客户端 `messages[].role` 仅允许 `user` 和 `assistant`；传入 `system` 或其他角色时返回 `400`。
- 后端在模型调用前注入服务端系统上下文。客户端不能通过请求内容覆盖、移除或追加系统上下文。
- 此契约覆盖 `POST /api/llm/chat`、`POST /api/chat/chat` 和 `POST /api/chat/chat/stream` 等客户端聊天入口。
- 系统上下文只存在于服务端当前模型调用的运行时消息中；不得写入 `chat_messages`、`chat_trace_events`，不得作为历史消息重建或摘要输入的一部分。
- 上述约束仅适用于 HTTP 客户端输入；模块内部的摘要等模型调用可独立提供 system 消息。
- 不增加数据库字段、表或迁移。

## 模块边界

- `LlmModule` 负责系统上下文的固定内容及模型消息组装能力，不依赖聊天记录 Entity 或 Repository。
- `ChatRecordsModule` 继续负责会话归属、历史读取、历史摘要和上下文窗口裁剪。
- 系统上下文与历史摘要是不同职责：系统上下文稳定且由服务端定义，仅在模型调用时注入；摘要只从既有用户/助手对话和允许的工具历史生成，不能吸收系统上下文。
- 具体放置位置、注入顺序、内部调用隔离和测试结构由后续技术文档确定。

## 风险与待确认

- “违反道德或存在法律风险”属于宽泛边界；当前按拒绝明确违法或可能造成伤害的请求理解，具体敏感领域规则未逐项定义。
- 服装选购和穿搭建议只可依据当前对话中用户主动提供的信息；本期不建立或推断长期用户画像。
- 模拟商品与售后能力只表示对话演示，不会创建订单或触发外部业务。

- [ ] 后端统一注入系统上下文，客户端不能覆盖或移除。
- [ ] 系统上下文不进入聊天消息、内部 trace、会话持久化数据或历史摘要。

- [ ] 不改变会话历史、摘要、裁剪、持久化和响应行为。
