# 对话地址管理界面请求设计文档

## 状态与上下文

- 状态：设计、CRUD 契约、技术方案与代码实施已完成；自动化测试和登录态浏览器验收暂缓。
- 最后更新：2026-11-16。
- 业务目的：用户在聊天中明确提出新增、修改或管理收货地址时，允许模型请求打开现有本人地址管理页面。
- 所属模块：`apps/api` 聊天工具编排；地址数据和写入继续由 `user-addresses` 模块及账号页面负责。
- 需求依据：[对话工具能力清单](./chat-tool-capability-inventory.md)、[对话工具扩展设计](./chat-tool-expansion-design.md)、[收货地址簿与 LLM 查询设计](../user-addresses/user-addresses-design.md)。
- 配套契约：[聊天地址管理界面请求 CRUD 契约](../../contracts/chat-tool-address-form-crud-contract.md)。

本设计只覆盖“请求打开地址管理界面”。地址读取、创建、修改、删除、默认地址设置和提交确认仍由现有认证页面与地址 API 负责，模型不获得地址写入权限。

## 范围

### 包含

- 新增模型工具 `request_address_form`，供用户明确要求管理本人收货地址时调用。
- 首版请求导航至现有本人地址管理路由 `/account/addresses`。
- 前端收到受限 SSE 事件后，使用现有命名路由执行导航，并根据真实导航结果显示固定 Toast。
- 用户在地址管理页面自行新增、编辑、删除和设置默认地址；所有写入继续经过既有认证 API、归属校验、幂等和并发规则。
- 工具结果只表达“导航请求已接受”或固定不可用状态，不回显地址内容。

### 不包含

- 在聊天消息内新增地址动态表单或地址确认卡。
- 模型读取、预填、展示或总结姓名、手机号、完整地址、地址标签或地址 ID。
- 模型创建、修改、删除地址，设置默认地址，或代替用户点击保存。
- 自动打开“新增地址”弹窗、自动进入某条地址的编辑状态，或绑定具体地址记录。
- 接收或执行模型提供的 URL、路由、用户 ID、会话 ID、地址 ID、请求键或 API 路径。
- 新增地址 HTTP API、Entity、字段、Migration、服务端草稿或跨会话表单持久化。
- JSON 聊天中的导航工具，除非后续另行设计并确认 JSON UI 事件协议。

## 用户流程

1. 用户明确表达“管理收货地址”“新增地址”或“修改地址”等意图。
2. 模型在适用时调用 `request_address_form`。
3. 服务端严格校验工具参数，并在当前聊天运行中记录一次性地址导航请求。
4. SSE 流发送固定的 `address-form` 事件；事件不进入聊天消息、公开展示数据、长期记忆或数据库。
5. 前端确认事件属于当前活动会话和当前账号后，导航到固定的 `account-addresses` 路由。
6. 导航成功后显示固定成功 Toast；路由失败、事件过期或认证失效时显示失败 Toast 或安全丢弃，不向模型伪报页面已打开。
7. 用户在地址管理页明确执行新增、编辑、删除或默认地址操作；地址模块继续负责所有字段校验、权限和持久化。

导航请求不承诺保留页面未提交内容。刷新、关闭页面、切换账号或切换会话后，未保存表单可以丢失，遵循现有页面生命周期。

## 工具输入与结果

### 推荐首版输入

推荐首版只接受严格空对象 `{}`，表示打开地址管理页：

```json
{}
```

这样可以避免模型控制具体编辑目标、绕过用户主动操作，且与现有账号页面能力保持最小耦合。

### 不支持的可选输入

首版不增加 `mode`。即使未来需要表达“管理”或“新增”的界面提示，也须另行设计并确认；工具不能自动打开新增弹窗或编辑指定地址。

```json
{
  "mode": "manage"
}
```

或：

```json
{
  "mode": "create"
}
```

### 安全结果

工具返回固定安全结构，例如：

```json
{
  "ok": true,
  "code": "requested"
}
```

不可用时返回：

```json
{
  "ok": false,
  "code": "unavailable"
}
```

结果不得包含完整地址、姓名、手机号、地址标签、地址 ID、用户 ID、会话 ID、URL、异常原文或自由文本。`requested` 只表示服务端已接受导航请求，不表示浏览器已完成导航。

## 事件与兼容性边界

- 推荐沿用 `request_preference_form` 的 SSE-only 一次性导航模式。
- 事件名称建议为 `address-form`，载荷首版为空对象：

```json
{
  "type": "address-form"
}
```

- 同一轮重复调用只处理第一次有效请求；后续聊天轮次可以再次请求。
- 事件只存在于当前运行内存，不能写入聊天正文、展示 envelope、trace 原始参数、activity 详情、长期记忆或跨会话存储。
- 前端只允许将事件映射到固定 `account-addresses` 命名路由，不执行模型提供的路径或脚本。
- 仅 SSE 注册该工具；JSON 聊天不注册。
- 地址管理页面仍由现有 `user-addresses` API 加载本人完整地址；导航工具不改变地址 CRUD、默认地址、幂等保存或订单收货快照语义。

## 权限、隐私与模块边界

- 用户和会话归属来自现有认证聊天上下文，工具 schema 不接受 `userId`、`conversationId` 或任何目标身份参数。
- `chat-records` 只负责工具装配和一次性导航事件，不导入地址 Entity、Repository、私有 DTO 或完整地址 schema。
- `user-addresses` 继续负责地址字段、归属、默认地址唯一性、`requestKey` 幂等、并发冲突和删除规则。
- 地址完整值只在本人认证地址页面/API 和订单收货快照边界内流转，不进入模型工具输入/输出、trace、activity、通用摘要或长期记忆。
- 工具不能代替用户保存地址，也不能把聊天中的自然语言地址自动转换成持久化写入。
- 导航失败不能降级为“地址已保存”或“地址已更新”；模型只能继续引导用户打开页面或重试。

## 错误与降级

| 情况                                     | 行为                                           |
| ---------------------------------------- | ---------------------------------------------- |
| 参数为空对象                             | 接受并请求打开固定地址管理页                   |
| 参数含未知字段、身份字段、URL 或地址字段 | 工具输入无效，不导航                           |
| 当前认证/聊天上下文不可用                | 返回固定 `unavailable`，不导航、不读写地址     |
| SSE 事件无法解析或载荷不符合白名单       | 前端丢弃，不执行导航                           |
| 同一轮重复调用                           | 只处理第一次有效调用                           |
| 用户切换账号、会话或离开聊天页           | 丢弃陈旧请求，不在之后恢复导航                 |
| 路由导航失败或被取消                     | 客户端显示固定失败 Toast，不回传模型、不写地址 |
| 地址页面加载失败                         | 沿用地址页面现有错误状态，不由工具伪造成功     |
