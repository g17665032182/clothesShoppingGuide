# LangGraph 节点级聊天历史持久化设计

## 状态与上下文

- 状态：已确认
- 业务目的：通过 LangGraph 节点记录完整聊天执行过程，使模型工具调用和工具结果可持久化，同时不向前端展示内部工具事件。
- 所属应用：`apps/api`
- 关联模块：`apps/api/src/llm`、`apps/api/src/chat-records`
- 关联契约：[`chat-records-crud-contract.md`](../../contracts/chat-records-crud-contract.md)
- 最后更新：2026-10-29

## 需求确认

已确认：

1. 工具调用过程只做服务端持久化，不在用户聊天详情接口中展示。
2. 使用 LangGraph `addNode` 增加持久化节点，不采用 Checkpoint 作为本次改造的主要记录方案。
3. 保留现有会话列表、会话详情、管理员查询、分页、删除和标题生成能力。
4. LLM 通用模块不能直接依赖聊天业务 Entity 或数据库 Repository。

实施决策（由用户授权代理确定）：

1. 单事件 payload 序列化后最大为 `32768` 字节；超限时拒绝写入并使本次 Graph 调用失败。
2. V1 在写入前递归掩码常见凭证字段；不替代未来按工具增加 allowlist 或专属脱敏器。
3. 流式接口纳入本次范围：模型分段输出的 tool call 先在服务端累积，等调用参数完整后再执行工具；工具结果返回后持久化并继续调用模型，前端只接收可展示文本。
4. 工具执行期间不新增 SSE 心跳，保持现有事件契约。

## 范围

### 包含

- 在 Graph 中增加输入事件、模型事件和工具事件持久化节点。
- 持久化用户消息、模型普通回复、模型工具调用、工具结果和失败状态。
- 使用会话 ID 关联内部事件，使用请求级 `runId` 和工具调用 ID 保证幂等。
- 流式模型输出中的工具调用片段只在服务端聚合，不通过 SSE `delta` 事件下发给前端。
- 在下一轮请求中读取内部事件并重建 LangChain 消息，使模型能够理解之前的工具调用结果。
- 保持现有前端聊天接口只返回用户消息和最终助手回复。
- 保留现有聊天记录表作为前端展示投影，具体投影写入方式由技术设计确定。

### 不包含

- LangGraph Checkpoint、Graph 中断恢复和时间旅行调试。
- 将工具调用参数、工具结果或内部错误直接返回前端。
- 新增商品、穿搭、RAG、向量数据库或其他业务工具。
- 修改客户端请求格式以传入工具、数据库连接或持久化参数。
- 管理员修改或删除单条内部工具事件。

## 用户角色与权限

| 角色     | 能力                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 登录用户 | 创建和继续自己的会话；读取自己的用户消息和助手回复；删除自己的会话          |
| 管理员   | 按现有管理员接口读取会话和可展示消息；不通过公开 API 读取内部工具参数和结果 |
| 服务端   | 在 Graph 节点中写入内部事件；服务端负责会话归属、脱敏和清理                 |

普通用户和管理员访问会话时，必须先通过现有会话归属规则校验 `conversationId`，不能仅凭客户端传入的 ID 读取内部事件。

## 运行架构

```text
POST /api/llm/chat
        |
        v
ChatRecordsService
        |
        v
LlmService
        |
        v
LangGraph
  START
    -> persistInput
    -> chatModel
    -> persistModelEvent
    -> route
         |-- 无工具调用 -> END
         |-- 有工具调用 -> tools
                            -> persistToolEvent
                            -> chatModel
```

### 节点职责

| 节点                | 职责                                       | 记录内容                                    |
| ------------------- | ------------------------------------------ | ------------------------------------------- |
| `persistInput`      | 记录本次请求中需要进入会话上下文的用户消息 | 用户消息、`conversationId`、`runId`、顺序   |
| `chatModel`         | 调用大模型，不直接访问数据库               | 模型响应交给下一个持久化节点                |
| `persistModelEvent` | 记录每次模型输出                           | 普通回复或工具调用、模型、Token 用量        |
| `tools`             | 使用 LangGraph `ToolNode` 执行工具         | 工具实际执行结果交给下一个持久化节点        |
| `persistToolEvent`  | 记录工具执行结果                           | 工具名、调用 ID、参数、结果、成功或失败状态 |

持久化节点只负责调用抽象的事件写入接口，不直接引用 `ChatMessage` Entity、MikroORM Repository 或具体业务工具。

## 内部事件模型

建议新增内部事件资源，例如 `chat_trace_events`。该资源不直接映射为前端消息 API。

| 字段             | 说明                                                  |
| ---------------- | ----------------------------------------------------- |
| `id`             | 服务端生成的事件 ID                                   |
| `conversationId` | 所属聊天会话                                          |
| `runId`          | 一次聊天请求的唯一 ID                                 |
| `sequence`       | 同一运行中的事件顺序                                  |
| `eventType`      | `input`、`model_response`、`tool_call`、`tool_result` |
| `messageId`      | 对应 LangChain 消息 ID，可为空                        |
| `toolCallId`     | 工具调用 ID，工具事件使用                             |
| `toolName`       | 工具名称，工具事件使用                                |
| `content`        | 可展示文本或规范化错误摘要                            |
| `payload`        | 结构化参数、工具结果或供应商元数据，内部字段          |
| `status`         | `success`、`failed` 或 `partial`                      |
| `model`          | 模型名称，模型事件使用                                |
| `usage`          | Token 用量，模型事件使用                              |
| `createdAt`      | 事件创建时间                                          |

`payload` 不对外返回，写入前必须执行长度限制和脱敏。原始供应商响应、API Key、Token 和数据库连接信息不得保存。

## 前端展示与历史重建

- 现有 `chat_messages` 继续作为用户可读的消息投影，查询接口只返回 `user` 和最终 `assistant` 消息。
- 工具调用和工具结果只写入内部事件资源，不出现在普通用户和管理员的消息分页响应中。
- 工具调用片段、工具参数和工具结果不进入 SSE `delta`。
- 下一轮模型调用需要按 `sequence` 读取内部事件，并重建 `HumanMessage`、带 `tool_calls` 的 `AIMessage` 和 `ToolMessage`。
- 上下文裁剪和摘要仍然适用；内部工具事件不能绕过上下文窗口限制。
- 摘要可以保留工具执行产生的业务结论，但不应直接把完整工具参数和完整原始结果注入摘要。

## 一致性、重试与失败语义

- `runId + sequence` 必须具备幂等约束，避免 Graph 重试产生重复事件。
- `toolCallId` 在工具调用记录和工具结果记录之间保持关联。
- 工具执行失败也要记录失败状态和经过脱敏的错误摘要。
- 模型最终回复失败时，之前已经成功写入的输入、模型和工具事件保留，便于排查；前端请求仍返回统一的上游调用错误。
- 新会话在 Graph 开始前创建以满足 trace 外键；客户端取消时删除该新会话及其 trace，模型或工具失败时保留会话和已提交 trace，但不保存半成品展示消息。
- 事件写入失败时，默认让当前 Graph 调用失败，不返回一条无法追溯的成功回复。
- 删除会话时必须级联删除内部事件，不能留下脱离用户归属的工具数据。
- 并发请求需要按会话和运行 ID 隔离，不能把一个请求的事件写入另一个会话。

## API 行为

现有公开 API 路径保持不变：

| 操作                                    | 行为                                                     |
| --------------------------------------- | -------------------------------------------------------- |
| `POST /api/llm/chat`                    | 执行 Graph，保存内部事件，返回最终助手回复和现有会话信息 |
| `GET /api/chat/conversations/:id`       | 只返回用户消息和最终助手回复，不返回工具事件             |
| `GET /api/admin/chat/conversations/:id` | 保持现有管理员查询范围，不返回工具参数和原始工具结果     |
| `DELETE /api/chat/conversations/:id`    | 同时删除展示消息和内部事件                               |

请求体不增加工具或持久化字段，客户端不能控制事件归属、保存策略或脱敏规则。

## 模块边界

### `LlmModule`

- 定义 Graph 状态、节点和事件写入抽象。
- 负责把模型输出和 `ToolNode` 输出转换为规范化事件。
- 不引用聊天 Entity、用户 Entity 或 MikroORM。

### `ChatRecordsModule`

- 负责会话归属、用户权限、事件持久化和展示消息投影。
- 负责从事件记录重建下一轮模型上下文。
- 负责删除会话时清理关联事件。

### 禁止耦合

- `LlmModule` 不直接查询或写入 `chat_conversations`、`chat_messages` 或内部事件表。
- Controller 不直接操作 Graph 状态或数据库。
- 前端不依赖 LangChain 消息对象、工具参数结构或数据库内部字段。

## 数据迁移与兼容

- 新增内部事件表、索引和会话外键。
- 现有 `chat_conversations` 和 `chat_messages` 保留，避免破坏已有查询接口。
- 已有历史消息没有工具事件，可继续作为普通 user/assistant 上下文使用。
- 新旧写入逻辑切换需要避免同一轮同时产生重复的展示消息。
- 迁移必须先审查 SQL、索引、外键级联和历史数据兼容性，再执行数据库验证。

## 验收清单

- [ ] 用户消息、模型回复、工具调用和工具结果均由 Graph 节点写入。
- [ ] 工具事件不会出现在用户或管理员的公开消息响应中。
- [ ] 下一轮对话能够重建之前的工具调用上下文。
- [ ] 同一运行重试不会产生重复事件。
- [ ] 工具失败和模型失败的记录语义符合本设计。
- [ ] 普通用户、管理员和删除操作的权限边界保持不变。
- [ ] 流式工具调用聚合、执行、持久化和后续模型输出顺序符合契约。
- [ ] 契约、迁移、测试和验证命令全部更新。
