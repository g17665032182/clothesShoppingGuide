# 对话偏好编辑界面请求设计文档

## 状态与上下文

- 状态：已确认；已实施。
- 最后更新：2026-11-16。
- 业务目的：用户在聊天中表达希望修改已保存的穿衣偏好时，允许模型请求打开现有偏好管理页面。
- 所属模块：`apps/api` 聊天工具编排；界面继续由 `apps/web` 偏好管理页面负责。
- 需求依据：[对话工具能力清单](./chat-tool-capability-inventory.md)、[扩展设计](./chat-tool-expansion-design.md)和本轮需求访谈确认。
- 相关契约：[用户偏好 CRUD 契约](../contracts/user-preferences-crud-contract.md)、[聊天偏好编辑界面请求契约](../contracts/chat-tool-preference-form-crud-contract.md)。

本设计仅覆盖请求打开偏好管理页面及可选类别预选，不新增聊天内动态表单，不授予模型任何偏好写入或设置修改能力。

## 范围

### 包含

- 新增模型工具 `request_preference_form`，供用户明确要求管理或修改本人已保存偏好时调用。
- 工具仅请求导航至现有 `/account/memories?view=preferences` 偏好管理视图。
- 可选预选一个既有偏好类别；类别必须来自服务端允许列表。
- 成功导航后，在聊天中显示固定的“已打开偏好管理”结果。
- 用户在现有偏好管理页面自行新增、编辑、删除和确认提交。

### 不包含

- 在聊天消息内渲染新的偏好动态表单或偏好编辑器。
- 模型读取、预填或展示已保存的偏好值。
- 模型创建、修改、删除偏好，修改偏好开关，或代替用户提交。
- 自动选择“添加”或“编辑”具体记录、自动打开某条偏好的编辑器。
- 在刷新、关闭页面或切换会话后恢复未提交草稿。
- 新增偏好 API、数据字段、Entity、迁移、存储或独立持久化草稿。

## 用户流程

1. 用户明确提出修改或管理本人穿衣偏好的需求。
2. 模型可调用 `request_preference_form`，可选传入一个有明确语义依据的偏好类别。
3. 服务端校验请求，仅向当前用户的现有偏好管理路由发出导航请求；不读取偏好值。
4. 前端在当前会话内执行路由导航。若类别存在，只预选对应类别，不自动提交或确定某条记录。
5. 导航成功或失败后，客户端使用固定 Toast 反馈实际路由结果；模型不得声称页面已打开。
6. 用户在偏好管理页确认变更；既有认证 CRUD API 和校验继续作为唯一写入入口。

用户在导航前或导航后的未保存修改不构成草稿持久化承诺。页面刷新、关闭或切换账号/会话时，未保存内容可以丢失，并应遵循现有页面行为。

## 工具输入与结果

输入为严格对象，只有可选的 `category`：

```json
{
  "category": "shoe_size"
}
```

允许的 `category` 沿用偏好领域九类：`size`、`shoe_size`、`fit`、`style`、`color`、`occasion`、`budget`、`avoidance`、`purchase_preference`。省略类别表示打开默认偏好管理视图，不由模型猜测。

成功结果仅使用固定状态和可选类别，不包含偏好值、偏好 ID、用户 ID、会话 ID 或其他个人资料。服务端通过现有聊天运行事件向前端表达导航意图；实际页面打开状态以客户端导航结果为准。

## 权限、隐私与兼容性

- 用户和会话绑定使用当前认证聊天上下文，不接受模型提供的用户、会话或目标 URL。
- 类别是导航提示，不代表用户授权修改，也不影响 CRUD 权限。
- 工具执行不得调用偏好读取或写入入口，不改变偏好开关。
- 工具参数和结果采用白名单；trace/activity 不记录偏好值或个人资料。
- 偏好开关关闭时，手动管理页面仍可用，符合既有偏好契约。
- 首版仅通过现有 SSE 流式通道发送一次性导航事件；JSON 聊天不注册该工具。继续复用现有前端路由，不新增 HTTP 路由或动态表单事件。
- 不改变既有偏好 CRUD 路由、数据和校验，不要求数据库迁移。

## 错误行为

- 输入结构非法、类别未知或含额外字段：拒绝请求，不导航。
- 当前用户未登录或会话上下文不可用：不导航，返回固定不可用状态。
- 导航请求不可用或客户端导航失败：按技术文档定义的固定状态处理；不暗示页面已打开，不执行任何偏好写入。同一轮仅处理首次有效请求，后续轮次可再次请求。
- SSE 事件发送失败或事件无法送达客户端时，不得把工具返回的 `requested` 描述为导航成功。

## 验收标准

- [ ] 工具仅在用户明确提出偏好管理/修改需求时适用。
- [ ] 无类别请求打开现有偏好视图；合法类别只作为预选提示。
- [ ] 不读取、回显或预填偏好值，不自动进入某条记录的编辑状态。
- [ ] 所有偏好写入仍须用户在现有页面确认，并由既有认证 API 执行。
- [ ] 未知类别、额外字段、用户/会话/URL 等伪造参数均不能导致越权或导航。
- [x] 成功和失败结果与前端实际导航结果一致；JSON/SSE 不引入未注册的任意 UI。
- [ ] 切换会话、刷新和关闭页面不承诺恢复未保存草稿。
- [ ] 未新增路由、迁移、依赖或偏好写入权限。
