## 目标与非目标

让用户在聊天中查询已有业务事实：本人最近的试穿任务、某件商品的真实规格组合，以及本人已保存的穿衣偏好。模型负责解释查询结果，领域模块仍负责事实、归属和当前状态。

本设计不增加模型写入权限，不提供任意查询工具，不新增外部数据源、后台任务、数据库表或迁移。不开放创建试穿、选择照片、同意照片处理、地址写入、偏好写入、正式下单、支付、取消及确认收货等模型工具。

## 用户角色与共同规则

- 只处理当前启用账号本人有权查询的资源。用户和会话来自认证上下文，工具不接收 `userId` 或 `conversationId`，管理员身份也不扩大聊天查询范围。
- 仅在本轮有明确查询意图时调用对应工具。普通推荐继续使用已有偏好上下文，不能为补充推荐无关地读取试穿历史或全部偏好。
- 工具参数和结果均使用严格字段白名单，禁止动态选择数据库表、字段、URL、组件或校验代码。
- 空列表、依赖失败和越权是不同状态。依赖失败不能解释成“没有记录”或“没有货”，部分结果不能解释成完整列表。
- 查询结果只代表读取时的事实，不构成库存预占、生成成功承诺、用户同意或操作授权。

## 本人试穿任务查询

### 入口与交互

用户询问“我上次试穿完成了吗”或“最近有哪些试穿任务”时，调用 `get_my_information` 并显式指定 `sections: ["try_on_tasks"]`。

默认查询最近一页未删除任务，按创建时间倒序，每页最多 5 条、页码 1–10。允许用独立的 `tryOnStatus` 筛选 `queued`、`processing`、`succeeded`、`failed`，不复用订单 `status`。相同创建时间须有稳定次序。

“上次”解释为本人最新创建的未删除任务；存在商品或时间歧义时展示有限摘要并询问。首阶段不增加任务 ID 详情查询工具，也不承诺找出超出分页范围的任意历史任务。

### 结果与操作边界

模型只获得任务安全引用、状态、商品外部标识/名称/类别/颜色、创建和完成时间，以及结果当前是否可查看。不返回输入照片引用、图片内容、结果 ID、下载链接、对象键、供应商信息或原始失败原因。

助手可以说明“正在处理”“生成失败”或“已生成，可到我的试穿查看”，不评价未读取的图片内容，也不估算完成时间。用户自行进入现有 `/account/try-ons` 查看或下载；本阶段不新增聊天结果卡片、自动轮询、通知订阅或自动标记已读。

读取历史任务不要求重新开启真实照片生成能力，也不绕过现有查看结果的认证和删除检查。

### 兼容

省略 `sections` 时继续只查原来的地址、订单、图片三个 section，避免默认扩大个人信息读取范围。显式 sections 可选择四类中的 1–4 类且不得重复；新筛选字段只允许与 `try_on_tasks` 同时出现。地址选择编排继续只处理原地址 section。

## 精确商品规格查询

### 入口与结果

用户明确问“这件衣服黑色 M 码有没有货、多少钱”时调用 `get_product_skus`。输入商品 `productExternalId`，可选颜色、尺码和页码；商品标识应来自本轮或已验证的历史商品引用，或用户明确给出的外部标识。只有商品名称或“这件”且无法唯一确定时先询问，不能猜测标识。

只查询有效商品下的有效规格，沿用当前目录支持的 CNY 价格及可售判断。每页最多 5 条、页码 1–10，返回颜色、尺码、十进制字符串价格、币种和 `inStock`，以及匹配总数和是否有下一页。不返回精确库存、预占量、成本价或内部 SKU ID。

### 筛选完整性

颜色和尺码按目录定义的规范化规则匹配，不做模型自行翻译、近似合并或推断。筛选必须作用于完整符合条件的规格集合，再排序和分页；不能先读取默认一页再在聊天层过滤，并据此断言没有该组合。

现有 `listSkus()` 只支持商品和分页参数。后续应由商品领域提供必要的有界公开查询能力，复用现有可售计算；本设计不规定具体 SQL 或端口签名。

商品不可用返回安全的不可查询结果；商品有效但没有匹配组合时返回成功空列表。匹配规格 `inStock: false` 才可回答该组合当前无货。购买时仍由原业务重读价格、规格和库存，不自动选规格或创建草稿。

## 本人偏好明细查询

仅在用户直接询问“我保存了哪些偏好”或“我保存的鞋码是多少”时调用 `get_my_preferences`。支持一个可选的既有偏好类别和有界分页，每页最多 5 条、页码 1–10。

只返回当前有效记录的 `category`、`valueType`、经原类别规则和安全规则验证的 `value`、`isPrimary`、`updatedAt`。不返回来源会话、来源消息、内部任务字段、完整记忆文档或用户标识。多条记录如实展示主偏好和更新时间，不替用户合并、删除或覆盖。

已有相关性上下文不是完整偏好清单，不能据此回答“全部已保存偏好”；完整查询须通过偏好领域的独立公开能力。读取失败不能用模型记忆补齐。

**第二阶段已确认：偏好开关关闭时，聊天明细工具不返回值，提示用户到偏好管理页面查看。** 关闭不删除偏好，手动管理保持可用，不提供“关闭推荐注入但仍允许明确查询”的例外。

## 后续候选的决策边界

| 候选                      | 需要先确认的事项                                                             | 本文明确保留的边界                                                                |
| ------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `request_address_form`    | 打开地址管理页还是聊天内表单；首版是否仅新增；编辑目标如何绑定和防止过期覆盖 | 完整地址由前端本人 API 读取和提交，不进入模型或通用展示元数据；默认地址不自动使用 |
| `request_preference_form` | 页面或表单；是否支持类别预选；未保存修改与切换会话的行为                     | 模型只请求界面，用户提交才写入；不能代删偏好或改设置                              |
| 物流摘要                  | 本地发货记录与承运商轨迹的区别；允许输出的物流字段及脱敏方式                 | 没有实时来源时只描述本地状态，不输出完整单号和收件信息                            |
| 店铺政策/售后知识         | 经审核的政策来源、适用范围、版本、维护人和过期处理                           | 无来源不承诺运费、时效、退换或退款，不声称可以办理                                |

这些候选不注册工具、不新增事件，也不借助任意动态表单或任意 URL 请求提前实现。

## 模块、数据与传输边界

- 聊天编排负责意图适用说明、绑定用户/会话、工具装配和安全输出；试穿、商品和偏好模块分别负责事实查询与领域校验。
- 跨模块仅调用公开入口或 Port，不从聊天模块访问其他模块的 Entity、Repository、存储服务或供应商客户端。必要的只读公开入口在技术阶段定义。
- 复用现有工具运行链路和 JSON/SSE 传输，不新增查询专用 HTTP 路由或 SSE 事件。查询正文可以进入现有 assistant 历史，但不新增原始工具 JSON 或资源结果卡片的持久化。
- 工具响应是本轮事实，不能将任务状态、库存或查询失败自动写入长期偏好和记忆。沿用既有来源资格和记忆契约，具体保护及回归方案在技术阶段说明。
- trace/activity 仅记录工具名称、有界筛选枚举、结果数量及固定状态，不记录偏好值、任务引用集合、照片或下载信息。安全投影须在进入运行事件和追踪前完成，不能只依靠前端隐藏。
- 已保存的旧消息和原展示 envelope 保持兼容。切账号清理会话状态，资源删除后重新查询当前状态，历史正文不构成可访问资源的凭据。

## 错误与降级

| 情况                       | 业务行为                                            |
| -------------------------- | --------------------------------------------------- |
| 非法、越界或未知输入       | 工具输入错误，不执行领域查询                        |
| 本人无记录或规格无匹配     | 成功空列表，保留分页语义                            |
| 依赖不可用                 | 固定 `unavailable`，允许用户重试，不返回异常原文    |
| 资源不存在、不可用或非本人 | 统一安全 `not_found`，不暴露他人资源是否存在        |
| 偏好开关关闭               | 已确认返回 `preferences_disabled`，不返回偏好值     |
| 单 section 失败            | 保留其他成功 section，失败 section 单独记录固定错误 |
| 结果超出页码或返回预算     | 提示到现有管理页继续查询；不静默截断并冒充完整结果  |

## 验收标准

以下为完整扩展方案的验收要求；第一、第二阶段实际结果分别见各自实施记录：

- [ ] 三类工具均拒绝未知参数、模型指定用户、非法枚举和越界分页。
- [ ] 试穿查询仅返回本人未删除任务；不触发生成、供应商调用、下载、删除或已读写入。
- [ ] 默认 sections 不扩大；新旧筛选组合、单 section 失败及地址选择分支保持兼容。
- [ ] SKU 过滤后分页覆盖超过一页的有效集合，区分无匹配、无货、商品不可用和依赖失败。
- [ ] 偏好明确查询与推荐注入分离，开关语义经确认；不发生写入、恢复旧任务或记忆串读。
- [ ] 原始领域字段不泄露到模型、trace、activity、日志或新展示元数据；恶意字符串只作为数据。
- [ ] JSON/SSE 使用相同安全结果；真实工具往返覆盖调用、结果反馈、追踪和公开历史。
- [ ] 登录态桌面及移动浏览器验证回答、失败重试、账号/会话切换及进入原管理页。
- [ ] 原商品推荐、购买弹框、地址选择、动态表单、订单查询和试穿动作回归通过。
