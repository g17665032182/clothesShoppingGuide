## 目标与范围

增加两个只读模型工具：

| 工具                 | 用户意图                                           | 权威来源                                        |
| -------------------- | -------------------------------------------------- | ----------------------------------------------- |
| `get_product_skus`   | 明确查询某件商品指定颜色、尺码的当前价格及有货状态 | 商品领域的有效商品、有效 SKU 及既有库存预占计算 |
| `get_my_preferences` | 明确查询本人已保存的偏好或某类别明细               | 独立结构化偏好领域及其开关                      |

仅向启用的已登录账号开放，私人查询绑定服务端当前用户，管理员没有跨用户旁路。复用既有聊天 JSON/SSE 通道，不新增 HTTP 路由、SSE 事件、卡片或页面。

不提供偏好写入、开关修改、SKU 选择、草稿更新、下单或库存预占；不提供记忆文档查询、试穿详情、物流或售后能力。不新增依赖、数据库字段、表、索引或迁移。

## 当前源码与复用边界

- `ProductCatalogService.listSkus()` 已提供下单界面的规格查询及可售判断，但没有颜色、尺码筛选，其响应含内部 SKU 标识及图片，不能直接作为模型结果。
- 商品搜索已有输入 trim、数据库 `lower` 比较的颜色和尺码匹配规则。第二阶段沿用该规则，不新增别名、翻译、Unicode 兼容归一化或跨品牌换算。
- `UserPreferencesReader.readContext()` 是相关性摘要，存在候选和输出数量限制，不能代表全部保存记录。
- `UserPreferencesService.list()` 返回管理字段，并调用可能创建默认设置记录的 `getSettings()`，不能直接用于纯只读工具。
- 现有偏好类别校验、安全文本校验及记忆来源资格可以复用；具体公开接口和查询机制在设计确认后的技术文档中定义。

## 精确规格查询

### 输入与商品确定

严格对象只接受 `productExternalId`、可选 `color`、可选 `size` 和可选 `page`。商品标识 trim 后 1–160 字符；颜色和尺码 trim 后 1–32 字符；拒绝控制字符。页码为实际整数 1–10，默认 1，不接受字符串数字、`pageSize`、内部 SKU ID、身份、SQL 或动作参数。

商品标识来自用户明确提供的外部标识，或本轮/已验证历史中可唯一确定的商品。只有名称或“这件”而无法确定商品时先询问，不能猜标识。历史引用只用于确定查询对象，当前可用性仍由服务端重读。

颜色和尺码分别按目录既有规则精确匹配；两者同时提供时必须同时匹配。不自动把“黑色”换成 `black`，不自动放宽无匹配条件。

### 结果与分页

只查询有效商品下有效且币种为 CNY 的 SKU。过滤完整匹配集合后稳定排序，再分页；每页 5 条，按现有规格列表的内部 SKU ID 升序稳定排序，ID 不输出。不能先取一页或固定数量后再过滤。

成功返回 `{ ok: true, productExternalId, items, page, pageSize: 5, total, hasNext }`。条目只含 `color`、`size`、`unitPrice`、`currency`、`inStock`：

- 单价为合法非负十进制字符串，币种固定 CNY，不由模型换算或改写。
- 有货状态复用实物库存扣除有效预占的现有规则，只返回布尔值。
- 不返回精确库存、预占量、内部 SKU ID、图片、成本或其他管理字段。
- 不合并颜色、尺码相同的不同 SKU，不推断所有同组合价格相同。
- `total` 是完整匹配集合数量；`hasNext` 按实际剩余结果计算。第 10 页后仍有数据时，说明聊天查询达到上限，提示进入原购买界面查看，不继续调用第 11 页。

商品不存在或停用返回固定 `not_found`；有效商品没有匹配规格返回成功空列表；匹配条目 `inStock: false` 才表示该条规格当前无货。依赖失败或安全投影失败返回固定 `unavailable`，不能伪装成无货。最终购买仍重新校验价格、规格和库存。

## 本人偏好明细查询

### 输入与只读范围

严格对象只接受可选 `category` 和可选 `page`。类别沿用 `size`、`shoe_size`、`fit`、`style`、`color`、`occasion`、`budget`、`avoidance`、`purchase_preference`，分页规则与 SKU 工具相同。

仅在用户明确问“我保存了哪些偏好”“我保存的鞋码是多少”等意图下调用。普通推荐继续使用已有相关性注入；不能为了完善推荐自行读取完整清单。

只读取本人 `active` 且未逻辑删除的记录。主偏好优先，其次更新时间倒序，最后用内部 ID 保证同时间排序稳定；内部 ID 不返回。类别过滤在计数、排序和分页前生效，不按相关性删减结果。

成功返回 `{ ok: true, items, page, pageSize: 5, total, hasNext }`。条目只含 `category`、`valueType`、`value`、`isPrimary`、`updatedAt`。值必须重新通过对应类别和既有敏感文本校验；类型与类别不符或不安全时，该次查询返回 `unavailable`，不能跳过损坏条目后仍宣称完整。不得返回用户 ID、偏好 ID、来源会话/消息、指纹、任务或 Markdown 文档。

空记录是成功空列表；失败不使用历史回复、相关性上下文或模型记忆补齐。多条记录按原值展示，不代替用户合并、纠错、删除或覆盖。

### 已确认：关闭偏好开关时的行为

已确认复用独立的 `user_preference_settings.enabled`。关闭时工具返回 `{ ok: false, code: "preferences_disabled" }`，不读取或返回偏好值；用户仍可在 `/account/memories` 手动查看、编辑和重新开启，关闭不删除数据。不得使用独立 Markdown 记忆开关代替。

设置记录缺失时按既有默认 `true` 解释，但查询不补建记录、不 flush，不恢复旧偏好任务。读取开关与偏好结果保持同次一致读取；之后关闭不能撤回已经进入聊天的结果或正文，新查询必须读取新状态。

该规则把“仅控制推荐注入”的旧偏好开关语义扩展到明确查询，已随本阶段设计获确认；不提供关闭注入但允许明细工具查询的例外。

## 追踪、历史与记忆

- 工具结果进入模型前完成字段白名单和安全校验；自由文本仅作数据，不作为指令。
- trace 仅保存工具名、合法类别、合法页码、颜色/尺码筛选是否存在、固定错误及结果计数。商品外部标识、颜色/尺码文本、偏好值和业务条目不原样记录，包括模型消息中嵌套或非法工具调用参数。
- SSE activity 沿用工具名、状态及空输入输出；原始工具 JSON 不进入公开历史或新展示元数据。隐藏调用和结果须成对处理；assistant 最终正文继续按原聊天规则保存。

**已确认沿用第一阶段的整轮来源隔离。** 本轮经校验调用任一新工具后，无论成功、空列表、开关关闭、商品不可用或依赖失败，该轮用户及助手消息均不作为自动 Markdown 记忆和摘要来源，也不登记记忆提取任务。既有混合批次、缓存重试及摘要来源检查须继续防止重新读入。

代价是同轮用户表达的其他长期背景也不自动提取；用户可手动维护，下一普通轮恢复。结构化偏好仍只由用户手动维护，不自动复制查询回显。此规则不重写旧消息或记忆，正文仍保存，不承诺从历史聊天中抹除已展示的偏好。

## 错误及兼容

非法工具参数不执行领域查询，使用既有工具失败通路，不回显原始值或异常。模型调用发生在聊天运行中，不能将工具校验错误描述为聊天 HTTP 必然返回 400。

原聊天 Body 的校验、JWT 401 和会话越权 404 保持不变。既有商品推荐、规格 HTTP 列表、购买弹框、地址选择、动态表单、订单及试穿工具保持原契约。两个新工具不注册卡片或商品搜索结果，不使查询变成购买授权。
