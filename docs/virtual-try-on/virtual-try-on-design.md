## 目标与边界

试穿模块为已登录用户提供“从服装商品卡选择颜色、上传本人照片、后台生成试穿结果、查看和管理历史”的完整业务闭环。

模块只接受现有商品目录中的服装商品事实，不接受任意服装图片，不负责商品搜索、尺码推荐、人体测量、订单或真实支付。首版不支持鞋类、多件搭配、结果分享、浏览器通知、邮件通知和运行中取消。

### 角色

| 角色             | 能力                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------- |
| 启用的普通用户   | 管理本人临时/已保存照片，创建和读取本人任务，读取/下载/删除本人结果，读取和标记本人站内提醒 |
| 管理员           | 沿用普通用户的本人能力，不获得跨用户试穿数据权限                                            |
| 未登录或禁用账号 | 不得访问试穿资源和图片对象                                                                  |
| 商品目录模块     | 提供商品类别、颜色、SKU 图片和主图事实；不创建试穿任务                                      |
| 图像供应商适配器 | 接收已审计的任务输入并返回生成结果或可分类错误；不直接暴露给 Controller                     |

## 核心流程

1. 商品卡只对 `tops`、`bottoms`、`dresses`、`outerwear` 展示试穿入口；`shoes` 不展示。
2. 前端请求当前商品的可试穿颜色投影。服务端重新校验商品仍启用，不能信任卡片旧数据。
3. 用户在首次生成前阅读第三方图像处理说明并同意指定版本的隐私协议。未同意不得创建任务。
4. 用户上传一张本人照片到试穿模块。照片只有在用户主动选择保存时才转为可复用照片，否则为任务临时资产。
5. 用户提交当前商品、颜色、照片资产和同意版本。服务端在事务中检查用户额度、活动任务、商品类别、颜色和图片回退规则，创建排队任务。
6. 后台任务读取商品图和照片，调用独立图像供应商适配器。临时错误最多自动重试一次；成功后保存结果，最终失败不扣每日次数。
7. 任务完成后生成本人可见的站内未读提醒。用户离开页面后，从“我的试穿”或站内提醒读取最新状态。
8. 成功结果永久保存，用户可查看、下载或删除。下载使用短期私有授权，不返回公开对象 URL。
9. 任务结束后删除未选择保存的输入照片；用户主动保存的照片独立于任务，可在照片管理中复用或删除。

## 商品与颜色选择

- 创建任务只接收 `productExternalId` 和 `color`，不接收 `skuId`、价格、尺码、商品图片 URL 或商品类别。
- 服务端读取当前启用商品，并拒绝 `shoes` 以及其他未知类别。
- 颜色必须匹配当前商品的有效 SKU 颜色，比较规则沿用商品目录的规范化约定。
- 选定颜色的 SKU 有可用图片时，使用该颜色的确定性图片投影；没有可用 SKU 图片时回退到商品主图。
- 图片选择必须由商品目录端口提供，不跨模块引用商品 Entity 或 Repository。
- 如果商品下架、类别变化、颜色失效或商品图片事实无法读取，任务不创建并返回可公开的业务错误。
- 多个尺码共享颜色时，试穿只使用颜色图片，不向用户暴露或推断尺码；生成结果必须展示“仅供视觉参考”的说明。

## 照片资产

照片分为两类：

| 类型        | 用途                         | 生命周期                               |
| ----------- | ---------------------------- | -------------------------------------- |
| `temporary` | 仅供一个试穿任务使用         | 任务成功或最终失败后删除对象并解除引用 |
| `saved`     | 用户主动选择的可复用本人照片 | 直到用户主动删除；不随单个任务删除     |

未选择保存且 30 分钟内未绑定试穿任务的临时上传自动过期并进入对象清理；任务中的临时照片不因该上传过期时间提前删除。

上传请求只允许 JPEG、PNG、WebP。服务端解码后限制单文件不超过 10 MiB、最长边不超过 4,096 像素，拒绝动画图片并清理 EXIF；不依赖客户端文件名或声明 MIME。不做单人识别硬校验，供应商无法处理时转为稳定失败原因。

系统不承诺自动识别姿势或保证单人照片一定可生成。供应商拒绝、输入无法处理和超时都映射为稳定的任务失败原因，不把供应商原始错误直接返回用户。

照片对象使用私有存储键，不在数据库中保存公开 URL。读取、下载和删除先验证用户归属，再由存储适配器生成短期授权或执行删除。对象删除失败时进入可重试清理状态，不向客户端泄露存储细节。

## 任务状态与次数

| 状态         | 语义                                   | 后续                       |
| ------------ | -------------------------------------- | -------------------------- |
| `queued`     | 已通过业务校验，等待后台处理           | 运行或最终失败             |
| `processing` | 正在准备图片或调用供应商               | 成功、临时重试或最终失败   |
| `succeeded`  | 结果对象已保存且可读取                 | 查看、下载、删除           |
| `failed`     | 已完成最多一次自动重试，未产生可用结果 | 查看失败原因、重新创建任务 |
| `deleted`    | 用户删除了结果或任务关联对象           | 不再出现在历史默认列表     |

- 每个用户最多一个 `queued` 或 `processing` 任务；并发创建必须在数据库唯一约束或等价事务边界内拒绝。
- 每个用户每天最多 5 次**成功生成**。失败、被拒绝、输入校验失败和重复读取不计次。
- 额度在成功结果提交同一事务中记账；并发竞争不能超过每日上限。每天按 `Asia/Shanghai` 自然日 00:00 重置。
- 供应商临时错误最多自动重试一次；第一次调用失败不计次，第二次仍失败转为 `failed`。
- 首版不支持取消；后台任务一旦创建，前端只能等待 `succeeded` 或 `failed`。
- 任务结果保存成功后才允许标记成功。结果对象和任务状态必须全成或全败，避免出现“成功但无图片”。

## 结果、提醒与删除

- 结果保存为私有对象，任务记录保存商品/颜色快照、供应商模型标识、生成时间、失败码和结果对象引用。
- 结果历史默认按创建时间倒序分页，只返回本人数据；`deleted` 默认不返回。
- `notificationReadAt = null` 表示任务完成提醒未读。读取详情或用户明确标记已读后更新该字段，不把轮询本身视为已读。
- 站内提醒只引用任务 ID、状态和商品名称，不复制照片或结果 URL；前端通过任务接口读取完整投影。
- 用户删除成功任务时，删除结果对象并将任务标记为 `deleted`；删除失败进入后台清理，不返回公开对象地址。
- 删除保存照片只删除该保存资产；历史任务中的商品和结果不因此删除。临时照片在任务结束时独立清理。
- 结果永久保存是业务默认，不代表第三方供应商无限期保留输入副本。当前渠道凭据仅用于开发环境合成/公开测试图；由于未取得人像留存、处理地区、禁止训练和删除 SLA 的书面保障，生产真实人像接入保持关闭。
- 结果和主动保存照片使用 Qiniu 私有对象存储的独立 `try-on/` 命名空间，不设置结果自动过期。下载使用 5 分钟短期授权；删除采用数据库墓碑及可重试物理删除，避免将清理失败伪装为已完成删除。

## 隐私、安全与可观测性

- 所有接口复用现有 JWT Guard 和当前用户上下文，不接受客户端 `userId`。
- 任务、照片、提醒和结果访问先校验归属；不存在与越权读取统一为 404，避免探测他人资源。
- 第三方同意版本、同意时间和必要的政策标识持久化；不把完整照片、Base64、供应商密钥或原始供应商错误写入普通日志、聊天消息或 LLM trace。
- 图像供应商使用服务端专用配置，API Key 只来自环境变量；不得复用前端或用户提交的渠道密钥。
- 供应商请求只传任务所需的照片和商品图片；默认不传用户昵称、邮箱、聊天正文或订单信息。
- 供应商数据留存、跨境处理、删除接口和训练用途在正式生产接入前必须完成供应商审查；未取得书面保障时停止真实人像接入。
- 结构化日志记录任务 ID、状态迁移、耗时、重试次数和安全错误码，不记录图片内容、签名 URL 或密钥。

## 模块边界与复用

- `virtual-try-on` 负责照片资产、任务状态、额度、提醒、结果生命周期和供应商编排。
- `product-catalog` 通过公开端口提供服装类别、颜色和图片投影；试穿模块不得读取其 Entity。
- `user-memory` 的 Qiniu 私有对象能力可作为存储实现参考，但试穿对象必须使用独立命名空间、独立归属校验和独立清理策略，不能共享记忆文档业务状态。
- `auth` 提供登录和当前用户；不新增试穿专用 Guard。
- 前端通过 `src/api/modules/try-on.ts` 和 `src/api/types/try-on.ts` 访问接口；聊天商品组件只发出公开的 `try-on` 事件，页面逻辑负责弹窗、上传和任务跳转。
- “我的试穿”使用独立页面目录，页面状态放在 `page.ts`，私有展示组件放在 `components/`；不把试穿任务塞入全局 Store。
- 站内提醒本期只服务试穿任务；若后续扩展为通用通知中心，应另立模块和契约。

## 已确认边界与持续风险

- 第三方供应商是否允许人像输入、是否留存输入/输出、删除 SLA、地区和训练用途：当前渠道公开资料不足，生产人像接入阻塞；开发环境仅使用合成/公开测试图。
- 默认模型使用 `gpt-image-2.6-flare`，供应商请求超时和图片编辑参数按技术文档实现；真实视觉质量和稳定 SLA 仍需后续验收。
- 上传采用 JPEG/PNG/WebP、10 MiB、最长边 4,096 像素、拒绝动画，并由服务端自动旋转和清理 EXIF 后转为 WebP。
- 额度按 `Asia/Shanghai` 自然日 00:00 重置。
- 结果与主动保存照片使用 Qiniu 私有 `try-on/` 命名空间；结果无自动过期，下载授权 5 分钟，删除通过墓碑及后台重试完成。对象加密和清理告警留到技术阶段确认。
- 站内提醒的产品入口固定为“我的试穿”页中的未读任务和完成提示，本期不增加全局导航未读角标。

## 验收清单

- [ ] 服装商品卡可启动试穿，鞋类和任意商品图不会进入任务。
- [ ] 颜色必须来自当前有效商品；缺少颜色图时稳定回退商品主图。
- [ ] 未登录、禁用账号、越权访问均被正确阻止。
- [ ] 首次同意、同意版本和未同意拒绝行为正确。
- [ ] 临时照片和已保存照片生命周期隔离，默认不保留输入照片。
- [ ] 单用户活动任务唯一、每日成功次数最多 5 次、失败不计次。
- [ ] 供应商临时错误只自动重试一次，结果对象与成功状态原子提交。
- [ ] 结果私有、可历史查看、可下载、可删除；删除不暴露公开对象 URL。
- [ ] 站内未读提醒只对本人可见，后台完成后离开页面仍能读取。
- [ ] 供应商密钥、Base64 和人像内容不会写入日志、聊天记录或模型 trace。
- [ ] 生产真实人像接入由供应商书面留存/地区/训练/删除保障解锁；开发渠道不接收真实人像。
- [ ] 商品、鉴权和现有订单流程保持兼容。
