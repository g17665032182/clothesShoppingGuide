# 商品目录 CRUD 契约

## 状态与上下文

- 状态：商品与 SKU 基础契约、“查看更多商品”及订单规格/库存协作增量均已确认。
- 资源：商品（Product）与商品 SKU（Product SKU）。
- 业务目的：提供真实、可校验的本地商品目录，支持服装导购查询和推荐。
- 所属模块：`apps/api/src/product-catalog/`。
- 数据库：复用项目当前 PostgreSQL 连接。
- 最后更新：2026-11-07。
- 设计：[服装导购体系设计文档](../product-guide/product-guide-design.md)。

## 范围与权限

- 首期只覆盖成人服装和鞋类。
- 已登录用户可以查询有效商品；用户隔离仍由现有 JWT Guard 和当前用户上下文负责。
- 商品数据只允许通过内部 CLI 写入；管理员只读查询的增量见本文末，不新增商品写 API。
- 游客不能调用商品查询工具或商品查询 API。
- 原商品目录阶段不提供下单、支付、收藏、比较或售后操作。订单阶段仅按下方已确认增量扩展规格查询和库存协作；订单业务由独立订单模块负责。

## 数据字段

### Product

| 字段                     | 约束与语义                                         |
| ------------------------ | -------------------------------------------------- |
| `id`                     | 服务端 UUID 主键，不可变                           |
| `externalId`             | 导入源稳定标识，必填，在目录内唯一                 |
| `name`                   | 必填，trim 后非空，最大 200 字符                   |
| `brand`                  | 可空，最大 100 字符                                |
| `category`               | `tops`、`bottoms`、`dresses`、`outerwear`、`shoes` |
| `description`            | 可空，最大 2,000 字符的纯文本，不解释为可信 HTML   |
| `styles`                 | 最多 10 个标签，每项最大 32 字符                   |
| `occasions`              | 最多 10 个标签，每项最大 32 字符                   |
| `fits`                   | 最多 10 个标签，每项最大 32 字符                   |
| `audience`               | 固定为 `adult`                                     |
| `productUrl`             | 可空，最大 2,048 字符的绝对 HTTP/HTTPS URL         |
| `isActive`               | 导入状态；仅有效商品参与推荐                       |
| `createdAt`, `updatedAt` | 服务端维护的 ISO 8601 时间                         |

### Product SKU

| 字段                     | 约束与语义                                                                |
| ------------------------ | ------------------------------------------------------------------------- |
| `id`                     | 服务端 UUID 主键，不可变                                                  |
| `productId`              | 必填，关联所属商品                                                        |
| `externalSkuId`          | 导入源稳定标识，在所属商品内唯一                                          |
| `color`                  | 必填，trim 后最大 32 字符；不要求规范词表                                 |
| `size`                   | 必填，trim 后最大 32 字符，如 `S`、`M`、`38`、`42`；不做跨品牌数值换算    |
| `price`                  | 非负人民币价格，PostgreSQL `numeric(12,2)`                                |
| `currency`               | 固定为 `CNY`                                                              |
| `stock`                  | 非负整数；现有实现仅供查询；订单增量拟明确为实物库存，预占/扣减规则见下文 |
| `imageUrl`               | 可空，最大 2,048 字符的绝对 HTTP/HTTPS URL                                |
| `isActive`               | SKU 可用状态                                                              |
| `createdAt`, `updatedAt` | 服务端维护的 ISO 8601 时间                                                |

Entity 不直接作为 API/工具响应。对外返回专用响应投影，不含内部数据库字段或导入诊断数据。

## 商品查询行为

### 查询输入

商品查询工具由 LLM 在服务端调用。输入只接受结构化过滤条件：

- `category`
- `size`
- `color`
- `style`
- `occasion`
- `fit`
- `budgetMin`、`budgetMax`
- `inStock`
- `limit`，默认最多 3
- `cursor`，用于同一查询的后续分页

过滤字段按单值处理，预算使用人民币。非人民币预算不得直接与商品价格比较；需要外币预算时应先向用户澄清或请求其提供人民币预算，不执行隐式汇率换算。不得允许客户端提供 SQL、排序表达式或内部字段。

### 查询结果

只返回有效商品及有效 SKU，并提供：

- 商品公开信息和规范化商品详情 URL。
- 当前匹配的 SKU 颜色、尺码、价格及库存可用性。
- 服务端生成的有限 `matchReasons` 标签。
- 不透明的下一页游标或 `null`。

商品卡片展示满足全部硬条件的匹配 SKU 中的最低价，统一为 CNY；没有匹配 SKU 或有效价格时不返回商品卡片。库存仅展示“有货/无货”，不对外展示精确库存数。不得把缺失库存解释成有货，不得将商品或 SKU 自由文本解释为已验证事实。

### 硬筛选和排序

- 用户本轮明确提出的预算、尺码和有货要求是硬条件。
- 颜色、风格、场合、版型和已保存偏好默认参与排序；用户明确要求必须匹配时才作为硬条件。
- 每个命中的软匹配信号加 1 分；按总分降序排序。
- 分数相同按 `product.externalId`、`sku.externalSkuId` 升序，保证顺序稳定。
- 每轮聊天只执行一次首轮商品查询且固定返回 3 件，模型不能通过提高页大小或重复调用扩充结果；“查看更多”表示同一查询下继续下一页，不重复此前页结果。
- 无结果时返回空集合及有限的机器可读原因，不自动放宽条件。

软匹配理由固定为 `category_match`、`size_match`、`budget_match`、`stock_available`、`color_match`、`style_match`、`occasion_match`、`fit_match`、`preference_match`。无结果原因只依据硬条件报告 `NO_MATCHING_SIZE`、`OVER_BUDGET`、`OUT_OF_STOCK`；无法归因时使用 `NO_MATCHING_PRODUCT`。

## 导入契约

- 文件顶层为 `{ "version": 1, "products": [...] }`。
- 输入包含商品及其 SKU，使用 `externalId` / `externalSkuId` 做稳定幂等键。
- 商品与 SKU 使用严格 schema；未知字段、重复 `externalId`、重复 `externalSkuId` 和空 SKU 列表均拒绝。
- 导入先解析并校验整个文件，再在单个数据库事务内写入；任何解析、校验或数据库错误都回滚整批。
- 相同标识再次导入更新记录，不存在时新增；不物理删除记录。
- `isActive` 缺省为 `true`，显式 `false` 表示停用。
- 文件未包含的已有商品保持原状态，不自动下架。
- 文件最大 10 MiB，最多 5,000 个商品，每个商品最多 100 个 SKU；超限整批拒绝。
- 导入报告包含新增、更新、下架/状态变化计数和按行/路径定位的安全错误，不输出凭据或整份敏感载荷。
- fixture 放在开发/测试目录；生产流程不得自动加载。

## API、工具与错误

原首期查询只通过聊天中的服务端商品查询工具访问。工具由商品模块公开的应用入口提供给 LLM Tool Registry；聊天消息通过既有 `publicDisplay` 投影展示商品卡片。直接 HTTP 访问仅限已确认分页接口和订单规格查询增量。

### 已确认增量：查看更多商品直接分页

- 新增 `POST /api/product-catalog/next-page`，仅已登录用户可调用；复用现有 JWT Guard，不新增角色或用户 ID 参数。
- Body 使用严格 Zod schema，包含 `query`（现有商品查询筛选字段及固定 `limit: 3`，不含 `cursor`）和 `cursor`。首轮和后续分页均固定每页 3 件；游标签名校验会拒绝被改动的筛选条件或页大小。
- 服务端将 `query` 与 `cursor` 组合后调用现有商品目录查询能力；现有签名校验必须确认游标仍绑定同一组筛选条件，非法、篡改、过期或条件不一致均返回 400。
- 响应复用商品查询投影：`items`、`nextCursor`、`noResultReason`。不返回 Entity、Repository 数据或内部标识。
- 新的聊天展示快照需保留由服务端从商品工具调用参数中白名单解析出的 `query`，以支持刷新或切换会话后的分页；模型输出和未知字段不得成为分页参数来源。
- 前端在被点击的商品结果组内追加响应商品并更新 `nextCursor`；请求期间仅禁用该组按钮，失败时保留已有商品和游标并显示可重试状态。不得发送聊天消息或调用 LLM。流式生成期间暂存商品卡片事件，收到 `done` 后再显示卡片。
- 旧展示快照没有 `query` 时隐藏“查看更多”按钮。下一页追加仅存在于当前前端展示状态，不回写已保存的聊天快照。
- 不新增 Entity、数据库字段、索引或 Migration；不提供新的商品写入能力。

任何未来新增 HTTP 查询必须另行确认，并使用模块内 Zod schema 和 Nest `StandardSchemaValidationPipe`，对象默认 `z.strictObject`，用户不得指定内部归属或写入字段。

错误边界：

- 未认证：`401`。
- 非法过滤输入、非法游标：`400`。
- 不存在或不可用商品：查询中不返回该商品，不向用户区分内部标识。
- 导入文件无效：CLI 以非零退出码结束，报告安全、可定位的校验错误且不写入。
- 数据库异常不得泄露 SQL、连接信息或 Entity 内容。
- 下一页接口复用以上认证、输入校验和游标错误边界；下一页没有匹配数据时返回空 `items` 和空 `nextCursor`。

## 迁移与删除

- 新增独立商品和 SKU 表、外键、唯一约束和查询索引。
- Migration 必须保留数据安全，不得修改既有用户/聊天/偏好数据。
- 商品及 SKU 下架为逻辑停用；首期无删除 API/CLI。
- 父商品停用后其 SKU 不得参与查询，即使 SKU 自身仍启用。
- 物理删除不在首期提供。
- 聊天消息保存生成时的商品名称、价格、图片和匹配理由快照；历史视图不得暗示价格和库存仍为当前值。详情链接仍使用导入 URL，不实时刷新。

- [ ] 排序确定，匹配理由由可验证的服务端标签构成。
- [ ] 游标维持原查询条件且跨页不重复。

- [ ] Migration SQL、测试、类型检查和构建均通过。

## 后续技术细节

以下不改变已确认的业务契约，由技术文档确定具体实现机制：

1. 游标签名密钥配置来源、载荷编码和过期后的工具错误表达；载荷包含查询指纹、版本及最后排序键，有效期 15 分钟。
2. 商品工具通过聊天模块在认证上下文内调用商品公开应用端口，不将用户 ID 暴露给模型参数。
3. 匹配标签和无结果原因已由本契约固定，技术实现不得增加模型推断标签。

## 已确认增量：订单规格与库存协作

业务范围与契约细化于 2026-11-07 获用户确认，首版规格查询和库存协作已实现。关联：[订单设计](../orders/order-module-design.md)、[订单 CRUD 契约](./order-crud-contract.md)。

- 新增 `GET /api/product-catalog/skus`，仅启用的已登录账号可按 `productExternalId` 分页查询有效商品的有效规格。返回稳定 `skuId`、颜色、尺码、SKU 当前单价、币种、图片和 `inStock`，不返回精确库存、预占量或 Entity。具体字段、分页和错误以订单契约为准。
- 旧商品搜索、下一页响应和聊天卡片投影不增加 SKU 标识；新规格接口是独立下单前查询，不新增聊天下单工具。
- 实物库存继续使用导入的 `stock`；预占量由订单协作维护。可售数量为实物库存减预占数量，始终非负。预占的具体存储方式留待技术设计。
- 商品搜索、下一页查询、推荐中的有货标签、规格查询和下单统一使用可售数量判断有货；不修改已保存历史聊天快照。
- 下单整单预占，模拟支付保持预占；取消、超时或未支付下架关闭释放整单预占；发货同时扣减实物并解除预占，收货不再扣库存。
- 重复导入 `stock` 是用文件中的当前实物库存覆盖，不是增量补货，不允许设置或清零预占量。不得导入低于有效预占量的库存，冲突整批拒绝并定位商品/SKU。
- 商品或 SKU 停用时，经订单模块公开协作入口关闭所有涉及的未支付订单，释放这些订单全部明细预占；已支付订单保留并可继续履约。
- 同批导入先计算下架关闭后的预占量，再校验实物库存下限；任一步失败时，整批商品更新、关联订单关闭和预占释放一并回滚。
- CLI 与测试 Seeder 必须使用相同的一致性规则，不得直接覆盖预占状态；导入者须提供当时实际库存，历史文件重放不等于库存增量。
- 商品模块对订单公开规格及库存协作能力，订单不导入商品私有 Entity/Repository；导入不直接写订单 Entity。具体原子事务与模块接线由技术文档决定。
- 增量迁移应保留既有商品/SKU 标识、价格和库存；没有历史订单时初始预占为零。本阶段不生成或执行 Migration。

增量验收包括规格权限与输入校验、无精确库存泄漏、可售状态一致性、并发预占/释放/扣减、导入下限保护、下架整单释放和整批失败回滚，详见订单契约。

## 已确认增量：管理员商品查看

管理员运营页面新增 `GET /api/admin/product-catalog/products` 和
`GET /api/admin/product-catalog/products/:id`，仅启用管理员可访问；普通用户 403，
未登录或禁用账号 401。返回列表、详情及精确实物/预占/可售库存，不返回 Entity。
普通商品查询、聊天和下单前规格响应不新增精确库存。

此增量只读，不支持商品编辑、上下架或库存修改；详见
[管理员运营 CRUD 契约](./admin-management-crud-contract.md)。
