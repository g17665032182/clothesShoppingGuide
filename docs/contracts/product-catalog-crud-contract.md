# 商品目录 CRUD 契约

## 状态与上下文

- 状态：待用户确认。
- 资源：商品（Product）与商品 SKU（Product SKU）。
- 业务目的：提供真实、可校验的本地商品目录，支持服装导购查询和推荐。
- 所属模块：`apps/api/src/product-catalog/`。
- 数据库：复用项目当前 PostgreSQL 连接。
- 最后更新：2026-11-05。
- 设计：[服装导购体系设计文档](../product-guide/product-guide-design.md)。

## 范围与权限

- 首期只覆盖成人服装和鞋类。
- 已登录用户可以查询有效商品；用户隔离仍由现有 JWT Guard 和当前用户上下文负责。
- 商品数据只允许通过内部 CLI 写入；不新增公开写 API、管理 API 或运营后台。
- 游客不能调用商品查询工具或商品查询 API。
- 不提供下单、支付、库存预占/扣减、收藏、比较或售后操作。

## 数据字段

### Product

| 字段                     | 约束与语义                              |
| ------------------------ | --------------------------------------- |
| `id`                     | 服务端 UUID 主键，不可变                |
| `externalId`             | 导入源稳定标识，必填，在目录内唯一      |
| `name`                   | 必填，trim 后非空，长度上限待确认       |
| `brand`                  | 可空                                    |
| `category`               | 成人服装/鞋类分类；具体允许值待确认     |
| `description`            | 可空的纯文本说明，不解释为可信 HTML     |
| `styles`                 | 风格标签集合；数量、长度与词表待确认    |
| `occasions`              | 场合标签集合；数量、长度与词表待确认    |
| `fits`                   | 版型标签集合；数量、长度与词表待确认    |
| `audience`               | 成人适用人群枚举；具体允许值待确认      |
| `productUrl`             | 可空的绝对 HTTP/HTTPS URL；禁止凭空生成 |
| `isActive`               | 导入状态；仅有效商品参与推荐            |
| `createdAt`, `updatedAt` | 服务端维护的 ISO 8601 时间              |

### Product SKU

| 字段                     | 约束与语义                           |
| ------------------------ | ------------------------------------ |
| `id`                     | 服务端 UUID 主键，不可变             |
| `productId`              | 必填，关联所属商品                   |
| `externalSkuId`          | 导入源稳定标识，在所属商品内唯一     |
| `color`                  | SKU 颜色；必填规则与规范词表待确认   |
| `size`                   | SKU 尺码；服装和鞋类的结构待确认     |
| `price`                  | 非负价格，精度和货币规则待确认       |
| `stock`                  | 非负整数；不得据此执行库存预占或扣减 |
| `imageUrl`               | 可空的绝对 HTTP/HTTPS URL            |
| `isActive`               | SKU 可用状态                         |
| `createdAt`, `updatedAt` | 服务端维护的 ISO 8601 时间           |

Entity 不直接作为 API/工具响应。对外返回专用响应投影，不含内部数据库字段或导入诊断数据。

## 商品查询行为

### 查询输入

商品查询工具由 LLM 在服务端调用。输入只接受结构化过滤条件：

- `category`
- `size`
- `color`
- `style`
- `occasion`
- `fit`
- `budgetMin`、`budgetMax`
- `inStock`
- `limit`，默认最多 3
- `cursor`，用于同一查询的后续分页

精确 schema、预算货币、过滤字段是否支持多值、游标签名/过期策略以及 HTTP API 是否公开，均待技术文档确认；不得允许客户端提供 SQL、排序表达式或内部字段。

### 查询结果

只返回有效商品及有效 SKU，并提供：

- 商品公开信息和规范化商品详情 URL。
- 当前匹配的 SKU 颜色、尺码、价格及库存可用性。
- 服务端生成的有限 `matchReasons` 标签。
- 不透明的下一页游标或 `null`。

价格是否按商品最低匹配 SKU、区间或选中 SKU 表达，待确认。不得把缺失库存解释成有货，不得将商品或 SKU 自由文本解释为已验证事实。

### 硬筛选和排序

- 用户本轮明确提出的预算、尺码和有货要求是硬条件。
- 颜色、风格、场合、版型和已保存偏好默认参与排序；用户明确要求必须匹配时才作为硬条件。
- 筛选后排序必须确定性；并列时使用稳定商品/SKU 标识作为最终顺序。
- 默认每页最多 3 件；“更多/换一批”使用相同过滤条件续取，不重复此前页结果。
- 无结果时返回空集合及有限的机器可读原因，不自动放宽条件。

排序分值、条件权重、匹配标签全集和无结果原因枚举待设计确认。

## 导入契约

- 文件为带版本字段的 JSON；首版格式标识及完整 schema 待确认。
- 输入包含商品及其 SKU，使用 `externalId` / `externalSkuId` 做稳定幂等键。
- 导入先解析并校验整个文件，再在单个数据库事务内写入；任何解析、校验或数据库错误都回滚整批。
- 相同外部标识重复出现、未知字段、重复 SKU 和空 SKU 列表均需拒绝，除非最终格式明确允许。
- 相同标识再次导入更新记录，不存在时新增；不物理删除记录。
- 文件中显式 `isActive: false` 表示下架；字段省略如何处理、文件未包含的历史商品是否保持原状态均待确认。
- 导入报告包含新增、更新、下架/状态变化计数和按行/路径定位的安全错误，不输出凭据或整份敏感载荷。
- fixture 放在开发/测试目录；生产流程不得自动加载。

## API、工具与错误

首期交互入口为聊天。服务端内部查询工具由商品模块公开的应用入口提供给 LLM Tool Registry；聊天消息通过既有 `publicDisplay` 投影展示商品卡片。

普通 HTTP 商品查询路由是否同时提供给已登录客户端尚待确认。任何后续 HTTP 查询必须使用模块内 Zod schema 和 Nest `StandardSchemaValidationPipe`，对象默认 `z.strictObject`，用户不得指定内部归属或写入字段。

错误边界：

- 未认证：`401`。
- 非法过滤输入、非法游标：`400`。
- 不存在或不可用商品：查询中不返回该商品，不向用户区分内部标识。
- 导入文件无效：CLI 以非零退出码结束，报告安全、可定位的校验错误且不写入。
- 数据库异常不得泄露 SQL、连接信息或 Entity 内容。

## 迁移与删除

- 新增独立商品和 SKU 表、外键、唯一约束和查询索引。
- Migration 必须保留数据安全，不得修改既有用户/聊天/偏好数据。
- 商品及 SKU 下架为逻辑停用；首期无删除 API/CLI。
- 父商品停用后其 SKU 不得参与查询，即使 SKU 自身仍启用。
- 物理删除、历史推荐快照及数据保留周期待确认，不在首期提供删除行为。

## 验收

- [ ] Product/SKU 字段、唯一约束、关联和索引已由用户确认。
- [ ] JSON 文件版本、字段 schema、未知字段和增量下架语义已确认。
- [ ] CLI 的全量预校验、事务回滚和重复导入行为有测试。
- [ ] 查询只返回有效商品及满足硬条件的有效 SKU。
- [ ] 排序确定，匹配理由由可验证的服务端标签构成。
- [ ] 游标维持原查询条件且跨页不重复。
- [ ] 无结果不会自动放宽筛选。
- [ ] 未认证访问、非法输入、未知字段和非法游标均得到约定错误。
- [ ] 商品实体不经由 Controller、LLM 工具或聊天消息直接泄漏。
- [ ] Migration SQL、测试、类型检查和构建均通过。

## 待确认项

1. 商品类别和 `audience` 的精确枚举。
2. 名称、描述及标签的长度/数量上限和规范词表策略。
3. 服装尺码与鞋码的导入结构，以及 SKU 颜色/尺码是否允许自定义字符串。
4. 价格的币种、精度及卡片展示语义（匹配 SKU 价格、最低价或价格区间）。
5. JSON 首版字段 schema、重复记录策略、缺省字段语义；未出现在下一文件中的商品默认保持现状还是下架。
6. 是否提供面向客户端的只读 HTTP 查询 API，还是只通过聊天工具公开。
7. 查询游标的过期/签名和服务端状态保存方式。
8. 筛选排序权重、匹配标签全集及无结果原因枚举。
9. `more` 与 `换一批` 是否同为纯分页操作，还是“换一批”需要排除当前展示集并从头取下一组。
10. 商品/推荐历史的保留期限和未来物理删除策略。
