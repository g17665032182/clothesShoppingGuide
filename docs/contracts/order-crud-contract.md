## 范围与权限

覆盖创建、本人/管理列表和详情、模拟支付、本人取消、管理员整单发货、本人确认收货、系统超时及未支付下架关闭。

不提供订单内容 PATCH、任意改价/修改状态、订单删除、代买家支付/收货、真实支付、退款退换货、前端页面或聊天下单。

除内部后台处理外，全部 API 要求启用账号的 Bearer JWT。当前用户由认证上下文取得，不接受客户端指定订单买家。所有启用账号包括管理员都可购买；管理员角色仅在 `/api/admin/orders` 下增加管理查询和发货权限。

## 逻辑数据字段

以下是 API 和持久化语义提案，不是已创建的数据库结构。具体数据库列类型、索引名称和迁移 SQL 在技术阶段确定。

### 订单

| 字段                                             | 类型与可空性                           | 写入、默认和返回约定                         |
| ------------------------------------------------ | -------------------------------------- | -------------------------------------------- |
| `id`                                             | UUID，非空                             | 服务端生成、不可变；列表和详情可返回         |
| `orderNo`                                        | 唯一订单号字符串，非空                 | 服务端生成，不允许客户端写入；列表和详情返回 |
| `userId`                                         | 用户 UUID，非空                        | 当前账号确定；仅管理响应返回买家标识         |
| `status`                                         | 状态枚举，非空                         | 初始 `pending_payment`，只通过指定动作流转   |
| `closeReason`                                    | 关闭原因或 `null`                      | 仅 `closed` 非空；由关闭原因决定             |
| `currency`                                       | 固定 `CNY`                             | 服务端写入并返回                             |
| `itemsAmount`                                    | 两位小数非负金额字符串                 | 服务端按快照计算，不接受客户端金额           |
| `shippingAmount`                                 | 固定 `"0.00"`                          | 服务端写入并返回                             |
| `discountAmount`                                 | 固定 `"0.00"`                          | 服务端写入并返回                             |
| `payableAmount`                                  | 两位小数金额字符串                     | 等于 `itemsAmount`；模拟支付金额             |
| `paymentMode`                                    | 固定 `simulated`                       | 所有订单响应保留该标识；不伪造真实支付流水   |
| `recipient`                                      | 收件人快照，非空                       | 创建时写入，详情可返回，不可修改             |
| `shipment`                                       | 物流快照或 `null`                      | 发货时写入，发货前为空，之后不可覆盖         |
| `expiresAt`                                      | ISO 8601 时间，非空                    | 创建时间加 30 分钟，由服务端确定             |
| `paidAt`、`shippedAt`、`completedAt`、`closedAt` | ISO 8601 时间或 `null`                 | 对应动作首次成功时写入，重试不改写           |
| `createdAt`、`updatedAt`                         | ISO 8601 时间，非空                    | 服务端维护                                   |
| 下单幂等记录                                     | 当前用户、幂等键、规范化请求及关联订单 | 用户与键组合唯一；不在响应中暴露内部请求指纹 |

状态枚举：`pending_payment`、`pending_shipment`、`pending_receipt`、`completed`、`closed`。

关闭原因：`user_cancelled`、`payment_expired`、`product_unavailable`。非关闭订单的 `closeReason`、`closedAt` 必须为空。

### 明细与快照

| 字段                | 语义                                                         |
| ------------------- | ------------------------------------------------------------ |
| `skuId`             | 稳定 SKU UUID，下单时校验并关联，商品导入不改变既有 SKU ID   |
| `productExternalId` | 商品外部标识快照                                             |
| `productName`       | 商品名称快照                                                 |
| `color`、`size`     | 所选 SKU 规格快照                                            |
| `imageUrl`          | 下单时允许公开的图片 URL 快照，可空                          |
| `unitPrice`         | 下单时 SKU 价格，两位小数金额字符串                          |
| `quantity`          | 正整数，本次提案每项 1–99                                    |
| `lineAmount`        | 精确单价乘数量，由服务端计算                                 |
| 明细归属            | 必须且只属于一张订单；订单无删除入口，不进行级联删除历史快照 |

收件人快照为 `recipient: { name, phone, address }`；物流快照为 `shipment: { carrier, trackingNo }`。

订单列表返回摘要，不含完整收货信息；详情返回明细、收件人和物流快照。商品或用户状态变化不覆盖快照，禁用用户不删除关联订单。

### 输入边界提案

| 输入                                      | 规则                                                                           |
| ----------------------------------------- | ------------------------------------------------------------------------------ |
| `id`、`skuId`、`userId`                   | UUID；订单 `id` 为路由参数，列表 `userId` 仅管理员可用                         |
| `idempotencyKey`                          | 创建必填 UUID；同一用户范围唯一，终止后也不能复用                              |
| `items`                                   | 必填数组，1–50 个不同 SKU；每项严格为 `{ skuId, quantity }`；重复 SKU 返回 400 |
| `quantity`                                | JSON 整数 1–99，不接收数字字符串或小数                                         |
| `recipient.name`                          | trim 后 1–100 字符，不允许控制字符                                             |
| `recipient.phone`                         | trim 后匹配可选前导 `+` 及 6–20 位数字，不接受空格或连字符                     |
| `recipient.address`                       | trim 后 1–500 字符，不允许控制字符；一段完整地址，不新增地区/地址簿模型        |
| `shipment.carrier`、`shipment.trackingNo` | trim 后各 1–100 字符，不允许控制字符                                           |
| `productExternalId`                       | trim 后 1–160 字符，不允许控制字符；用于规格 Query                             |
| `orderNo`                                 | trim 后 1–100 字符；订单列表精确匹配筛选                                       |
| `page`、`pageSize`                        | Query 转换为正整数，默认 1、20；`pageSize` 最大 100                            |
| `status`                                  | 仅允许上述状态枚举，省略表示不筛选                                             |

所有对象输入及嵌套对象默认严格拒绝未知字段。不允许客户端提供金额、订单归属、状态、支付时间、库存或服务端快照字段；必填字段不能传 `null`，可选筛选省略表示不筛选，显式 `null` 拒绝。

Body、Query、Param 的校验规则分别定义在所属模块的 Zod schema，并绑定现有 Nest `StandardSchemaValidationPipe`；类型从 schema 派生。Swagger DTO 只承担文档元数据，不重复实现运行时校验。

## API 契约提案

全局前缀为 `/api`。成功响应为安全投影，不直接返回 Entity。

| 操作     | 方法与路由                              | 请求                                                     | 成功响应                           | 权限           |
| -------- | --------------------------------------- | -------------------------------------------------------- | ---------------------------------- | -------------- |
| 规格查询 | `GET /api/product-catalog/skus`         | Query：必填 `productExternalId`，可选 `page`、`pageSize` | 200，规格分页                      | 启用账号       |
| 创建订单 | `POST /api/orders`                      | Body：`idempotencyKey`、`items`、`recipient`             | 首次 201；同请求重试 200；订单详情 | 启用账号，本人 |
| 本人列表 | `GET /api/orders`                       | Query：可选 `page`、`pageSize`、`status`、`orderNo`      | 200，订单摘要分页                  | 启用账号，本人 |
| 本人详情 | `GET /api/orders/:id`                   | Param：`id`                                              | 200，订单详情                      | 启用账号，本人 |
| 模拟支付 | `POST /api/orders/:id/simulate-payment` | Param：`id`；Body：`{}`                                  | 200，当前订单详情                  | 启用账号，本人 |
| 取消     | `POST /api/orders/:id/cancel`           | Param：`id`；Body：`{}`                                  | 200，当前订单详情                  | 启用账号，本人 |
| 确认收货 | `POST /api/orders/:id/confirm-receipt`  | Param：`id`；Body：`{}`                                  | 200，当前订单详情                  | 启用账号，本人 |
| 管理列表 | `GET /api/admin/orders`                 | 本人列表 Query 加可选 `userId`                           | 200，含买家标识的摘要分页          | 启用管理员     |
| 管理详情 | `GET /api/admin/orders/:id`             | Param：`id`                                              | 200，含买家标识的订单详情          | 启用管理员     |
| 整单发货 | `POST /api/admin/orders/:id/ship`       | Param：`id`；Body：`carrier`、`trackingNo`               | 200，管理订单详情                  | 启用管理员     |

规格项投影为 `skuId`、`productExternalId`、`productName`、`color`、`size`、`unitPrice`、`currency`、`inStock`、`imageUrl`；只返回有效父商品的有效 SKU，不公开实物或预占数量。`unitPrice` 为该 SKU 单价，不是商品卡片最低价。有效商品无有效 SKU 时返回空页；父商品不存在或停用返回 404。

分页统一形状为 `{ items, total, page, pageSize }`。本人查询不接受 `userId`，即便该字段等于本人也返回 400。管理查询支持任一合法用户 UUID，不要求买家仍启用。订单默认 `createdAt DESC, id DESC`；规格按稳定 `skuId ASC` 排序。列表为空返回 200 和空数组。

摘要包含 `id`、`orderNo`、`status`、`closeReason`、金额、币种、`paymentMode`、商品总数量、创建与各阶段时间；详情增加 `items`、`recipient`、`shipment`。管理投影额外返回 `userId`。响应不含密码、Token、内部锁/任务状态、幂等请求指纹、商品导入诊断或其他用户资料。

## 状态转换与重试

| 动作     | 首次允许状态             | 结果与库存                                 | 同动作成功重试                       |
| -------- | ------------------------ | ------------------------------------------ | ------------------------------------ |
| 创建     | 无订单                   | `pending_payment`；整单预占                | 相同键及规范化输入返回原订单当前状态 |
| 模拟支付 | 未过期 `pending_payment` | `pending_shipment`；保持预占               | 已支付、待收货或已完成返回当前状态   |
| 本人取消 | 未过期 `pending_payment` | `closed/user_cancelled`；释放整单预占      | 已本人取消返回当前状态               |
| 系统超时 | 到期 `pending_payment`   | `closed/payment_expired`；释放整单预占     | 不再释放                             |
| 商品下架 | `pending_payment`        | `closed/product_unavailable`；释放整单预占 | 不再释放；不覆盖其他关闭原因         |
| 整单发货 | `pending_shipment`       | `pending_receipt`；扣减实物、解除预占      | 已发货/完成且物流相同则返回当前状态  |
| 确认收货 | `pending_receipt`        | `completed`；库存不变                      | 已完成返回当前状态                   |

首次成功动作的时间与快照不因重试改变。物流不同的重复发货、已支付后取消、已关闭后支付、未发货确认收货等不满足条件的操作返回 409。

处理未支付订单动作时如已到截止时间，应关闭并释放预占后返回 409；不能因异常处理回滚掉应完成的关闭，也不能收取模拟款项。如何安全完成这些事务结果，在技术文档中明确。

创建幂等比较使用规范化输入：收货字段 trim、SKU 按稳定标识排序后比较，明细重复在校验阶段拒绝。同一用户相同键但输入不同返回 409；不同用户相同键互不影响。幂等命中先返回原订单，不因商品后来改价、下架、库存变化而再次创建或重算。原订单已到期时返回处理到期后的当前状态，不重新计时。

## 库存与导入约束

- 实物库存不小于预占数量，预占非负，可售数量为两者之差。
- 待支付、待发货占用库存；发货后同时减少实物与预占；收货不再扣库存。
- 多 SKU 创建、发货和关闭均须全成或全败，不能部分预占、发货或释放。
- 支付、取消、到期、下架竞争同一订单时，必须依据同一份有效状态完成唯一转换。
- 商品改价不影响锁价期内订单；商品/SKU 下架关闭整张未支付订单，已支付订单继续按快照发货。
- 同批下架与库存覆盖，以整单关闭释放后的预占量校验；低于剩余预占则整批导入失败，商品更新、订单关闭和释放全部回滚。
- 导入只能指定当前实物库存，不能提供预占量。错误定位商品/SKU，CLI 非零退出，不泄露订单收货信息。
- 测试 Seeder 必须遵守同样库存保护；禁止直接覆盖正在预占的状态或重置预占量。
- 搜索、更多分页、规格及下单均使用可售库存语义，不更改已有推荐结果和历史聊天快照的结构。

## 错误行为提案

| 状态码 | 场景                                                                                 |
| ------ | ------------------------------------------------------------------------------------ |
| 400    | Body/Query/Param 非法、未知字段、重复 SKU、数量越界、显式非法 `null`                 |
| 401    | 未登录、Token 无效、账号禁用                                                         |
| 403    | 已登录非管理员调用管理接口                                                           |
| 404    | 订单不存在；本人接口访问他人订单；创建时指定不存在/不可用 SKU；规格父商品不存在/停用 |
| 409    | 库存不足、幂等键与输入冲突、订单过期、非法状态转换、试图覆盖物流信息                 |
| 503    | 按现有异常映射判定的数据库暂时不可用                                                 |
| 500    | 未预期的内部错误；不得暴露 SQL、连接或内部对象                                       |

创建时任一 SKU 不存在或不可用则整单 404，任一可售数量不足则整单 409。响应可说明请求中的对应 SKU 不可下单，但不返回实际库存或其他用户订单信息。

采用现有 Nest 异常和数据库错误映射，不新建一套响应封装或让业务状态错误伪装成输入 schema 错误。成功及失败均不得输出密码、Token、连接信息或收货信息日志。

## 持久化与兼容性约束

| 约束     | 本轮设计要求                                                                             |
| -------- | ---------------------------------------------------------------------------------------- |
| 唯一性   | `orderNo` 全局唯一；下单键在当前用户范围唯一；每张订单同一 SKU 最多一条明细              |
| 关联     | 订单归属用户，明细归属订单并关联 SKU；禁用用户、下架商品不删除订单                       |
| 不变量   | 金额非负且与明细一致；状态、关闭原因、动作时间一致；预占与实物库存不为负                 |
| 索引需求 | 本人/管理分页、订单号查询、用户与状态筛选、到期扫描及 SKU 预占汇总                       |
| 初始兼容 | 没有历史订单，既有 SKU 初始预占为零；保留既有库存、稳定标识、聊天/偏好数据               |
| 迁移     | 创建并审查增量 Migration，检查历史数据、约束、索引及回滚影响；禁止用清库验证代替迁移验证 |
| 删除     | 本轮不提供订单、明细或快照删除；不引入商品/用户删除级联清空订单                          |

具体存储模型、事务接线、锁顺序、金额类型精度和后台到期处理机制只在技术文档阶段确定。
