# 聊天偏好编辑界面请求契约

## 状态与依据

- 状态：已确认；已实施。
- 最后更新：2026-11-16。
- 资源：当前聊天运行中的偏好管理页面导航请求；不创建持久化资源。
- 所属模块：`chat-records` 聊天工具编排；偏好 CRUD 仍归 `user-preferences` 模块。
- 设计：[对话偏好编辑界面请求设计](../modules/llm/chat-tool-preference-form-design.md)。
- 领域依据：[用户偏好 CRUD 契约](./user-preferences-crud-contract.md)。

## 权限与操作范围

`request_preference_form` 仅允许请求当前用户打开本人现有偏好管理页。工具不拥有读取偏好明细、写入偏好或更改设置的权限。所有新增、修改、删除和开关操作继续由用户在偏好页发起，并经过既有认证 API。

服务端从认证上下文取得用户和会话，不接受模型提供 `userId`、`conversationId`、`preferenceId`、目标 URL 或 API 路径。

## 工具输入

输入对象严格拒绝未知字段：

| 字段       | 类型     | 规则                                                                                                          |
| ---------- | -------- | ------------------------------------------------------------------------------------------------------------- |
| `category` | 可选枚举 | 仅允许 `size`、`shoe_size`、`fit`、`style`、`color`、`occasion`、`budget`、`avoidance`、`purchase_preference` |

空对象合法并打开默认偏好管理视图。类别只用于界面预选；不代表授权、不触发偏好查询，也不指定或编辑某条已有记录。

## 运行时导航与结果

- 目标页面固定为当前应用已有 `/account/memories?view=preferences`，目标不得由模型控制。
- 首版服务端仅通过 SSE 流发送一次性、受限导航意图，可携带可选类别枚举；JSON 聊天不注册此 UI 请求工具。
- 前端只允许将该意图映射到上述固定页面和已知类别；不得执行任意 URL、脚本、组件或 API。
- 客户端完成或未能完成导航后，以固定 Toast 反馈实际路由结果，不伪造聊天消息。
- 工具返回给模型的结果仅包含 `ok` 和固定 `code`，以及请求中的安全类别枚举；不含偏好值、偏好 ID、用户 ID、会话 ID。
- trace/activity 仅可保留工具名、类别枚举和固定结果状态，不保存个人资料或导航外的自由文本。

状态码建议：

| 结果                  | 固定 code         | 行为                                                 |
| --------------------- | ----------------- | ---------------------------------------------------- |
| 导航意图已接受        | `requested`       | 客户端尝试固定路由导航；不得据此伪称客户端已成功打开 |
| 输入无效              | `invalid_request` | 不导航                                               |
| 认证/会话上下文不可用 | `unavailable`     | 不导航、不修改偏好                                   |
| 客户端导航失败        | 客户端固定反馈    | 显示失败 Toast；不回传模型、不修改偏好               |

若聊天传输无法同步获知客户端导航最终结果，工具只报告 `requested`；前端负责根据实际路由结果展示成功或失败，不能将请求已发送等同于页面已打开。

## 与偏好 CRUD 的边界

- 不调用偏好读取接口，不将现有偏好值预填到页面或聊天。
- 不调用创建、更新、删除或设置接口。
- 不改变偏好开关关闭时手动管理页面可用的既有语义。
- 用户提交时复用 `/api/preferences` 及既有 Zod 校验、认证、归属检查和错误行为。
- 任何用户输入只在现有偏好管理前端与偏好 API 之间流转，不进入模型上下文、通用聊天表单结果或工具 trace。

## 草稿、重复与生命周期

- 不建立服务端草稿或偏好表单实例，不新增数据库表和迁移。
- 页面当前已有的本地未保存状态按既有页面生命周期处理；本契约不保证刷新、关闭页面或切换会话后恢复。
- 同一轮重复调用只处理第一次有效请求；后续聊天轮次可以重新请求导航，不应产生偏好数据写入或其他持久化副作用。
- 导航请求与偏好开关状态无关；页面继续按用户身份加载既有管理状态。

## 错误与安全

- 未知类别、额外字段及伪造身份、会话、URL 或资源字段：拒绝请求，不导航。
- 认证或运行上下文不可用：统一固定 `unavailable`，不泄漏内部异常。
- 前端无法解析或执行固定导航意图：固定失败状态，不回退到模型提供的 URL。
- 越权、异常和重复请求均不得引发偏好 CRUD。
- 聊天历史不得把自然语言或 Markdown 中的任意 JSON 当作导航命令。

- [x] 未知字段、非法类别和模型伪造的用户/会话/URL 均被拒绝。
- [x] 工具不读取或写入偏好，不改变设置，不预填已有值。
- [x] 模型仅得到安全状态和类别，不得到偏好明细或内部标识。
- [x] 前端实际导航失败时显示失败状态，不错误报告成功。
- [x] 重复调用、未登录和会话切换不会产生数据副作用。
- [x] 既有 CRUD 权限、校验、路由和设置语义保持不变。
