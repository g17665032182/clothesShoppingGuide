# 对话本站购物规则查询契约

## 状态与授权

- 日期：2026-11-17。
- 状态：依据用户“直接写完文档，然后按实施文档实施”及后续“继续”“确认”完成实现；API 类型检查、构建及定向格式检查通过，业务测试和运行验收暂缓。
- 工具：`get_shopping_rules`。
- 文档：[设计](../llm/chat-tool-shopping-rules-design.md)、[技术](../llm/chat-tool-shopping-rules-technical.md)、[实施](../llm/chat-tool-shopping-rules-implementation.md)。

只查询既有已确认契约描述的本站系统规则，不建立未经提供或审核的真实店铺政策。订单功能不支持售后，不表示用户没有相关权利。

## 权威来源与范围

来源固定为：

- `order-crud-contract`：对应 `docs/contracts/order-crud-contract.md`，负责金额、模拟支付、支付期、订单动作及非目标。
- `chat-tool-order-fulfillment-crud-contract`：对应已实施的本人本地履约摘要契约，负责本地来源和无实时轨迹边界。
- `security-and-business-boundaries`：对应 `docs/development/security-and-business-boundaries.md`，负责用户确认及模型无订单写权限。

当前运行源码已经实现上述规则。本次仅新增按主题返回的静态安全说明，不改订单规则或 API。历史设计中“所有商品和购买均为纯对话模拟”等旧描述不是本工具来源。

## 输入与权限

```json
{ "topic": "payment" }
```

`topic` 必填，严格枚举 `shipping`、`payment`、`cancellation`、`fulfillment`、`after_sales`，每次一个主题，不默认查询全部。使用 `z.strictObject`；未知字段、空值、自由文本、身份、订单号、URL、文件路径、版本选择及动作参数均拒绝，不做转换或模糊匹配。

仅在现有认证聊天中使用，JSON/SSE 共用注册；普通用户和管理员获得相同公开系统规则。工具不需要身份参数，不读任何用户、订单或地址数据，不扩大认证范围。

## 结果

成功返回 JSON 字符串，形状如下：

```json
{
  "ok": true,
  "scope": "site_capabilities",
  "source": "approved_project_contracts",
  "version": "2026-11-17.v1",
  "topic": "payment",
  "title": "付款规则",
  "statements": ["当前订单仅支持模拟支付，不产生真实扣款。"],
  "sourceDocumentIds": ["order-crud-contract"],
  "notice": "仅说明本站当前系统规则，不代表第三方商家政策、法定权利判断或售后受理结果。"
}
```

示例只说明形状；完整主题内容由服务端固定发布的目录决定。

- 所有对象严格拒绝未知字段。`ok`、scope/source/version/notice 是固定字面量。
- `title` 非空且至多 40 字符；`statements` 为 1–5 条、每条 1–300 字符；不含控制字符。
- `sourceDocumentIds` 为上述三个固定标识中的 1–3 个，不重复；不是 URL、文件读取指令或操作凭据。
- 每次只返回请求主题，且必须通过结果 schema；不返回内部路径、时间戳、账号、订单状态或其他用户数据。
- 固定目录缺失、损坏、主题不一致或异常时返回 `{ "ok": false, "code": "unavailable" }`。非法输入在工具 schema 拒绝，不执行读取，不以模型知识补齐。

## 五类内容边界

| 主题         | 已有来源允许说明的内容                                                                      |
| ------------ | ------------------------------------------------------------------------------------------- |
| shipping     | 当前本站订单 CNY 运费为 `0.00`、应付为商品金额；不是其他商家或未来政策承诺                  |
| payment      | 仅模拟支付，无真实扣款；支付期自订单创建起 30 分钟，具体截止以该订单服务端记录为准          |
| cancellation | 只支持本人未过期的 `pending_payment` 订单；用户选择并明确确认，提交时重验；已付款取消未接入 |
| fulfillment  | 管理员登记整单发货，用户自行确认收货；查询仅有本地状态，不支持实时轨迹或 ETA，不推断签收    |
| after_sales  | 系统未接入真实退款、退货、换货和退款进度；没有真实店铺退换条件、费用、地址或处理期限来源    |

不从 `after_sales` 的功能缺失推导“不退不换”、不符合法定条件或商家拒绝售后；不编造受理渠道、政策期限或承诺。

## 发布与维护

- 运行来源是随源码发布的只读主题目录，由本仓库订单/聊天维护者在代码审阅中维护；不是运行时任意 Markdown 读取、网络检索或向量知识库。
- 维护者修改来源规则时须在同次变更更新目录、schema 固定版本和文档；删去失效内容，未确认的新政策不发布。
- 本版只表示当前部署所包含的规则快照，版本不冒充商家生效日期。不提供过期版本查询、动态上架、管理员编辑、自动政策提取或联网更新。

## 隐私、历史与持久化

- 不新增业务 API、HTTP Body/Query/Param、SSE 事件、Entity、数据库迁移、文件写入、依赖或配置。
- 校验通过后立即复用本轮明细查询来源隔离标记；成功和故障均使用户/助手两条消息退出自动记忆与摘要来源且不入队，避免把系统规则存成个人偏好，下一普通轮恢复。
- 原始工具调用与结果从后续模型历史配对隐藏，包含独立、嵌套、非法及具名孤立结果。最终聊天正文仍按原规则保存。
- trace 输入最多保留合法 topic；结果仅保留 `ok`、合法 topic、固定版本和 1–5 的条目计数，或固定 unavailable；不保存正文、来源数组、原始参数或异常。
- activity 复用 `input/output: null`，不注册可操作卡片或展示 envelope。
