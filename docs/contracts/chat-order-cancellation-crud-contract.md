# 聊天订单取消契约

## 状态与依据

- 状态：已确认。
- 实现状态：未实现；本契约仅描述拟新增的聊天查询与展示行为。
- 资源：聊天中的本人可取消订单投影；不新增持久化资源。
- 所属模块：订单规则归属 `apps/api/src/orders/`；聊天工具与展示归属 `apps/api/src/chat-records/`、`apps/api/src/llm/`；前端归属 `apps/web/src/pages/chat/` 及共享订单组件。
- 关联文档：[设计文档](../modules/chat-order-cancellation/chat-order-cancellation-design.md)、[订单 CRUD 契约](./order-crud-contract.md)、[聊天购买 CRUD 契约](./chat-purchase-crud-contract.md)。
- 依据：既有订单状态规则、本人订单查询工具及取消接口；用户确认沿用只取消未支付订单的规则。

## 范围与权限

启用账号在明确表达取消订单意图后，可查询并选择取消本人尚未过期的待付款订单。查询工具通过服务端闭包绑定当前用户，不接受 `userId` 参数。聊天模型没有取消订单的写工具。

管理员不具备代用户取消权限。未登录、禁用账号或本人订单归属不匹配时，沿用既有认证、授权和本人订单 404 语义。

本功能不修改订单持久化字段、订单状态转换或原有 HTTP 动作契约，不新增 Migration。

## 可取消条件

| 订单当前状态       | 到期状态               | 聊天卡片                                                |
| ------------------ | ---------------------- | ------------------------------------------------------- |
| `pending_payment`  | 未到 `expiresAt`       | 展示摘要及取消入口                                      |
| `pending_payment`  | 已到或超过 `expiresAt` | 不作为可取消订单展示；先由既有订单读取/过期逻辑更新状态 |
| `pending_shipment` | 不适用                 | 不展示取消入口                                          |
| `pending_receipt`  | 不适用                 | 不展示取消入口                                          |
| `completed`        | 不适用                 | 不展示取消入口                                          |
| `closed`           | 不适用                 | 不展示取消入口                                          |

到期边界遵循原订单契约：`now >= expiresAt` 即到期。最终取消接口仍再次执行服务端状态及截止时间校验，聊天查询结果不构成锁定或取消承诺。

## LLM 工具契约

复用 `list_my_orders`，不新增写工具。

- 触发：仅在用户当前意图明确为取消订单时调用，并以 `pending_payment` 作为状态筛选。
- 归属：当前 `userId` 由服务端绑定，工具 schema 不接受用户 ID、订单收货信息或任意状态变更字段。
- 数量：最多返回 5 笔；沿用既有分页上限和订单排序。
- 输出白名单：订单 ID（受限引用）、订单号、状态、金额、商品名称、颜色、尺码、数量、创建时间，以及可取消判定所需的支付截止时间或布尔值。
- 输出禁止：姓名、手机号、完整地址、物流单号、付款凭证、内部用户 ID、数据库实体或管理字段。
- 操作能力：只读，不取消、不支付、不确认收货。
- 空结果：明确返回成功但无可取消订单；不得伪造卡片或声称取消成功。
- 工具错误：使用现有安全错误码；不回退为模型猜测订单状态。

工具查询结果用于模型回答及服务端构造结构化卡片。订单标识不得从 assistant 文本、Markdown、客户端提交的历史消息或未经服务端验证的工具 JSON 提取。

## 聊天展示投影

服务端为本轮 assistant 消息增加可选的可信订单卡片引用。展示字段为：

| 字段            | 规则                                                   |
| --------------- | ------------------------------------------------------ |
| `orderId`       | 本人订单 UUID，仅作为受限 API 引用                     |
| `orderNo`       | 服务端订单号                                           |
| `status`        | 当前订单状态                                           |
| `cancelable`    | 仅当本人订单为未过期 `pending_payment` 时为 `true`     |
| `items`         | 商品名称、颜色、尺码、数量白名单                       |
| `payableAmount` | 已存在订单金额投影                                     |
| `createdAt`     | 订单创建时间                                           |
| `expiresAt`     | 待支付订单截止时间，供状态提示；不是客户端权威时间判定 |

前端必须区分此服务端投影与普通 assistant 文本。仅可信投影可创建订单卡片和动作；渲染动作时仍只传 `orderId` 给现有本人 API，服务器重新授权并校验状态。

卡片使用现有取消确认交互。点击取消入口仅打开确认 UI；用户明确确认后才提交动作。成功提示只在收到服务端成功响应后显示。

## API 与校验

不新增公开 API。操作沿用：

| 操作         | 方法与路由                    | 请求                                     | 行为                                                        |
| ------------ | ----------------------------- | ---------------------------------------- | ----------------------------------------------------------- |
| 取消本人订单 | `POST /api/orders/:id/cancel` | Param：既有 UUID schema；Body：严格 `{}` | 仅本人未过期 `pending_payment` 可取消，成功返回本人订单详情 |
| 读取本人订单 | `GET /api/orders/:id`         | Param：既有 UUID schema                  | 查询最新状态，结果未知或冲突时用于恢复卡片                  |

两条路由沿用既有 Zod schema、`StandardSchemaValidationPipe`、JWT Guard 和订单契约中的状态码，不新增校验器或重复实现。非法输入、未知字段、本人隔离和非法状态转换按订单 CRUD 契约执行。

## 幂等、并发与失败恢复

- 取消状态转换继续由订单 Service 在现有事务及锁边界内执行。
- 查询与点击之间若订单已支付、到期、关闭或删除，服务端不按旧卡片状态执行取消。
- 409 时重新读取订单状态并更新卡片，取消入口依最新投影禁用或移除。
- 请求结果未知时不显示“已取消”；读取 `GET /api/orders/:id` 核实，不以新幂等键或模型文本推断结果。
- 同一订单重复取消遵循现有订单取消重试语义。

## 隐私与追踪

- 工具结果及卡片不允许返回或记录订单 `recipient`、物流快照、手机号、地址或支付凭据。
- 专属 trace 白名单只保留完成意图和结果追踪所需的工具名、受限订单标识、状态、可取消判定与安全错误码；不得保存完整订单 Entity。
- assistant 原始聊天文本及通用历史保存规则保持既有行为，不承诺清除用户主动发送的信息。
- 日志不得记录完整工具结果、认证凭据或收件信息。

## 错误行为

| 状态码 | 场景                             | 前端/模型行为                                    |
| ------ | -------------------------------- | ------------------------------------------------ |
| 400    | 订单 UUID 或请求格式非法         | 按既有安全错误显示，不提交动作                   |
| 401    | 未登录、Token 无效或账号禁用     | 沿用全局认证行为                                 |
| 404    | 订单不存在或不属于当前用户       | 不泄露他人订单存在性；刷新对应卡片或提示无法访问 |
| 409    | 已支付、已到期或其他非法状态转换 | 读取最新本人订单状态，不显示成功                 |
| 503    | 数据库暂时不可用                 | 保留失败/未知状态及重试入口                      |

具体状态码和映射以既有订单 CRUD 契约为准；本功能不扩大错误详情或新增订单枚举。

## 验收清单

- [ ] 工具只在明确取消意图后按本人身份查询待付款订单。
- [ ] 用户 ID 不可由模型或客户端传入；跨用户订单不可读取或取消。
- [ ] 只把当前未过期待付款订单投影为可取消卡片，最多 5 笔。
- [ ] 可信结构化投影以外的文本和工具输出无法生成按钮。
- [ ] 确认前不发起取消请求；成功提示依据 API 成功响应。
- [ ] 过期、已支付、已关闭及其他状态变化由服务端拒绝，并正确刷新。
- [ ] 请求未知结果经本人订单读取核实，不乐观改变状态。
- [ ] 工具、trace、卡片和日志不含收件信息、物流信息或支付凭据。
- [ ] 订单现有 schema、HTTP 错误、事务、库存释放、状态重试和历史消息兼容。
