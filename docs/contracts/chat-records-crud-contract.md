# 用户聊天记录 CRUD 契约

## 状态与上下文

- 状态：现有契约已确认（含系统上下文及客户端角色输入契约）；2026-11-03 AI Elements 设计关联扩展已确认。
- 资源名称：聊天会话与聊天消息
- 业务目的：持久化用户与大模型的聊天记录和 LangGraph 工具执行事件，并支持管理员分页查询可展示消息。
- 需求来源：用户明确要求自动保存、管理员查询、分页和标题自动生成。
- 确认依据：用户回复；现有 `LlmModule`、JWT Guard、RolesGuard 和 MikroORM 约定。
- 涉及模块：`apps/api/src/chat-records`、`apps/api/src/llm`、数据库迁移、内部聊天事件存储。
- 当前框架：NestJS 12、MikroORM 7.2、PostgreSQL、TypeScript 6.0.3。
- 最后更新：2026-11-03（设计关联扩展已确认，尚未实现）。

## 范围

- 包含：自动保存当前聊天轮次、用户会话列表/详情/删除、管理员列表/详情、分页和自动标题。
- 包含：通过 LangGraph 节点保存用户输入、模型输出、工具调用和工具结果等内部事件。
- 包含：调用模型前的聊天上下文压缩，完整原始消息仍然保留。
- 由后端维护并注入统一系统上下文；系统上下文内容见[后端系统上下文设计](../llm/system-context-design.md)。
- 系统上下文仅用于当前模型调用，不写入聊天消息、内部 trace、历史摘要或会话持久化数据。
- 所有客户端聊天入口仅接受 `user` 和 `assistant` 消息；客户端不得以 system 角色或额外系统指令字段提交系统信息，违规请求返回 `400`。
- 商品推荐和本站订单已接入真实目录及持久化业务；购买仅提供模拟支付、不真实扣款，正式订单动作由用户按钮触发。外部代购、退款售后仍未接入。
- 包含：下一轮模型调用时重建内部工具消息上下文。
- 包含：流式模型输出中的工具调用片段在服务端聚合、执行和持久化；工具片段不进入 SSE `delta`。
- 不包含：消息编辑、消息单独删除、全文搜索、管理员删除和系统消息持久化。
- 不包含：向前端展示工具调用参数、工具结果、内部错误和供应商原始响应。
- 路由前缀：全局 `/api`。

### 2026-11-08 聊天购买增量（已批准并实现）

[聊天购买契约](./chat-purchase-crud-contract.md)及技术、实施方案均已获确认并完成代码集成，增加真实商品购买草稿、确认卡及关联订单展示；正式订单动作由用户按钮调用，不提供模型订单写工具。草稿独立于聊天文本及摘要持久化，删除会话时清理草稿与展示引用，保留正式订单。用户主动发送的收货文本仍按本契约保存；购买轮次的 user/assistant 消息均标记 `memory_extraction_eligible=false`，不排队长期记忆提取，并从摘要来源排除。摘要通过最终 trace 的可见消息绑定识别整轮资格，不混用模型消息 ID 和数据库消息 ID；未绑定的失败/取消 trace 不作为摘要来源。验证证据与浏览器缺口见[实施记录](../chat-purchase/chat-purchase-implementation.md)。

## API 契约

| 操作           | 方法与路由                              | 认证/授权 | 响应                                  |
| -------------- | --------------------------------------- | --------- | ------------------------------------- |
| 聊天并保存     | `POST /api/llm/chat`                    | 登录用户  | `ChatOutput + conversationId + title` |
| 我的会话列表   | `GET /api/chat/conversations`           | 登录用户  | 分页会话                              |
| 我的会话详情   | `GET /api/chat/conversations/:id`       | 登录用户  | 会话 + 分页消息                       |
| 删除我的会话   | `DELETE /api/chat/conversations/:id`    | 登录用户  | `204`                                 |
| 管理员会话列表 | `GET /api/admin/chat/conversations`     | 管理员    | 分页会话，可按 `userId` 过滤          |
| 管理员会话详情 | `GET /api/admin/chat/conversations/:id` | 管理员    | 会话 + 分页消息                       |

### 聊天请求角色

- 所有客户端聊天入口（包括 `/api/llm/chat`、`/api/chat/chat` 和 `/api/chat/chat/stream`）仅接受 `user` 和 `assistant` 消息；客户端不得通过 system 角色消息或 `systemPrompt`、`systemContext`、`instructions` 等字段提交系统信息。
- 严格 Zod schema 对 system/未知角色和额外系统指令字段返回 `400`，不静默忽略。
- 服务端在调用模型前注入系统上下文；客户端不能设置、覆盖或移除该上下文。
- 系统上下文仅作为本次模型调用的运行时指令，不写入 `chat_messages` 或 `chat_trace_events`，也不参与历史消息重建和聊天摘要生成。
- 此限制只作用于 HTTP 客户端 DTO。后端内部 LLM 调用（例如聊天摘要）仍可使用 system 消息。
- 响应结构、认证方式、会话持久化和历史摘要行为不变；不新增数据库字段、表或迁移。

## 查询、权限与数据行为

- 分页：`page` 默认 1，`pageSize` 默认 20，最大 100。
- 会话排序：`updatedAt desc`；消息排序：`createdAt asc`。
- 资源归属：普通用户只能读取/删除 `userId` 等于当前用户的会话。
- 删除方式：物理删除会话，消息通过外键级联删除。
- 模型调用失败：不保存本轮展示消息；新会话保留会话及已提交的内部 trace，客户端取消则清理新会话及其 trace。
- Graph 节点已经写入的内部事件在后续模型或工具失败时保留，并记录失败状态或保留已有成功状态。
- 上下文压缩只影响发送给模型的请求，不修改或删除数据库中的原始消息。
- `LLM_CONTEXT_WINDOW_TOKENS` 由服务端配置；输入预算预留约 20% 输出空间。
- 可用输入预算达到 75% 时触发压缩，达到 90% 时必须压缩。
- 保留最近 25%～35% 输入预算，较早消息压缩为 512～1024 Token 结构化摘要。
- 使用摘要覆盖消息 ID 做增量压缩；摘要失败时降级为最近消息上下文。
- 标题生成：首条用户消息规范化后截取 30 个 Unicode 字符。
- 消息内容保存 DTO/LlmService 转换后的字符串，不保存 LangChain `BaseMessage` 或供应商原始结构。
- 内部事件保存重建模型上下文所需的规范化字段，不保存 API Key、Token、数据库连接信息或未经脱敏的供应商原始响应。
- 工具事件只用于服务端审计和历史重建，不出现在普通用户或管理员的消息分页响应中。
- 工具事件不出现在流式 `delta` 事件中；工具执行期间允许没有文本增量。
- 内部事件使用 `runId + sequence` 和 `toolCallId` 保证重试幂等。
- 不存在或越权资源：统一返回 `404`。
- 单事件 `payload` 序列化后最大 `32768` 字节；超限拒绝事件写入并使 Graph 调用失败。
- V1 在写入前递归掩码常见凭证字段；此规则不替代未来按工具增加的字段 allowlist 或专属脱敏器。

## 2026-11-03 AI Elements 展示扩展（已确认）

确认依据：2026-11-03 用户回复“确认设计文档”。以下为该设计关联的消息展示扩展；技术及实施文档通过审批后才能修改代码。

- 消息响应新增 `activities: ChatActivity[]`、`sources: ChatSource[]` 和 `context: ChatContextUsage | null`，字段见[流式契约](./chat-streaming-crud-contract.md)。
- 只展示与已保存 assistant 消息 ID 绑定的 `payload.publicDisplay` 公开投影；用户消息和旧记录返回空活动、空来源和 null 上下文，不从旧正文生成元数据。
- 先校验会话权限，再读取当前页对应展示数据；普通用户越权仍为 404，管理员沿用原只读权限。
- 本扩展取代此前工具信息完全不展示的限制；内部 trace 对象、系统指令、记忆全文、原始错误和供应商响应不公开。
- 历史投影再次应用白名单与敏感字段过滤，不将数据库中的任意 payload 直接当响应返回。
- Sources 保存该轮真实结构化来源的稳定 ID、标题和合法 URL，恢复时重新校验并去重；历史页不自动抓取链接。
- Context 恢复本轮最终模型调用的用量与当时保存的窗口上限；旧记录未知时为 null，不套用当前模型配置伪造历史百分比。
- 拟复用现有模型 trace JSON 字段，绑定和消息保存处于同一事务；不改变原请求、Entity、索引、迁移和删除级联规则。
  具体可行性在技术阶段验证；必要的数据结构调整须重新确认。

关联[设计文档](../chat-streaming/ai-elements-design.md)和[技术文档](../chat-streaming/ai-elements-technical.md)；历史验收项记录原有能力，不代表本扩展已实现或验证。
