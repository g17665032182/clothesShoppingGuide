## 状态与依据

- 状态：原契约于 2026-11-10 已确认；2026-11-13 确认的用户信息工具及下单地址选择卡联动已实施；其余字段/API 提案状态不变。
- 实现状态：地址簿核心 CRUD 与地址选择 API 已实现；登录态浏览器验收未执行。
- 最后更新：2026-11-13。
- 资源：用户收货地址簿。
- 所属模块：拟新增 `apps/api/src/user-addresses/`；前端页面归账号区域。
- 关联文档：[收货地址设计](../user-addresses/user-addresses-design.md)、[订单契约](./order-crud-contract.md)、[聊天购买契约](./chat-purchase-crud-contract.md)。
- 依据：用户确认建立本人地址管理、LLM 本人地址/订单查询及购买对话采集地址；查询工具不得回传完整联系方式；新增地址须显式确认。

## 范围与授权

地址簿覆盖启用用户对本人地址的列表、详情、新增、修改、删除和默认地址设置。地址 ID、当前登录用户和会话 ID 由服务端授权上下文绑定。

管理员仅可管理自己的地址；不提供跨用户地址管理接口。普通用户列表和工具均不接受 `userId` 参数。

LLM 可调用 `get_my_information` 查询本人订单摘要、地址引用和已保存图片元数据。工具 schema 不接受 `userId`。地址结果只含地址 ID、默认标志和系统生成标签；不得返回完整姓名、手机号、完整地址或订单收件快照。`list_my_orders` 仍服务既有本人订单/取消候选流程，地址专用模型查询工具已停用。

模型不得执行地址簿写入或正式订单动作。用户在购买对话提供新地址后，服务端生成结构化确认卡；用户点击显式保存按钮后，才写入地址簿。用户可选择仅用于本次订单而不持久化。

## 逻辑字段（提案）

| 字段     | API 名称/类型           | 持久化提案                          | 写入与返回约定                                 |
| -------- | ----------------------- | ----------------------------------- | ---------------------------------------------- |
| 主键     | `id: string`            | UUID                                | 服务端生成；仅本人返回                         |
| 收件人   | `recipientName: string` | `varchar`，长度待确认               | 本人 CRUD 可读写；只读地址工具不返回           |
| 联系电话 | `phone: string`         | `varchar`，长度待确认               | 本人 CRUD 可读写；只读地址工具不返回完整值     |
| 完整地址 | `address: string`       | `text` 或 `varchar`，字段拆分待确认 | 本人 CRUD 可读写；地址工具不返回               |
| 标签     | `label: string \| null` | `varchar` 或 null                   | 供用户辨认；模型可按确认后的脱敏规则读取       |
| 默认标志 | `isDefault: boolean`    | `boolean`                           | 任一用户最多一条为默认；具体默认转换规则待确认 |
| 用户归属 | `userId: string`        | UUID + 外键                         | 仅服务端写入，不出现在本人响应或模型工具结果   |
| 创建时间 | `createdAt: string`     | `timestamptz`                       | 服务端维护，只读                               |
| 更新时间 | `updatedAt: string`     | `timestamptz`                       | 服务端维护，只读                               |

下单时将地址簿当时的姓名、电话和地址复制到订单收件快照。后续地址修改/删除不得改变订单快照。订单快照不持有对地址簿记录的级联删除关系。

地址字段布局、名称、长度、唯一约束和地址数量上限均待用户确认；以上字段暂为设计提案，不可据此创建 Entity 或 Migration。

## 输入校验（提案）

- 所有 Body、Query、Param 使用所属模块 Zod schema，`z.strictObject` 拒绝未知字段，并使用现有 Nest `StandardSchemaValidationPipe`。
- `id` 必须为 UUID；用户 ID、`isDefault`、审计时间和归属不得由客户端写入。
- 姓名、电话、地址和标签需 trim、拒绝控制字符，并限制最大长度；具体边界待确认。
- PATCH 省略表示不修改；是否允许显式 `null` 清除标签或默认状态待确认。
- 电话格式沿用订单契约的可选前缀 `+` 加 6–20 位数字作为提案，待确认。
- 新地址结构化确认卡及地址工具均复用相同字段规则，不接受模型推断的 `userId`、`addressId` 所有权或 `isDefault`。
- 任一字段校验失败返回 HTTP 400，未知字段不得静默忽略。

## API 契约（提案）

全局前缀 `/api`，全部要求启用账号 Bearer JWT。成功响应为独立安全 DTO，不直接返回 Entity。

| 操作         | 方法与路由                         | 请求                                                            | 成功响应                        | 权限/错误                             |
| ------------ | ---------------------------------- | --------------------------------------------------------------- | ------------------------------- | ------------------------------------- |
| 本人地址列表 | `GET /api/user-addresses`          | Query：分页参数待确认                                           | 200，地址数组或分页             | 本人；401                             |
| 本人地址详情 | `GET /api/user-addresses/:id`      | UUID Param                                                      | 200，完整本人地址               | 他人或不存在均 404                    |
| 新增地址     | `POST /api/user-addresses`         | Body：UUID `requestKey`、收件人、电话、地址、标签、可选默认提案 | 201，地址 DTO；重放时返回原地址 | 400 校验；409 键内容冲突/默认并发冲突 |
| 修改地址     | `PATCH /api/user-addresses/:id`    | UUID Param + 部分地址字段                                       | 200，更新 DTO                   | 他人或不存在 404；400/409             |
| 删除地址     | `DELETE /api/user-addresses/:id`   | UUID Param                                                      | 204                             | 他人或不存在 404                      |
| 查询默认地址 | 不单独暴露；列表内标识 `isDefault` | 无                                                              | —                               | 是否需要独立路由待确认                |

对外 API 路径待确认；仓库其他本人资源使用 `/api/users/me`，因此 `GET/PATCH/DELETE /api/users/me/addresses` 也是候选。确认前不生成 DTO 或 Controller。

## LLM 查询与地址选择契约

用户信息工具逐请求绑定 `currentUser.id`，模型不能自行指定归属。地址查询通过统一的 `get_my_information` 工具完成：

| 工具/操作            | 输入                                              | 输出                                                        | 明确禁止                                                      |
| -------------------- | ------------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------- |
| `get_my_information` | `sections: ["addresses"]`、有界 `page`            | 本人地址 `addressId`、`isDefault`、系统生成的 `displayName` | `userId`、姓名、完整电话、完整地址、用户自定义标签            |
| 购买地址选择认证 API | `addressId`、当前草稿路径参数和 `expectedVersion` | 本人购买草稿安全响应；仅认证 HTTP 响应包含当前草稿收件信息  | 模型调用、完整地址请求体、跨会话/跨用户引用、自动选择默认地址 |

地址选择路由为 `POST /api/chat/conversations/:conversationId/purchase-draft/:draftId/select-address`，Body 使用严格 schema，只接受 `addressId` 与 `expectedVersion`。服务端从当前用户地址簿读取完整值，再校验当前购买草稿归属、状态和版本后写入草稿。`select_my_shipping_address` 不再注册为模型工具；旧 trace 和历史读取仅保留安全兼容处理。地址簿新增只通过认证 HTTP 确认操作写入，不提供模型可调用的 `create_address` 工具。

工具错误统一为不会区分他人资源存在性的安全错误；完整地址不得出现在工具返回、模型调用追踪、工具 activity、日志、摘要或长期记忆。工具只读查询结果必须经过响应白名单。

## 购买对话与地址保存契约（提案）

- 点击商品卡“购买”后，仅在当前会话购买草稿中询问缺失收货字段。
- 用户明确选中本人地址 ID 后，服务端按当前用户读取记录并复制当时地址字段至草稿；越权或失效 ID 返回通用不可用结果。
- 购买草稿缺少收件字段且用户本轮未明确提供完整信息时，通过 `get_my_information` 查询 `addresses` section。查询成功且地址簿非空时，前端以选择卡展示本人地址，由用户明确点击后才写入本次购买草稿。
- 默认地址只可作为卡片标记，不自动选中或写入。卡片以外的地址详情由前端使用本人地址 API 临时读取；选择操作必须校验当前用户、地址 ID 和草稿版本。
- 地址查询成功且地址簿为空时，通过 `request_dynamic_form` 询问当前草稿尚缺字段；查询失败时不能按空地址簿处理，只有用户明确选择手动填写后才调用动态表单。
- 对话收集的新地址先生成服务端校验后的预览，不直接持久化。
- 用户可选择“保存到地址簿”或“仅用于本次订单”。保存动作由前端结构化卡按钮调用地址簿创建 API；不能由模型文本或工具自动触发。
- 地址创建请求必须包含由客户端为每次新增生成的 UUID `requestKey`。同一用户、同一键、相同规范化地址内容的重试返回原地址；同一用户、同一键但内容不同返回 409。数据库以 `(user_id, create_request_key)` 唯一约束兜底。
- 地址簿保存与购买草稿更新分别提交，不做跨模块事务。保存结果未知时，客户端使用原 `requestKey` 重试；服务端返回已保存地址后，后续购买草稿更新使用该权威结果，不得再次创建地址。
- 地址详情仅在本人地址簿页和本人购买确认视图展示。LLM 工具结果只返回地址引用，不回传具体值。
- 用户原始聊天消息仍按既有聊天记录规则持久化并发送至已配置模型提供方；本契约不宣称对这些既有路径做全面删除或脱敏。
- 地址字段不得进入长期记忆和通用摘要。地址相关工具 trace 采用字段白名单，不得保存明文参数或结果。
- 卡片选择只将用户明确选中的地址写入本次购买草稿，不改变默认标志、不新建地址，也不自动确认正式订单；订单仍由用户显式提交。

## 默认地址、排序与并发（待确认）

- 地址列表排序提案：默认地址优先，其余按 `updatedAt DESC, id DESC`。
- 地址数量上限、分页默认值和最大页大小待确认。
- 设置新默认地址必须与清除旧默认在同一事务完成；任一用户最多一个默认地址。
- 首条是否自动成为默认、能否清除默认、删除默认后的行为和并发默认切换冲突返回规则待确认。
- 并发 PATCH 使用更新时间或版本条件的具体方案在技术阶段定义；不允许迟到写入覆盖较新数据。
- 重复地址是否允许、如何处理待确认。

## 错误行为（提案）

| 状态码 | 场景                                                           |
| ------ | -------------------------------------------------------------- |
| 400    | 输入非法、未知字段、字段长度/格式越界                          |
| 401    | 未登录、Token 无效或账号禁用                                   |
| 404    | 地址不存在或不属于当前用户；对外统一                           |
| 409    | 默认地址并发冲突、版本冲突、同一 `requestKey` 对应不同地址内容 |
| 503    | 现有异常映射判定的数据库暂时不可用                             |
| 500    | 未预期内部错误；不得泄露 SQL、连接或对象内容                   |

## 迁移、删除与生命周期

- 新增独立 `user_addresses` 持久化资源，带用户外键和用户查询所需索引；列类型、索引、唯一默认实现和删除策略待技术阶段确定。
- 新用户无地址时正常返回空列表，不阻止其他账号或订单能力。
- 删除地址仅删除地址簿记录；正式订单快照永久按既有订单保留规则处理。
- 用户禁用不自动转移或读取其地址；账号注销、聊天删除和备份中的地址保留/清除期限待确认。
- 迁移必须增量并验证外键、索引、唯一默认规则及历史数据兼容；禁止使用 `migration:fresh` 替代迁移验证。

## 验收清单

- [ ] Zod/Nest 校验覆盖有效/非法字段、边界、未知字段、默认值和 400 映射。
- [ ] CRUD、归属隔离、管理员本人边界、禁用账号、资源不存在和默认地址并发有测试。
- [ ] 同一用户最多一个默认地址；用户确认的创建/删除/清除规则均有覆盖。
- [ ] 地址工具不能接收 userId，无法返回完整 PII，也无法调用订单写操作。
- [ ] 订单查询工具只能看到当前用户的摘要，无法查询他人订单或订单收货快照。
- [ ] 用户选地址后服务端复制权威值，模型不能通过 ID 或完整字段越权。
- [ ] 同一用户使用同一 `requestKey` 和相同规范化内容重试返回原地址；同键不同内容返回 409。
- [ ] 地址簿保存与购买草稿更新分别提交；保存响应未知时可用原键重试并恢复流程，不产生重复地址。
- [ ] 购买对话新地址未显式点击保存时不会写入地址簿。
- [ ] 下单时缺失字段会查询地址簿；地址存在时用户通过前端卡片明确选择，无地址时请求动态表单。
- [ ] 默认地址只标记不自动选中；查询失败不会走空地址分支。
- [ ] 地址详情不进入模型、trace、activity、历史或 `publicDisplay`；旧订单地址不自动复用。
- [ ] 工具参数/结果、trace、activity、日志和摘要不新增明文地址副本。
- [ ] 修改/删除地址不改变既有订单收货快照。
- [ ] Migration 在具名隔离数据库验证；不影响默认开发数据库。
