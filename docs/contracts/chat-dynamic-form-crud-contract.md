# 聊天动态表单 CRUD 契约

## 状态与依据

- 状态：原契约及 2026-11-13 确认的地址选择卡片/空地址簿表单联动已实施；登录态浏览器验收未执行。
- 资源：绑定聊天会话的动态表单实例及一次提交结果。
- 所属模块：`chat-dynamic-form`；聊天流由 `chat-records` 传输，业务写入由具体领域模块处理。
- 最后更新：2026-11-13。
- 关联文档：[动态表单设计](../chat-dynamic-form/chat-dynamic-form-design.md)、[流式聊天契约](./chat-streaming-crud-contract.md)、[聊天购买契约](./chat-purchase-crud-contract.md)。

## 权限与范围

启用账号只能读取、填写和提交本人会话中的动态表单。模型只能请求生成表单，不拥有提交用户值的权限。管理员不具备跨用户表单读取或提交权限。

表单提交是业务处理入口，但不改变具体业务模块的确认规则。购买表单只更新购买草稿；正式订单、支付、取消和确认收货仍由既有用户操作接口执行。

## 资源字段

| 字段          | 类型          | 规则                                        |
| ------------- | ------------- | ------------------------------------------- |
| `formId`      | UUID          | 服务端生成，绑定用户、会话和运行            |
| `formKind`    | 注册表标识    | 服务端注册，首版 `purchase_recipient`       |
| `revision`    | 正整数        | 字段定义或服务端初始值变化时递增            |
| `title`       | 字符串        | 服务端限制长度，纯文本                      |
| `description` | 字符串或 null | 纯文本，不允许 HTML/脚本                    |
| `fields`      | 字段数组      | 1–20 个，严格字段 schema                    |
| `submitLabel` | 字符串        | 服务端限制长度，纯文本                      |
| `status`      | 枚举          | `open`、`submitted`、`expired`、`cancelled` |
| `expiresAt`   | ISO 时间      | 服务端生成                                  |

字段对象：

```json
{
  "key": "recipient.phone",
  "label": "手机号",
  "type": "tel",
  "required": true,
  "placeholder": null,
  "options": null
}
```

首版字段类型为 `text`、`textarea`、`tel`、`number`、`select`、`checkbox`。`select` 必须提供 1–50 个服务端确认选项；其他类型不得携带 `options`。未知字段、重复 key、控制字符、过长文本和额外对象键均拒绝。

## 工具契约

### `request_dynamic_form`

模型工具输入为严格对象：

```json
{
  "formKind": "purchase_recipient",
  "fields": [
    {
      "key": "recipient.name",
      "label": "收件人",
      "type": "text",
      "required": true
    }
  ],
  "title": "补充购买信息",
  "description": "请填写下单所需信息",
  "submitLabel": "确认提交"
}
```

服务端只接受注册 `formKind`，并将字段与业务处理器允许字段求交集；模型不能提供用户 ID、会话 ID、订单 ID、提交 URL、数据库字段、任意校验表达式或敏感初始值。

工具成功后，服务端发送 `form` SSE 事件：

```json
{
  "form": {
    "formId": "uuid",
    "formKind": "purchase_recipient",
    "revision": 1,
    "title": "补充购买信息",
    "description": "请填写下单所需信息",
    "fields": [],
    "submitLabel": "确认提交",
    "status": "open",
    "expiresAt": "2026-11-14T00:00:00.000Z"
  }
}
```

工具结果和 trace 只保存安全引用、状态和字段 key，不保存用户填写值。

## HTTP/API 契约

具体路由在技术阶段确定；逻辑操作固定如下：

| 操作         | 输入                           | 成功结果                 |
| ------------ | ------------------------------ | ------------------------ |
| 读取当前表单 | 当前会话                       | 当前 `open` 表单或 null  |
| 提交表单     | `formId`、`revision`、`values` | 业务处理器结果和表单状态 |
| 取消表单     | `formId`、`revision`           | 表单进入 `cancelled`     |

提交输入：

```json
{
  "revision": 1,
  "values": {
    "recipient.name": "张三",
    "recipient.phone": "13800000000"
  }
}
```

`values` 必须是严格对象；字段 key 必须属于服务端表单定义；值按字段类型和 `formKind` 的业务 schema 再次校验。缺少必填字段、未知字段、类型错误、过期、版本冲突和业务资源变化分别返回可公开错误。

## 状态、幂等与错误

- 相同 `formId`、`revision` 和规范化值的重复提交返回第一次业务结果。
- 相同表单提交不同值返回 409，不能覆盖已提交结果。
- 表单读取或提交必须检查当前用户和会话归属；越权统一为 404。
- `400`：请求结构、字段 key、字段类型或未知字段非法。
- `404`：表单不存在或不属于当前用户/会话。
- `409`：版本冲突、已提交、已取消、已过期或业务资源状态不允许。
- `422`：业务处理器返回字段级语义错误（如手机号格式不符合购买契约）；是否采用 422 待技术阶段结合现有异常映射确认。
- `503`：数据库或依赖服务暂不可用。

表单提交未知结果时，前端重新读取同一 `formId` 状态，不生成新表单或盲目重复写入。

### 购买地址卡片联动（已实施）

- 购买草稿缺少收件字段时，先使用 `get_my_information` 查询本人地址簿。
- 地址簿非空时展示只含安全引用的前端地址选择卡；用户明确点击后才更新本人草稿。
- 默认地址仅作标记，不自动选中或写入草稿。
- 只有查询成功且地址簿为空时，才调用 `request_dynamic_form` 收集尚缺字段。
- 地址详情由前端通过本人 API 临时读取，不进入模型或聊天持久化投影；表单仍不创建正式订单。

## 传输、历史与隐私

- `form` 定义通过当前 SSE 运行发送；历史仅保存安全的表单引用和脱敏状态，不保存表单填写值。
- 普通 Markdown 中出现的 JSON 不作为表单。
- 表单卡片不凭自身字段获得订单、地址或其他业务权限。
- 用户填写值不得进入 tool activity、trace 原文、普通日志、长期记忆或模型下一轮上下文；业务模块仅接收服务端解析后的值。
- 表单结果可返回 `formId`、`formKind`、状态、业务引用和公开 issues，不返回联系方式、详细地址、密钥或内部对象。

## 兼容性与迁移

首版优先复用现有聊天展示 envelope、SSE 通道和业务服务公开 Port；是否新增表单实例持久化表、迁移和恢复接口待技术阶段确认。不得用 `migration:fresh` 替代增量迁移验证。

## 验收清单

- [ ] 工具严格拒绝未知 `formKind`、字段类型、字段 key 和额外键。
- [ ] SSE 只发送服务端校验后的表单 JSON，不发送模型原始参数。
- [ ] 前端只渲染注册字段类型，不能执行任意组件或脚本。
- [ ] 提交必须经过用户确认、服务端业务 schema、归属检查和版本校验。
- [ ] 重复、断网、过期和冲突不会产生重复业务写入。
- [ ] 购买表单不创建正式订单，敏感值不进入模型和通用展示链路。
- [ ] 表单字段错误能定位到字段，并保留用户未提交的本地值。
