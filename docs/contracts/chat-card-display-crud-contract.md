# 聊天卡片展示 CRUD 契约

## 状态与依据

- 状态：设计、契约、技术文档和实施文档已由用户确认；功能已实现，验证结果见[实施记录](../chat-card-display/chat-card-display-implementation.md)。
- 资源：聊天 assistant 消息中的结构化卡片展示块。
- 所属模块：`chat-records` 负责服务端投影；`llm` 提供工具运行结果；`apps/web` 负责解析及组件分发。
- 关联文档：[聊天通用卡片展示设计](../chat-card-display/chat-card-display-design.md)、[聊天记录 CRUD 契约](./chat-records-crud-contract.md)、[流式聊天 CRUD 契约](./chat-streaming-crud-contract.md)。
- 最后更新：2026-11-12。

本契约描述聊天卡片展示行为。当前确认的聊天记录、SSE、商品目录、订单、购买和取消契约继续有效。

## 目标协议

助手需要展示商品、订单等列表时，调用统一的前端展示工具。工具返回卡片 JSON；Markdown 展示层识别 `type` 并按 `name` 选择对应模板。该工具负责呈现结构，不取代商品目录或订单模块的数据查询和权限检查。

卡片对象：

```json
{
  "type": "card",
  "name": "product",
  "data": {}
}
```

| 字段   | 类型             | 规则                                                               |
| ------ | ---------------- | ------------------------------------------------------------------ |
| `type` | 固定字符串       | 只能为 `card`，作为卡片展示判别字段                                |
| `name` | 注册表标识       | 选择具体模板；首批为 `product`、`order`                            |
| `data` | 按模板定义的对象 | 使用对应模板的严格 schema 校验，不接受任意实体或任意 trace payload |

展示工具名为 `display_chat_card`。工具仅接收模板名及当前轮次领域查询结果的引用，由服务端从本轮安全来源物化卡片，不接受模型编写的商品价格、库存、订单状态等业务事实。每张卡片最多 5 个条目；卡片与既有展示数据共用 16 KiB `publicDisplay` 预算，超限时拒绝新增卡片，不截断业务字段。订单卡首版只读。

## 传输与历史行为

- 流式聊天：服务端仅在卡片数据通过工具来源检查和公开字段校验后，通过独立 `card` SSE 事件向对应 assistant 回复发送结构化卡片展示数据，事件载荷为 `{ "card": { "type": "card", "name": "...", "data": {} } }`。
- Markdown 集成：前端 Markdown 展示层识别 `type: "card"`，将 `name` 映射到本地注册的 Vue 卡片组件；未知类型或名称不动态加载任意组件。
- 历史恢复：卡片存入与已保存 assistant 消息 ID 绑定的服务端 `publicDisplay.cards`；不从客户端正文、普通 Markdown JSON 或未经校验的内部 trace payload 重建。
- 兼容：普通消息正文和既有展示字段保持兼容；`productResults`、`orderCancellationCandidates`、`purchase` 保留，不迁移或删除。
- 持久化：复用现有聊天展示元数据，不新增 Entity、字段、索引或 Migration。

卡片数据采用服务端校验后的结构化通路，不扫描普通 Markdown 正文中的任意 JSON。新增事件不改变现有 `delta`、`activity`、`done`、`error` 语义；卡片在正文之后按工具调用顺序展示。

## 数据、权限与安全

- 卡片属于当前认证用户有权访问的聊天会话；普通用户越权和不存在资源沿用聊天记录 404 约定。
- 卡片只能承载对应业务模块允许公开的数据。服务端按 `name` 使用字段白名单，拒绝未知字段，并限制字符串、数组和 JSON 总字节数。
- 商品价格、库存、商品标识及订单状态必须来自已验证的领域工具/服务结果，不能信任模型重新编写的同名 JSON 字段。
- 订单数据不含 recipient、手机号、详细地址、物流单号、支付凭据、userId、Entity 或管理字段。
- `type: "card"` 与 `name` 只选择展示形态，不构成授权、确认或写操作凭据。
- 订单操作继续沿用订单契约：用户显式操作、服务端当前用户归属检查、状态复核及既有确认 UI。
- 工具 activity 不公开卡片原始输出；工具 trace 仅可记录工具 schema 允许的引用字段及卡片公开字段白名单投影。未经投影的原始载荷、完整实体、联系方式、密钥、图片 Base64、对象键和签名 URL 不得进入公开响应、activity、日志或工具 trace。

## 错误与降级

| 情况                              | 行为                                                     |
| --------------------------------- | -------------------------------------------------------- |
| 普通 Markdown 或普通代码块        | 沿用现有 Markdown 渲染                                   |
| `type` 不是 `card`                | 不按卡片处理                                             |
| JSON 格式非法或模板 schema 不匹配 | 不渲染卡片；不把部分字段当作可信数据                     |
| `name` 未注册                     | 不动态选择组件；保持安全降级                             |
| 服务端工具结果来源不可信          | 不发送卡片数据                                           |
| 历史记录缺少新字段或包含旧版本    | 保留正文并返回无卡片数据                                 |
| 卡片数据预算超限                  | 拒绝新增卡片，不截断字段；正文和既有有效展示数据保持可读 |

历史 envelope 缺少 `cards` 时回退为空数组；损坏或未知模板卡片整卡丢弃，其他有效消息内容继续展示。

## 验收清单

- [x] 仅 `type: "card"` 进入卡片展示路径。
- [x] `name` 只映射到明确注册的商品、订单等本地模板。
- [x] 每种卡片采用独立严格结构校验和字段白名单。
- [x] 普通 Markdown JSON、模型正文和客户端历史内容不能伪造可信订单动作。
- [x] 实时响应与历史恢复遵循相同的数据来源、消息绑定和权限检查。
- [x] 旧消息和未知卡片名称安全降级，现有商品、订单及购买流程保持兼容。
- [x] 订单卡片不扩大既有订单写权限或绕过用户确认。

实施任务拆分、文件所有权、集成顺序和验收标准已由用户确认，详见[实施文档](../chat-card-display/chat-card-display-implementation.md)。
