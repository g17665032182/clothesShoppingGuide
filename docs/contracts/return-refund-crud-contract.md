## 范围与权限

本契约描述本人订单退货退款申请从聊天草稿创建或订单页直接创建、用户提交、管理员审核、退货物流登记至本站退款状态登记的行为。它不表示商家已受理，也不执行任何真实资金操作。

- 大模型必须调用已注册的售后工具才能创建本人订单的“待用户提交”申请；普通回复文本、Markdown、前端解析或未注册工具不能创建记录。订单、用户和商品归属均由服务端校验。
- 用户可从本人订单页独立创建并直接提交申请，无需调用大模型；也可查看、补充并提交助手创建的申请、上传可选凭证、填写退货物流，并在限定阶段取消。
- 管理员使用现有管理员角色在后台审核、拒绝、确认收货验货、推进退款中及登记退款完成。
- 模型没有审核、拒绝、取消、物流填写或退款状态写入工具；助手工具只执行经明确确认的申请草稿创建。
- 一笔订单最多一条未结束申请。申请终态后可重新申请；已退款数量不可再次申请。
- 未提供越权读取、管理员代用户申请、换货、真实退款或任意状态修改。

## 申请状态

| 状态                      | 含义                                           |
| ------------------------- | ---------------------------------------------- |
| `pending_user_submission` | 助手创建，等待用户在订单页检查、补充并提交     |
| `pending_review`          | 用户正式提交，等待管理员审核                   |
| `approved_pending_return` | 管理员通过，等待用户寄回                       |
| `returned_by_user`        | 用户已填写退货承运商和物流单号                 |
| `pending_inspection`      | 管理员确认包裹收到，等待/正在验货              |
| `refund_processing`       | 管理员登记本站退款处理中                       |
| `refunded`                | 管理员登记本站退款完成，不代表真实资金渠道退款 |
| `rejected`                | 管理员拒绝，必须有拒绝原因                     |
| `cancelled`               | 用户在允许阶段取消                             |

`pending_review` 可以附带 `manualReviewRequired` 标记及原因。规则内申请须为订单 `completed`，且提交时的北京时间自然日不晚于确认收货日后的第 6 个自然日；确认收货当天算第 1 天，第 7 天 23:59:59.999 为截止时刻（含）。超期、未完成或无法可靠判定的申请仍可提交，但必须进入人工审核队列，不得自动拒绝或由模型判定。

## 数据语义

### 申请

| 字段             | 语义                                                                                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 申请 ID          | 服务端生成 UUID，不可由客户端指定                                                                                                                        |
| 订单 ID / 订单号 | 关联唯一订单；响应按用户/管理员权限投影                                                                                                                  |
| 买家 ID          | 由服务端订单归属确定，普通用户输入中不存在                                                                                                               |
| 状态             | 仅按允许的状态机流转                                                                                                                                     |
| 原因             | 用户自由描述，助手可整理；创建前须向用户展示并确认                                                                                                       |
| 人工审核标记     | 由服务端按订单状态和收货时间判定，模型不可提供                                                                                                           |
| 拒绝原因         | 管理员拒绝时必填，普通用户不可写入                                                                                                                       |
| 金额、币种       | 服务端由申请项订单快照计算；管理员不可修改                                                                                                               |
| 凭证             | 用户订单页可选上传、可后补；支持 JPG/PNG/WebP 图片（单份最大 10 MiB）及 MP4 视频（单份最大 50 MiB），每申请最多 5 份；不得进入聊天模型、trace 或公开日志 |
| 退货物流         | 通过审核后用户必填一组承运商和物流单号                                                                                                                   |
| 审核与动作时间   | 服务端记录各状态转换时间及执行角色                                                                                                                       |

### 申请项

每项引用原订单明细，保存购买数量、申请数量、快照单价和计算金额。申请数量为正整数，不得超过该商品购买数量减去已登记退款完成的数量。申请金额为快照单价乘申请数量之和；不含其他费用，不可由客户端或管理员覆盖。

一个申请允许选择一笔订单中的部分或多项商品。凭证按申请归属，不作为模型工具数据。文件访问、格式、数量、尺寸与保留策略需在技术阶段依托现有私有文件能力确认。

## 行为与转换

| 动作                     | 初始状态                                     | 后续状态                  | 权限与规则                                               |
| ------------------------ | -------------------------------------------- | ------------------------- | -------------------------------------------------------- |
| 聊天创建申请             | 无                                           | `pending_user_submission` | 当前用户本人订单；商品、数量、原因齐全；本轮明确再次确认 |
| 订单页直接申请           | 无                                           | `pending_review`          | 本人订单页提交；商品、数量、原因齐全；用户显式提交       |
| 用户提交                 | `pending_user_submission`                    | `pending_review`          | 本人；校验订单与申请项；服务器计算常规/人工审核标记      |
| 用户取消                 | `pending_user_submission` / `pending_review` | `cancelled`               | 本人；其他阶段不可取消                                   |
| 管理员通过               | `pending_review`                             | `approved_pending_return` | 管理员角色；原子状态校验                                 |
| 管理员拒绝               | `pending_review`                             | `rejected`                | 管理员角色；拒绝原因必填                                 |
| 用户登记寄回             | `approved_pending_return`                    | `returned_by_user`        | 本人；承运商与物流单号必填                               |
| 管理员确认收货           | `returned_by_user`                           | `pending_inspection`      | 管理员角色                                               |
| 管理员确认验货并开始退款 | `pending_inspection`                         | `refund_processing`       | 管理员角色；本站登记，不发起真实退款                     |
| 管理员登记退款完成       | `refund_processing`                          | `refunded`                | 管理员角色；固定申请金额，不可修改                       |

状态转换采用服务端并发保护；重试不得重复扣减已退款数量或伪造退款完成。`rejected`、`cancelled`、`refunded` 为终态；同订单终态后可新建申请，但累计 `refunded` 数量不可超过订单购买量。

## 输入与校验

所有对象输入默认严格拒绝未知字段。身份字段、状态、审核标志、金额、审核时间及退款数量不允许由用户或模型指定。

- 聊天工具创建输入：本人订单标识、订单明细标识与申请数量、自由文本退货原因、确认上下文；禁止 `userId`、状态、金额、文件、物流或管理员字段。
- 用户提交输入：申请版本/必要的幂等标识及用户确认所需的申请资料；不能覆盖订单项、数量、金额、归属或审核标记。
- 凭证上传：由订单页认证 API 处理，不经过聊天模型。只允许 JPG/PNG/WebP 图片及 MP4 视频，每申请最多 5 份，图片每份最大 10 MiB、视频每份最大 50 MiB。
- 退货物流：审核通过的本人申请、承运商和物流单号；未知字段拒绝。
- 管理员审核/处理：只接受当前状态允许的动作和必要原因；管理员不能任意指定目标状态或退款金额。
- 列表与详情：用户只能读本人申请；管理员可按确定的状态/时间筛选并分页。具体路由、页大小和 DTO 在技术阶段确认。

金额使用订单项下单快照，不读取当前商品价。资格窗口按 `Asia/Shanghai` 自然日计算，提交时读取服务端可信时钟；第 7 天结束时刻包含在资格窗口内。

## 响应与隐私

- 用户列表/详情返回本人申请摘要、商品快照、申请数量、固定金额、状态、人工审核提示及时间；按订单页必要性提供凭证和退货物流的用户可见字段。
- 聊天工具只返回创建成功所需的最小申请摘要，不返回凭证、地址、手机号、物流单号、管理员私有备注或其他订单用户数据。
- 管理员响应可包含审核所需的用户标识和申请资料；收货人完整快照除非明确必要不得返回。
- 凭证对象键、签名 URL、图片内容和其他私有存储字段不进入模型上下文、SSE activity、trace、日志或公开聊天历史。
- 退款状态明确标识为本站登记；不得对用户声称真实支付通道已退款。

## 错误与幂等

| 状态码 | 场景                                                          |
| ------ | ------------------------------------------------------------- |
| 400    | 输入非法、未知字段、数量/格式越界或不允许的状态字段           |
| 401    | 未登录、Token 无效或账号禁用                                  |
| 403    | 非本人资源访问或非管理员调用后台动作                          |
| 404    | 订单、订单项或申请不存在/不属于当前用户                       |
| 409    | 订单已有未结束申请、数量已申请/已退款、状态竞态或非法状态转换 |
| 503    | 按现有异常映射判定的数据库暂时不可用                          |

聊天创建需支持调用重试的幂等处理，避免相同一次已确认调用创建重复记录；幂等键的生成和生命周期在技术阶段确定。状态动作重试返回当前安全状态或一致的冲突，不可重复产生副作用。

## 持久化与迁移

此资源会新增售后申请与申请商品记录，并可能新增凭证引用或审计字段；具体 Entity、外键、索引、唯一约束和 Migration 均待技术阶段确定。迁移必须保留所有现有订单和商品数据，禁止用 `migration:fresh` 替代增量迁移验证。

预计需要原子保证：

- 每笔订单最多一个活动申请。
- 同一订单项活动申请量与累计已退款量不超过购买量。
- 退款金额完全由订单快照计算。
- 各审核和物流动作只可从允许状态转换。
- 退款完成数量只被登记一次。

## 实施说明

- 设计、契约及技术阶段已确认；具体 Entity、权限和迁移按已确认的技术/实施文档落地。
- 审计保留和对象清理失败重试细节在实施记录说明。

## 验收清单

- [ ] 助手严格绑定本人订单并只创建待用户提交申请。
- [ ] 无明确二次确认不创建；重复调用幂等。
- [ ] 支持部分商品/数量，校验已申请和已退款累计量并处理并发。
- [ ] 确认收货当天起第 7 个北京时间自然日（含当日结束时刻）内的已完成订单进入常规待审核；其他情况仍可提交但进入人工审核，不自动拒绝。
- [ ] 用户订单页可独立创建并提交申请，也可查看、补充助手创建的申请；支持上传可选凭证、取消允许状态和登记退货物流。
- [ ] 管理员审核/拒绝、确认收到和验货、登记退款处理中及完成均受角色与状态限制。
- [ ] 一笔订单最多一条活动申请；终态后可重开，已退款数量不可重复申请。
- [ ] 申请金额由订单快照计算且不能修改。
- [ ] 凭证、联系方式、物流凭据、存储键和签名 URL 不进入模型、trace、日志或非必要响应。
- [ ] 所有状态和验证均明确真实退款未接入；“已退款”只代表本站登记。
