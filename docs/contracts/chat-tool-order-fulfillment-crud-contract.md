# 对话本人订单履约摘要查询契约

## 状态与依据

- 状态：按用户“直接写完文档，然后按实施文档实施”“继续下一阶段”的授权完成实现；业务测试及运行验收暂缓，静态检查见实施记录。
- 日期：2026-11-17。
- 工具：`get_my_order_fulfillment`。
- 依据：[能力清单](../modules/llm/chat-tool-capability-inventory.md)、[设计](../modules/llm/chat-tool-order-fulfillment-design.md)、[订单契约](./order-crud-contract.md)、[用户信息契约](./chat-user-information-crud-contract.md)。

首版只重新组合既有聊天订单白名单中的订单号、状态及时间，加上固定来源说明。不开放 `shipment`、承运商、单号或任何新的个人信息字段，也不改变原工具的返回白名单。

## 输入与权限

严格输入：

```json
{ "orderNo": "用户明确提供或可信查询得到的订单号" }
```

- `orderNo` 必填字符串，trim 后 1–100 字符，禁止控制字符；不转换数字、不做模糊匹配。
- 使用 `z.strictObject`，未知字段、`null`、空值、身份、内部订单 ID、URL、分页和动作参数均拒绝。
- 当前用户由服务端认证上下文单独绑定。管理员在普通聊天中也只能查询本人订单。
- 只有用户明确询问具体订单的发货/履约情况时调用。订单不明确时先用现有订单查询或询问用户，不能猜测。
- JSON 和 SSE 聊天使用同一工具；不新增 HTTP 路由或 SSE 事件。

## 输出白名单

成功返回 JSON 字符串：

```json
{
  "ok": true,
  "source": "local_order_record",
  "realtimeTrackingAvailable": false,
  "order": {
    "orderNo": "示例订单号",
    "status": "pending_receipt",
    "shippedAt": "2026-11-17T00:00:00.000Z",
    "completedAt": null
  }
}
```

- `status` 只允许现有五种订单状态。
- 时间为服务端记录的 ISO 8601 字符串或 `null`，不根据状态虚构时间。
- `source`、`realtimeTrackingAvailable` 是服务端固定字面量，不接受模型或数据库自定义值。
- 不返回订单内部 ID、买家、商品、金额、支付凭据、收件信息、承运商、完整或部分单号、物流轨迹、位置、预计送达时间、URL、对象键及内部字段。
- 不读取完整详情后再裁剪：领域查询只选择上述订单字段。

## 状态解释与错误

| 结果                 | 允许解释                                                       |
| -------------------- | -------------------------------------------------------------- |
| `pending_payment`    | 本地记录为待付款，不能承诺发货                                 |
| `pending_shipment`   | 本地记录为待发货                                               |
| `pending_receipt`    | 本地已登记发货、待用户确认收货；不能推断揽件、运输、派送或签收 |
| `completed`          | 本地订单已完成；不能当作承运商签收凭证                         |
| `closed`             | 本地订单已关闭，不能承诺发货；本工具不返回关闭原因             |
| 无本人匹配订单       | `{ "ok": false, "code": "not_found" }`                         |
| 读取故障或不合法结果 | `{ "ok": false, "code": "unavailable" }`                       |

不存在与他人订单统一 `not_found`。错误不得包含输入回显、异常、SQL 或连接信息。参数错误在工具 schema 边界拒绝，不进行领域读取；没有新增 HTTP 400 映射。

## 只读、历史与隐私

- 领域模块提供公开 reader，限定本人及精确订单号；独立 EntityManager、只读一致性事务，不调用可能处理到期状态的订单详情/动作服务。
- 不发货、不刷新物流、不自动关闭过期订单、不支付、不取消、不收货、不写库存。
- 参数校验通过后，在第一个异步读取前标记本轮来源隔离；成功、未找到和失败均使本轮用户及助手消息退出自动记忆提取和摘要来源，不登记提取任务。下一普通轮恢复。
- 工具调用和结果从后续模型历史中配对隐藏，包含非法、嵌套和孤立工具消息；最终聊天正文按原规则保存。
- trace 输入固定 `{}`，不保留订单号。输出只保留 `ok`、固定 `source`/实时可用标志及合法订单状态，或固定错误码；不保留订单号、时间和原始结果。
- activity 的 input/output 继续为 `null`；不新增卡片、展示 envelope 或查询持久化表。
