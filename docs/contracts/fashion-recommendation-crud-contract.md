## 资源一：推荐组与穿搭方案引用契约

推荐组是当前 assistant 消息中一组由服务端登记的推荐结果。它可以包含单品、整套方案和整套方案中的槽位。推荐组不是商品主数据的替代品，也不允许客户端直接创建商品事实。

### 推荐组安全快照

| 字段                 | API/内部类型     | 规则                                                     |
| -------------------- | ---------------- | -------------------------------------------------------- |
| `recommendationId`   | UUID             | 服务端生成，绑定当前用户、会话和 assistant 消息          |
| `conversationId`     | UUID             | 只能来自当前认证用户所属会话                             |
| `assistantMessageId` | UUID             | 必须是当前会话中的 assistant 消息                        |
| `intentSnapshot`     | JSONB            | 只保存风格、场合、季节、预算桶、硬条件和槽位白名单       |
| `targets`            | JSONB 数组       | 只保存 `item`、`outfit`、`slot` 引用及服务端商品投影摘要 |
| `sourceSnapshot`     | JSONB            | 保存来源标识、来源类型和观测时间；不保存供应商原始响应   |
| `createdAt`          | timestamptz      | 服务端生成                                               |
| `expiresAt`          | timestamptz/null | 由技术阶段确定；过期后不得接受新的客户端反馈引用         |

`targets` 中的商品引用至少包含 `sourceId`、来源商品引用、商品类别、已验证价格/币种（如有）、可用布尔值、公开标签、详情 URL（如有）和 `observedAt`。缺失或不可验证的字段必须为 `null` 或省略，不能由模型补齐。

### 穿搭方案结构

每个 `outfit` 目标包含：

- `outfitRef`：服务端生成的整套方案引用；
- `styleSummary`：基于当前意图和已验证标签生成的简短说明；
- `items`：一个或多个 `slot`，每个槽位引用一个已登记的商品项；
- `total`：仅在同币种且每件商品价格都可验证时提供 `amount` 和 `currency`，否则为 `null`；
- `missingSlots`：没有可验证商品的槽位列表；不能用文字建议伪造商品项。

首期槽位只使用 `tops`、`bottoms`、`dresses`、`outerwear`、`shoes`。配饰、妆容、发型和搭配动作可以出现在说明中，但没有商品来源投影时不能进入 `items`。

推荐组登记只允许由聊天服务调用内部端口。普通 HTTP 客户端和 LLM 工具不能提交完整 `targets` 或商品价格、库存、来源原始载荷。

## 查询、权限与数据行为

- 分页：画像首期不分页；若未来开放反馈历史，默认 20、最大 100。
- 排序：画像中的标签按置信度降序、标签名升序；不向客户端返回原始反馈全文。
- 过滤：当前推荐上下文只读取与当前需求相关的风格、场合、预算和版型信号。
- 公开性：全部个人 API 仅认证用户本人可用；管理员没有旁路。
- 删除方式：反馈事件和画像按用户清空操作一并删除；画像清空必须使未完成任务失效。推荐组、聊天正文和公开卡片保留。
- 关联记录：聊天删除不自动改变画像；画像清空不删除聊天正文、用户偏好或 Markdown 记忆。
- 并发：按用户串行化画像更新；任务领取、重试和清空需要 generation/租约保护。
- 失败：反馈保存成功但画像任务失败时，反馈不丢失，任务可重试；推荐读取失败只跳过画像，仍可使用当前需求和商品查询。
- 迁移：新增表和索引不得修改既有用户、商品、订单、聊天、偏好或记忆数据；迁移必须支持空库和已有用户。

## 商品来源适配 Port

推荐编排层只依赖统一的来源 Port。每个实现必须返回经过白名单校验的商品投影，不得把供应商 SDK、网页 DOM 或原始 MCP 响应泄露到推荐模块。

统一投影至少包含：

- `sourceId`、`sourceType`、来源商品引用；
- 商品类别、名称、图片和详情 URL（如来源提供）；
- 价格、币种、可用布尔值及 `observedAt`；
- 来源明确提供的公开标签；
- 本次查询的分页/限流信息和安全错误状态。

当前已确认的实现只有本地 `product-catalog` Port。首期不启用在线 API/MCP；拼多多和淘宝是后续优先调研/接入候选。平台/地区覆盖、认证方式、调用预算、结果上限、缓存/刷新周期及来源条款均为待确认事项，在确认前不能在契约中声称已接入。

## 验收清单

- [ ] 用户只能提交属于本人当前会话和推荐组的反馈。
- [ ] Body、Query、路由参数均绑定对应 Zod schema；未知字段被拒绝。
- [ ] 反馈重复提交幂等，不重复增加画像证据。
- [ ] 画像读取只返回摘要，不返回原始聊天、供应商载荷或内部实体字段。
- [ ] 当前需求、硬条件和实时商品事实优先于派生画像。
- [ ] 关闭推荐学习后不登记新学习事件；清空后在途任务不能回写。
- [ ] 结构化偏好和 Markdown 记忆不被推荐画像任务自动修改。
- [ ] 未认证、越权引用、非法原因码、未知字段和任务冲突均有约定错误响应。
- [ ] 迁移、任务重试、并发更新、清空保护和删除策略有专用验证。
- [ ] 未执行的真实模型、外部商品源和浏览器交互验收明确记录。
