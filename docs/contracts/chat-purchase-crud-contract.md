## 范围与权限

启用账号只能在本人会话准备、读取、修改、放弃和确认购买草稿。当前用户来自已有认证上下文，不接受 userId、订单金额、支付状态或库存参数。管理员没有跨用户草稿权限。

每个会话最多一份进行中草稿，每份仅有一个商品、一个 SKU、一个数量。草稿不预占库存。正式订单及其动作沿用原订单契约。

模型工具只能查询和修改未提交草稿，不能创建订单、模拟支付、取消订单或确认收货。HTTP 确认提交入口由明确用户操作触发，模型不拥有对应工具。

`request_purchase_form` 是无参数、只读的界面请求工具。仅当服务端确认当前本人会话存在 collecting/ready 草稿时，SSE 才发送无业务字段的 `purchase-form` 事件，前端据此读取最新草稿并打开现有购买弹框；该信号不持久化、不从模型正文或工具参数构造表单，也不携带收件字段。

## 逻辑字段

| 字段                     | 类型与可空性    | 规则                                                             |
| ------------------------ | --------------- | ---------------------------------------------------------------- |
| `id`                     | UUID            | 服务端生成的草稿 ID                                              |
| `conversationId`         | UUID            | 本人会话，不可迁移到其他会话                                     |
| 归属用户                 | 服务端内部 UUID | 从认证取得，不接受输入，不作为公开草稿字段                       |
| `productExternalId`      | 字符串          | 创建必填；更换商品必须替换整个草稿                               |
| `skuId`                  | UUID 或 null    | 必须属于当前商品；待选择时为 null                                |
| `quantity`               | JSON 整数       | 默认 1，范围 1–99                                                |
| `recipient`              | 对象            | name、phone、address 分别允许 null 表示未填；ready 时全部有效    |
| `status`                 | 枚举            | collecting、ready、submitted、cancelled、expired                 |
| `version`                | 正整数          | 服务端推进；修改与提交采用版本条件                               |
| `confirmation`           | 对象或 null     | 服务端生成的当前版本商品、规格、价格、金额及收货确认快照         |
| `issues`                 | 公开问题数组    | 仅返回缺失字段、需选择、商品不可用、价格变化或库存不足等业务原因 |
| `orderId`                | UUID 或 null    | submitted 时指向唯一本人订单，其他状态为 null                    |
| `createdAt`、`updatedAt` | ISO 8601        | 服务端维护；updatedAt 表示有效用户修改时间                       |
| `expiresAt`              | ISO 8601        | 最后有效用户修改时间加 24 小时                                   |

确认快照包含本版本商品 externalId、skuId、名称、颜色、尺码、公开图片 URL 或 null、quantity、unitPrice、currency、itemsAmount、shippingAmount、payableAmount、recipient。金额为两位小数字符串，币种 CNY，运费 0.00，金额由服务端计算。

`confirmation` 的版本必须与当前草稿 `version` 一致。价格、规格等确认条件变化会使旧版本不可提交；库存可售状态仅为查询快照，下单仍以事务检查为准。缺失字段和阻止原因的具体 TypeScript 判别联合在技术阶段定义，不直接暴露内部异常。

## 输入校验

| 输入                                 | 规则                                                       |
| ------------------------------------ | ---------------------------------------------------------- |
| `conversationId`、`draftId`、`skuId` | UUID；客户端不能通过草稿 ID 绕过会话归属                   |
| `productExternalId`                  | trim 后 1–160 字符，拒绝控制字符                           |
| `expectedVersion`                    | 正整数，不接受数字字符串；仅首次发起无草稿时允许 null      |
| `quantity`                           | JSON 整数 1–99，不能为 null                                |
| `recipient.name`                     | trim 后 1–100 字符，拒绝控制字符；PATCH 显式 null 表示清空 |
| `recipient.phone`                    | trim 后可选前导 + 及 6–20 位数字；PATCH 显式 null 表示清空 |
| `recipient.address`                  | trim 后 1–500 字符，拒绝控制字符；PATCH 显式 null 表示清空 |
| PATCH 的 `skuId`                     | UUID 或 null；null 表示清除选择                            |
| PATCH 对象                           | 至少一个可修改字段；省略字段保持原值，recipient 按字段合并 |

所有 Body、Query、Param 及嵌套对象使用所属模块 Zod schema，默认严格拒绝未知字段，绑定现有 Nest `StandardSchemaValidationPipe`，输入与输出类型从 schema 派生。Swagger DTO 只用于文档。

草稿 PATCH 不接受商品、状态、金额、币种、orderId、expiresAt。模型抽取也必须经过同一字段约束及归属、版本与 SKU 业务校验，工具不能比 HTTP 入口获得更多写权限。

## API 提案

全局前缀 `/api`，下表均要求启用账号 Bearer JWT。

| 操作         | 方法与路由                                                                     | 输入                                                 | 成功响应                                                         |
| ------------ | ------------------------------------------------------------------------------ | ---------------------------------------------------- | ---------------------------------------------------------------- |
| 读取当前购买 | `GET /api/chat/conversations/:conversationId/purchase-draft`                   | 会话 Param                                           | 200，`{ draft, order }`；没有草稿时两者为 null                   |
| 发起或替换   | `POST /api/chat/conversations/:conversationId/purchase-draft/start`            | `{ productExternalId, expectedVersion }`             | 200，`{ draft, order }`                                          |
| 修改草稿     | `PATCH /api/chat/conversations/:conversationId/purchase-draft/:draftId`        | `{ expectedVersion, skuId?, quantity?, recipient? }` | 200，最新草稿投影                                                |
| 放弃草稿     | `POST /api/chat/conversations/:conversationId/purchase-draft/:draftId/discard` | `{ expectedVersion }`                                | 200，终止草稿投影                                                |
| 确认下单     | `POST /api/chat/conversations/:conversationId/purchase-draft/:draftId/confirm` | `{ expectedVersion }`                                | 首次 201，成功重试 200，`{ draft, order }`，order 为本人订单详情 |

本轮读取不按历史消息页推断草稿，独立返回当前或最近一次购买状态，避免未加载历史页时丢失进行中操作。已关联订单按本人订单详情投影返回；订单列表仍不带完整收货信息。

start 的行为：

- 没有进行中草稿时，expectedVersion 为 null，新建草稿。
- 相同商品已有进行中草稿时恢复原草稿，版本条件不匹配返回 409；不重置收货信息、数量或有效期。
- 不同商品已有进行中草稿时，前端先询问是否放弃；用户明确接受后携带当前版本发起 start。服务端原子终止旧草稿并创建新草稿。
- 多标签页同时首次发起时只能出现一份进行中草稿；冲突请求重新读取，不得悄悄替换另一请求创建的草稿。
- submitted、cancelled、expired 不阻止新的主动购买；新草稿使用新 ID，不复制旧收货信息。

放弃和替换不能终止 submitted 订单。普通聊天中的“取消本次购买”只能执行未提交草稿放弃，发现已经提交时返回订单状态及显式操作入口。

## 复用接口

| 操作         | 原接口                                  | 本轮行为                                                   |
| ------------ | --------------------------------------- | ---------------------------------------------------------- |
| 查询 SKU     | `GET /api/product-catalog/skus`         | 沿用分页与真实 SKU 投影，处理完整有效规格集合              |
| 本人订单列表 | `GET /api/orders`                       | 分页、状态及订单号筛选，`{ items, total, page, pageSize }` |
| 本人订单详情 | `GET /api/orders/:id`                   | 明细、收货、物流与模拟支付标识                             |
| 模拟支付     | `POST /api/orders/:id/simulate-payment` | Body 严格为 `{}`，仅本人                                   |
| 取消订单     | `POST /api/orders/:id/cancel`           | Body 严格为 `{}`，仅未支付本人订单                         |
| 确认收货     | `POST /api/orders/:id/confirm-receipt`  | Body 严格为 `{}`，仅已发货本人订单                         |

直接 `POST /api/orders` 的原请求保持兼容，不将新增确认版本字段塞入旧 strict schema。聊天确认由独立入口调用订单公开能力；确认条件、幂等和原子事务的具体内部接口在技术阶段确定。

## 状态、版本与幂等

- 所有有效修改使用当前版本；同值重试可以返回当前投影，但不能续期或覆盖并发新版本。
- 超过草稿期限即不可修改或首次提交，读取时返回 expired 状态；任务延迟不能延长有效期。
- ready 后修改任一规格、数量或收货字段，旧确认版本失效；重新计算后才能展示新确认卡。
- 价格或规格变化使已展示确认失效，生成新确认快照后必须重新点击确认，不在一次请求内自动接受新价格。
- 正式创建事务必须依据已展示价格核对锁定 SKU 并预占库存，不允许先建单再用事后比较代替。
- 草稿提交状态、唯一订单关联与订单创建必须全成或全败；模型生成失败不能造成重复订单。
- 服务端保存已成功确认的版本与订单关联。相同草稿、相同成功确认版本的重试先返回关联订单，不受之后草稿期限、商品变化或订单状态影响。
- 对 submitted 草稿使用其他版本或企图修改内容返回 409，不再创建订单。
- 失败或未知结果不分配新的下单身份；允许读取确认结果或重试同一次请求。明确修改并重新确认后才形成新的确认内容。
- 支付、取消、收货沿用订单原幂等和状态规则，不重复预占、释放或扣减。

## 错误行为

| 状态码 | 场景                                                                                              |
| ------ | ------------------------------------------------------------------------------------------------- |
| 400    | 非法 UUID、未知字段、空 PATCH、数量或字段边界非法                                                 |
| 401    | 未登录、认证失败或账号禁用                                                                        |
| 404    | 会话、草稿或订单不存在/越权；发起时商品不存在或不可用                                             |
| 409    | 版本冲突、已有其他活跃草稿、草稿终止、信息未完整、到期、价格/规格变化、库存不足或提交时商品不可用 |
| 503    | 现有异常映射判定的数据库暂时不可用                                                                |
| 500    | 非预期内部异常，使用既有安全错误响应                                                              |

409 不创建订单；前端保留用户已填写信息并重新读取当前投影。重新读取后商品事实已变化时返回对应 issues，不让缺货或下架导致用户收货草稿丢失。恢复查询无法核实商品状态时显示加载失败并禁止确认，不把暂时查询失败当成商品已下架。

沿用 Nest 标准异常，不另建通用错误封装。业务原因仅包含可公开信息，不泄露精确库存、他人订单、收货日志、SQL 或供应商对象。

## 聊天与展示契约增量

- 商品“购买”操作以结构化商品标识启动购买，不凭纯文本标题推断目标商品。
- 当前聊天请求继续只接受 user/assistant 消息，客户端不得提交 system 提示或授权信息。
- 购买草稿作为服务端业务状态注入当前会话运行，历史摘要不能覆盖当前草稿。
- 模型工具仅查询真实规格、读取本人草稿、更新已明确字段及放弃草稿；调用与结果必须通过版本及归属校验。
- 助手需要用户在购买草稿表单补充信息时调用 `request_purchase_form`；工具只请求打开本人当前可编辑草稿，不创建或修改草稿。无有效草稿、已提交或已终止时不发送打开事件。
- `purchase-form` 是仅限当前 SSE 运行的一次性 UI 事件，无 payload，不写入 `PublicDisplayEnvelope`、聊天历史或长期记忆；前端收到后重新读取服务端草稿，校验当前会话后打开弹框。
- 表单打开后允许用户在模型流式生成期间编辑本地输入；保存、放弃、地址选择和确认下单仍等待本轮生成结束，避免并发修改草稿。
- 确认卡和订单卡使用服务端白名单投影，禁止从模型 Markdown 或任意工具 JSON 生成可执行按钮。
- JSON 聊天结果及 assistant 历史消息增加可空 `purchase` 引用：`{ draftId, version, orderId }`，两种 ID 均为 UUID，version 为正整数，orderId 未提交时为 null。旧消息及无购买信息的消息返回 null，不从旧正文推断。
- SSE 新增 `purchase` 事件，数据为 `{ purchase: { draftId, version, orderId } }`，只发送当前账号及当前会话经持久化核实的引用，不携带收货字段。客户端收到后读取购买状态或本人订单，不直接把引用当作当前可提交确认卡。
- 本轮成功时，purchase 引用与 assistant 消息公开展示同事务绑定，在 done 前发送；done 仍是成功流最后一个业务事件。失败或取消时不把未保存展示消息当作正式历史，已成功更新的草稿可通过独立查询恢复。
- 引用只存关联信息，不把收货快照复制到通用 publicDisplay。技术文档须核实投影容量、版本兼容与序列化边界，不能改变现有 delta、done、error 的顺序及保存语义。
- 未收到 done 不代表购买操作回滚；通过购买状态接口核实。正式订单创建不依赖模型成功生成回复。
- 历史卡片不代表最新价格或订单状态，恢复后核对最新版本再开放按钮。
- 新购买能力覆盖旧契约“购买仅虚拟展示”和 Confirmation 非目标的相关范围；原系统指令保护及内部 trace 公开限制继续适用。

## 持久化、删除与隐私

| 项目       | 约定                                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------------------- |
| 持久化     | 草稿、字段、版本、有效期、确认快照及提交关联均为服务端权威状态                                                            |
| 唯一性     | 每会话最多一份进行中草稿；每草稿最多一个正式订单                                                                          |
| 归属       | 草稿绑定用户和会话，不能转让；访问先校验会话归属                                                                          |
| 会话删除   | 删除草稿与会话展示引用，不删除正式订单及其幂等记录                                                                        |
| 删除竞争   | 会话删除与提交有唯一顺序；先删除禁止创建，先创建订单保留                                                                  |
| 过期       | 业务终止，不宣称自动擦除用户已发送聊天或订单数据                                                                          |
| 记忆       | 不写入长期偏好或 Markdown，不默认复用旧订单地址                                                                           |
| 展示权限   | 完整收货信息仅本人购买视图、既有本人/管理员订单详情可见；现有聊天文本访问权限不变                                         |
| 工具与日志 | 专属白名单保护收货信息，结构化工具 trace、activity 和普通日志不新增收货字段明文副本；用户原始聊天文本仍按既有记录规则保存 |
| 迁移       | 增量 Migration、约束与并发验证；保留旧数据，禁止 migration:fresh 代替验证                                                 |

实际表结构、索引、外键、并发锁、事务公开接口及迁移回滚影响见已确认的[技术文档](../chat-purchase/chat-purchase-technical.md)，执行结果和剩余验收见已确认的[实施文档](../chat-purchase/chat-purchase-implementation.md)。

## 验收清单

- [ ] Schema 与 HTTP 覆盖 UUID、边界、未知字段、PATCH 省略/null、版本及 400 行为。
- [ ] 本人隔离、管理员无跨用户草稿权、禁用账号和越权 404 正确。
- [ ] 完整真实 SKU 集合、单一可售规格、歧义选择和下架场景正确。
- [ ] 恢复草稿、同值不续期、24 小时边界、放弃和替换正确。
- [ ] 旧确认卡失效，原子检查变价，不生成用户未确认的新价格订单。
- [ ] 缺货、事务失败不产生部分订单、草稿关联或预占。
- [ ] 重复提交、多标签页、并发修改/提交、超时重试至多关联一单。
- [ ] 删除会话与提交竞争有测试，已成功订单可从“我的订单”访问。
- [ ] 模型没有订单写工具，聊天指令不能越过显式按钮动作入口。
- [ ] SSE/历史卡片不能伪造成功状态或覆盖其他会话。
- [ ] 本人订单页状态、动作、加载/失败/空态与响应式交互通过验证。
- [ ] 收货信息不进入长期记忆、新购买默认地址或工具公开调试字段。
- [ ] 模型请求收集购买信息时，仅本人活跃草稿能触发前端表单；SSE、trace、历史和记忆不包含收件字段或可伪造表单数据。
- [ ] 迁移及旧接口兼容验证完成，并明确模拟支付性质。
