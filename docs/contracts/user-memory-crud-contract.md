# 用户长期记忆 CRUD 契约

## 状态与上下文

- 状态：已确认，实施中
- 资源名称：用户长期记忆文档
- 业务目的：保留现有结构化服装偏好，并新增每位用户一份可直接编辑的 Markdown 长期记忆文档。
- 需求范围：Markdown 文档以服装、穿搭和购物为主，其他有助于个性化协作的长期信息为辅。
- 需求来源：用户确认保留现有偏好功能；新增用户级 Markdown 文档；服务端作为权威副本；聊天中静默提取并更新文档。
- 涉及模块：`apps/api/src/user-memory`、`llm`、`chat-records`、`auth` 及前端记忆页面。
- 当前基础：NestJS、MikroORM、PostgreSQL、JWT 鉴权、Zod 请求校验和现有聊天记录模块。
- 最后更新：2026-11-03

本契约、设计文档、技术文档和实施文档均已获用户确认。

## 资源边界

### 保留的用户偏好

- 当前结构化服装偏好功能继续保留，原有数据和行为不迁入 Markdown 文档。
- 本次不改变现有偏好字段、接口、设置和管理行为；如需改名或调整 UI，另在技术设计中列出并确认兼容性。
- 现有记忆开关同时控制结构化用户偏好和 Markdown 文档的提取与注入；关闭开关不删除已有数据。

### 新增的 Markdown 文档

- 每位登录用户至多拥有一份 Markdown 长期记忆文档。
- 文档是自由格式 Markdown，不受服装偏好枚举字段限制。
- 服务端持久化副本为权威数据；客户端通过登录态 API 读写，不直接决定服务端文件路径。
- 文档内容以服装和购物相关长期信息为主，其他有助于个性化协作的信息为辅。
- 聊天静默提取可更新该文档；提取失败不得阻断聊天。
- 文档更新、清空、用户手动编辑和异步提取间的并发语义待技术设计确认。

## 范围

### 包含

- 登录用户读取和编辑自己的完整 Markdown 文档。
- 登录用户清空或删除自己的 Markdown 文档。
- 聊天后的异步静默提取，并把通过规则校验的长期信息写入文档。
- 后续聊天按相关性和长度限制读取 Markdown 记忆。
- 按用户隔离访问；删除账号时清理该账号文档及关联任务。

### 不包含

- 游客长期记忆。
- 修改或迁移现有结构化偏好数据。
- 管理员或客服读取用户记忆原文。
- 图片、语音、文件和商品点击行为的提取。
- 记忆跨账号共享或历史版本恢复。
- 密码、Token、API Key 等认证凭据。
- 健康、身份、财务等敏感个人信息不得写入文档。

## 文档资源契约

| 字段        | API 类型草案    | 持久化类型草案          | 约束与说明                              |
| ----------- | --------------- | ----------------------- | --------------------------------------- |
| `content`   | `string`        | 七牛 Kodo Markdown 对象 | 用户可编辑的完整文档；UTF-8 最大 32 KiB |
| `updatedAt` | ISO 8601 字符串 | 服务端时间              | 每次成功更新时生成                      |
| `revision`  | 非负整数        | PostgreSQL 状态行版本   | 用于并发编辑检测；内容变化时递增        |
| `userId`    | 不由客户端提交  | 当前用户关联            | 只由认证上下文确定，用户间严格隔离      |

服务端文件路径、对象键、内部存储 URI、完整磁盘路径和其他用户 ID 不得返回给客户端。

## API 契约

路由、响应、文档大小上限和版本控制方式已由技术文档确定。

| 操作                   | 方法与路由草案                  | 认证/授权        | 成功响应草案                                     |
| ---------------------- | ------------------------------- | ---------------- | ------------------------------------------------ |
| 读取我的 Markdown 文档 | `GET /api/memories/document`    | 登录用户，仅本人 | `content`、`updatedAt`，可选 `revision`          |
| 替换我的 Markdown 文档 | `PUT /api/memories/document`    | 登录用户，仅本人 | 保存后的 `content`、`updatedAt`，可选 `revision` |
| 清空我的 Markdown 文档 | `DELETE /api/memories/document` | 登录用户，仅本人 | 空文档状态或统一空响应                           |
| 修改记忆设置           | 沿用现有记忆设置 API            | 登录用户，仅本人 | 设置响应                                         |

写入请求建议使用严格对象，至少包含 `content`；未知字段返回 `400`。是否使用 `If-Match`、revision 或其他乐观锁避免覆盖并发编辑，待技术设计确认。

现有结构化用户偏好 API 不属于本次契约变更范围，继续按其已实现行为运行。

## 权限与归属

- 普通用户只能读取、更新或清空自己的 Markdown 文档。
- 当前用户 ID 只能取自认证上下文，不接受客户端指定或覆盖。
- 文档不存在、资源不属于当前用户和越权访问统一为 `404`，不得泄露其他用户数据是否存在。
- 游客不能创建或访问长期记忆。
- 管理员和客服没有普通业务接口的记忆原文读取权限。
- 聊天模块通过记忆模块导出的受限能力读取内容，不得直接访问存储实现。
- 删除账号时必须清理文档以及其关联的待处理记忆提取任务。

## 业务行为

### 静默提取与更新

- 仅在已确认的文本聊天流程中提取；提取在当前回复完成后异步执行。
- 服装、穿搭和购物长期信息优先；其他个人背景仅在能帮助未来个性化协作时作为补充。
- 只保存用户明确表达且具有长期价值的内容；模型推测、低置信度和临时意图不保存。
- 提取不得把整段聊天原文复制到文档；只生成经过校验的最小必要 Markdown 变更。
- 提取应尊重用户手动编辑和明确删除；通过最新文档上的精确 append/replace/delete 补丁合并。
- 同一聊天任务重复执行不得重复追加相同内容。
- 用户清空文档后，未完成的旧任务不得将清空前内容重新写回。

### 查询与使用

- 只向模型提供与当前问题相关且受数量或 Token 上限限制的记忆内容。
- 优先级为：当前消息明确要求 > 用户长期记忆 > 系统默认规则。
- 不向客户端返回内部提取候选、模型推理、供应商错误或其他用户内容。

### 设置和删除

- 关闭设置不删除现有文档。
- 清空 Markdown 文档不影响现有结构化用户偏好、聊天记录或其他用户数据。
- 删除来源聊天不自动删除已经写入 Markdown 文档的内容；文档不向客户端展示来源内部字段。
- 删除账号时清理文档及相关任务。

## 错误契约草案

| 场景                       | HTTP 状态草案        | 规则                                     |
| -------------------------- | -------------------- | ---------------------------------------- |
| 未登录访问                 | `401`                | 沿用现有 JWT Guard                       |
| Body、Param 或文档长度非法 | `400`                | 由 Zod schema 和 Nest 标准校验 Pipe 映射 |
| 未知字段                   | `400`                | 严格对象拒绝，不静默丢弃                 |
| 文档并发版本冲突           | `409`                | 不得静默覆盖用户刚提交的内容             |
| 文档不存在或越权           | `404`                | 不泄露资源是否存在性                     |
| 提取模型失败               | 不影响聊天 HTTP 响应 | 记录脱敏失败分类并按策略重试             |
| 服务端持久化失败           | `5xx` 或异步任务失败 | 不返回路径、SQL、连接信息或凭据          |

## 持久化、安全与兼容性

- 用户已确认服务端作为 Markdown 文档权威副本；具体介质、目录/对象键、持久卷、备份和多实例一致性由技术文档选择。
- 不能把用户文档写入仓库源码目录或临时部署目录。
- 文档数据必须按用户隔离，并执行服务端输入长度、格式和安全策略校验。
- Markdown 展示必须按纯文本或安全 Markdown 渲染，不允许不可信 HTML 执行。
- 新存储结构、数据库字段、索引、账号删除清理和迁移必须在技术文档确认后实施。
- 现有结构化偏好数据保持原样；若技术实现要迁移任何偏好数据，必须先更新契约并重新确认。
- 不能修改 `chat_messages` 或 `chat_trace_events` 的公开语义来代替长期记忆。

## 已确认实现项

- 文档更新使用 revision 乐观锁；冲突返回 `409`。
- 异步提取只应用精确 Markdown 补丁，不覆盖用户最新文档。
- 清空移除当前对象指针并递增 generation，旧对象延迟清理。
- 文档最大 32 KiB，聊天记忆上下文总预算 512 token。
- 正文使用七牛 Kodo 私有 Bucket，PostgreSQL 保存元数据和对象指针。

- [ ] 未知字段、超长内容和非法版本请求返回约定错误。
- [ ] Markdown 文档以服装和购物为主，其他有帮助的长期背景为辅。
- [ ] 提取失败不会阻断聊天；重复任务不会重复写入。
- [ ] 用户清空文档后旧任务不能复活旧内容。
- [ ] 并发编辑不会静默覆盖用户内容。
- [ ] 清空文档不影响结构化偏好和聊天记录。
