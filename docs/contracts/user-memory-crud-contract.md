# 用户长期记忆 CRUD 契约

## 状态与上下文

- 状态：已确认，进入技术设计
- 资源名称：用户长期记忆
- 业务目的：保存登录用户明确表达的服装相关长期偏好，并在后续导购聊天中提供受限的个性化上下文。
- 需求来源：用户完成需求访谈并确认跨会话、静默提取、用户可控和单用户隔离规则。
- 涉及模块：规划中的 `apps/api/src/user-memory`、`llm`、`chat-records`、`auth`。
- 现有基础：NestJS、MikroORM、PostgreSQL、JWT 鉴权、Zod 请求校验和现有聊天记录模块。
- 最后更新：2026-11-03

本契约只记录产品和资源边界。设计文档和本契约已获用户确认；Entity、DTO、Controller、Service、Migration、任务处理器和前端页面仍须等待技术文档确认与实施审批。

## 范围

### 包含

- 登录用户查看自己的长期记忆。
- 登录用户手动新增、修改、删除单条记忆。
- 登录用户删除全部记忆。
- 登录用户开启或关闭记忆功能。
- 聊天成功后的异步静默提取和结构化更新。
- 记忆来源会话关联、更新时间和来源删除状态。
- 跨会话读取相关记忆并按上下文长度限制注入导购聊天。

### 不包含

- 游客长期记忆。
- 管理员或客服读取用户记忆原文。
- 从图片、语音、文件或点击行为提取记忆。
- 健康、身份、财务和无关敏感画像。
- 向量检索、Embedding 和自由文本画像。
- 记忆跨账号共享、导出或恢复历史版本。
- 商品排序、广告、营销和其他非导购聊天用途。

## 资源与字段契约

## API 契约草案

路由命名和响应包装是产品层草案，最终以技术文档为准。

| 操作         | 方法与路由草案                 | 认证/授权          | 成功响应草案                 |
| ------------ | ------------------------------ | ------------------ | ---------------------------- |
| 查询我的记忆 | `GET /api/memories`            | 登录用户           | 记忆列表和设置状态           |
| 手动新增     | `POST /api/memories`           | 登录用户           | 创建后的记忆对象             |
| 修改单条     | `PATCH /api/memories/:id`      | 登录用户且仅限本人 | 更新后的记忆对象             |
| 删除单条     | `DELETE /api/memories/:id`     | 登录用户且仅限本人 | `204` 或统一空响应，待确认   |
| 删除全部     | `DELETE /api/memories`         | 登录用户           | 删除统计或统一空响应，待确认 |
| 修改设置     | `PATCH /api/memories/settings` | 登录用户           | 更新后的设置                 |

### 请求校验原则

- 所有 Body、Query 和路由参数使用所属模块 DTO 目录中的 Zod schema。
- 对象请求默认使用严格对象，未知字段返回 `400`。
- `userId`、来源会话归属、审计字段和时间字段不得由客户端提交或覆盖。
- `value` 必须按 `category` 使用对应结构化 schema；不接受把任意 JSON 当作自由文本画像。
- 手动新增和修改不得写入被禁止的敏感类别。
- 分页、排序和列表过滤方式待技术设计确认；若提供分页，沿用现有分页默认值和上限约定。

## 权限与归属

- 普通用户只能读取、创建、修改和删除自己的记忆。
- 资源不存在、资源不属于当前用户和用户无权访问来源会话时，统一返回 `404`，不泄露资源是否存在。
- 游客接口不得创建、读取或修改长期记忆。
- 管理员和客服没有普通业务接口的记忆原文读取权限。
- 聊天模块读取记忆时必须通过记忆模块公开的受限能力，不能直接访问 Repository 或 Entity。
- 删除账号时，账号删除流程必须同步清理全部长期记忆及其必要的内部任务数据。

## 业务行为

### 提取与更新

- 仅对文本聊天执行提取。
- 当前聊天回复完成后异步提交提取任务。
- 提取候选必须经过结构化校验、敏感过滤、长期语义判断、冲突处理和幂等检查。
- 提取任务失败、超时或达到重试上限时，不影响当前聊天成功响应。
- 同一来源消息重复处理不得创建重复记忆。
- 明确的长期新值覆盖当前有效值；临时表达只影响当前聊天。

### 查询与注入

- 默认只在服装导购聊天中使用。
- 当前消息明确要求优先于长期记忆，长期记忆优先于系统默认规则。
- 只读取与当前问题相关且受数量或 Token 上限限制的记忆。
- 不向前端返回内部提取候选、模型推理、供应商错误或完整原始上下文。

### 删除与生命周期

- 删除单条记忆后，不再参与后续推荐和注入。
- 删除全部记忆不影响聊天记录本身，并取消未完成提取任务，避免删除后旧任务重新生成记忆。
- 删除来源聊天不自动删除记忆；来源状态标记为已删除或不可用。
- 关闭设置不删除已有记忆，重新开启后可继续使用已有记忆。
- 记忆默认不自动过期。

## 错误契约草案

| 场景                      | HTTP 状态草案              | 规则                                     |
| ------------------------- | -------------------------- | ---------------------------------------- |
| 未登录访问                | `401`                      | 沿用现有 JWT Guard                       |
| Body、Query 或 Param 非法 | `400`                      | 由 Zod schema 与 Nest 标准校验 Pipe 映射 |
| 未知字段                  | `400`                      | 严格对象拒绝，不静默丢弃                 |
| 记忆不存在或越权          | `404`                      | 不泄露资源存在性                         |
| 类别和值冲突              | `400` 或 `409` 待确认      | 按最终业务冲突规则处理                   |
| 删除全部确认不足          | `400` 待确认               | 若设计为需要显式确认，则由接口契约约束   |
| 记忆提取模型失败          | 不影响聊天 HTTP 响应       | 记录内部失败状态并按策略重试             |
| 数据库写入失败            | `5xx` 或异步任务失败待确认 | 不返回内部 SQL、连接信息或凭据           |

## 删除、迁移与兼容性

- 本资源尚未实现，不得直接创建 Entity、Migration、Controller 或前端页面。
- 技术设计确认后，需要明确记忆表、设置字段、任务存储、索引、外键和账号删除顺序。
- 不能修改现有 `chat_messages` 或 `chat_trace_events` 的公开语义来代替长期记忆。
- 删除来源聊天时，需要在不复制原文的前提下更新来源状态，具体实现方式待技术设计确认。
- 若后续调整类别或 `value` 结构，必须补充迁移兼容性和历史数据转换方案。
