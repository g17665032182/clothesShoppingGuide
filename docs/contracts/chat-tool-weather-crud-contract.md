# 聊天天气查询工具契约

## 状态与范围

- 状态：已确认按次授权的 IP 城市建议流程
- 工具名：`get_weather_forecast`
- 用途：在普通聊天中查询用户明确指定城市的近 3 天天气预报，作为穿搭参考。
- 入口：现有认证聊天 JSON/SSE，以及认证后的 `POST /api/llm/weather/location`。
- 本契约不代表第三方天气数据具有官方气象预警效力。

## 输入

| 字段   | 类型   | 规则                                                                                                       |
| ------ | ------ | ---------------------------------------------------------------------------------------------------------- |
| `city` | string | 必填；去除首尾空白后非空，最大长度 100；不得传入 API Key、用户 ID、任意 URL 或未由用户明确给出的精确坐标。 |

具体 Zod schema、未知字段拒绝策略及 MCP 输入映射由技术文档按仓库现有约定明确。

## 成功结果

只返回经服务端验证和字段白名单映射的 JSON：

| 字段                              | 含义                                                                    |
| --------------------------------- | ----------------------------------------------------------------------- |
| `ok`                              | 固定为 `true`。                                                         |
| `location`                        | 天气服务确认的地点名称。                                                |
| `days`                            | 1 至 3 条逐日预报。                                                     |
| `date`                            | 预报日期。                                                              |
| `dayCondition` / `nightCondition` | 日间和夜间天气描述。                                                    |
| `highC` / `lowC`                  | 当日最高和最低温度，单位摄氏度。                                        |
| `precipitationMm`                 | 降水量，单位毫米；来源缺失时为 `null`。                                 |
| `windDirection`                   | 风向；来源缺失时为 `null`。                                             |
| `windSpeedKmh`                    | 风速，单位公里/小时；来源缺失或单位未确认时不得猜测。                   |
| `windScale`                       | 风级；来源缺失时为 `null`。                                             |
| `humidityPercent`                 | 相对湿度百分比；来源缺失时为 `null`。                                   |
| `updatedAt`                       | 上游数据更新时间；缺失或格式不合法时为 `null`，不得伪装成本次查询时间。 |

若服务端无法确认 MCP 响应字段及单位，应返回失败或将可选字段设为 `null`，不得猜测单位。此预报不是当前实况。

## 失败结果

- 配置缺失、服务连接失败、超时、城市无匹配、上游限额、无效响应统一返回不含敏感信息的失败结构，例如 `{ "ok": false, "code": "unavailable" }` 或经确认的区分码。
- 不返回 API Key、请求 URL 查询参数、堆栈、服务端环境、MCP 原始异常或原始响应。
- 工具失败不应被表示为天气查询成功；模型不得补造当前天气事实。

## 权限、隐私与持久化

- 天气查询只在认证聊天中发生，城市必须来自当前用户明确请求或明确确认的地点。
- 城市不明确时仍先询问。用户可以手动输入，也可以在天气弹窗明确同意将本次请求的公网 IPv4 发送给高德以获取候选城市。只有确认或修改城市并提交后才发起天气查询。
- 定位接口只接受 `{ "consent": true }`，不接收客户端指定的 IP。只使用连接地址，或由已配置的受信反向代理提供的客户端地址。
- 定位返回 `200` 和 `{ "city": "上海市" }` 或 `{ "city": null }`。地点未知、没有可用公网 IPv4、未配置天气服务或高德调用失败时返回 `null`，界面保留手动输入。未认证、无效请求和限流使用现有 HTTP 错误处理。
- 定位响应禁止缓存。定位过程不向模型、应用请求日志、聊天 trace、数据库或用户记忆写入原始 IP，不使用浏览器定位、账号资料或长期记忆推断地点。
- 不新增数据库资源或持久化字段；城市、天气结果、供应商响应不写入用户记忆或摘要来源。
- Trace/activity 只按批准的白名单记录必要状态，不记录凭据、原始 MCP 响应或详细外部错误。
- 最终聊天文本遵守现有聊天消息持久化约定。

## 调用和兼容性

- 仅当独立远程工具开关启用、天气 MCP 配置完整且服务可用时注册工具。
- 每轮最多成功或失败尝试一次。
- 不兼容天气 MCP 工具名、schema 或返回格式变化时按失败处理，不向模型透传未知字段。
- 不新增数据库迁移或公开 API 版本变化。
