# 聊天试穿工具契约

## 状态与依据

- 状态：用户已于 2026-11-12 确认新调用链契约；旧版入口卡片契约已作废。
- 资源：由商品卡试穿动作触发的生成图片及其安全聊天响应。
- 所属模块：`apps/web` 发起用户操作；`chat-records` 编排聊天工具；`product-catalog` 提供当前商品事实；`virtual-try-on` 提供照片、生成、结果与访问控制能力。具体依赖边界见已确认的技术文档。
- 最后更新：2026-11-12。
- 关联文档：[聊天试穿工具设计](../chat-try-on/chat-try-on-design.md)、[AI 虚拟试穿 CRUD 契约](./virtual-try-on-crud-contract.md)。

用户提出的新目标链路：点击已开启试穿的商品卡片，调用试穿工具并提供本人照片；工具查询当前商品信息，调用生图大模型，把生成图片交还聊天模型，再由聊天模型响应给前端渲染。

## 调用边界

- 用户在商品卡发起试穿后，前端先让其选择本人照片并明确同意本次图像处理，再提交结构化聊天动作；原始照片不进入聊天消息。
- 商品标识与照片引用由前端用户操作提供，但服务端必须重新校验商品资格和照片归属。
- 当前用户身份从认证上下文获取；工具参数不得接收 `userId`、任意商品事实、供应商配置或对象存储内部字段。
- 工具输入为商品 `externalId` 和本人照片资产 `photoId`；由服务端读取受控照片内容。聊天请求不得携带原始图像字节或 Base64。
- 调用任何外部生图模型前必须校验明确同意及照片资产当前状态。
- 生图结果作为受控图像内容交给聊天模型；聊天回复返回前端时，图片通过本人任务权限的结果引用提供。不得把公开长期 URL、签名 URL 或存储对象键写入普通 trace、工具 activity 或聊天消息。
- 最终前端渲染采用固定白名单响应结构，不从 Markdown 或未验证工具输出推断图片地址。

## 现有能力与兼容约束

- 商品当前资格使用公开 `ProductCatalogTryOnPort` 复核。
- 试穿照片上传、用户隔离、任务、额度和结果由现有 `virtual-try-on` 契约约束；具体模块公开端口、聊天动作 envelope、任务等待和多模态消息传递方式由技术文档定义。
- 当前虚拟试穿契约明确：生产真实人像供应商处理需先完成留存、处理地区、禁止训练及删除保障审查；在此之前真实用户照片流程保持关闭。
- 复用 `virtual-try-on` 已有照片、任务、额度、图像供应商和私有结果能力。
- 真实人像供应商审查完成前，生产环境保持真实照片处理关闭。
- 所有错误向模型和前端只返回稳定业务状态，不包含供应商原文或内部凭据。

## 主要失败行为

| 场景                                   | 行为                                                 |
| -------------------------------------- | ---------------------------------------------------- |
| 商品不存在、已停用或当前不具备资格     | 不调用生图模型，返回稳定不可用结果                   |
| 照片不属于当前用户、已删除或状态不允许 | 不调用生图模型，返回安全拒绝                         |
| 缺少适用的明确同意                     | 不向外部模型传输图像                                 |
| 供应商超时或失败                       | 不泄露原始异常；按任务状态和稳定错误码返回可恢复结果 |
| 结果不可访问或图片校验失败             | 不把不安全图片引用传给聊天模型或前端                 |

## 审批说明

用户于 2026-11-12 确认本文调用链和安全边界：前端先选择照片并同意；服务端工具接收商品 `externalId` 与照片 `photoId`，验证当前商品、照片归属和同意，再复用试穿能力生成图片；生成图片交给聊天模型，前端从受控结果引用渲染。原照片不进入聊天消息或 trace，生产真实人像处理在供应商审查通过前保持关闭。技术细节见已确认的[技术文档](../chat-try-on/chat-try-on-technical.md)，实施计划已确认并进入实现阶段。
