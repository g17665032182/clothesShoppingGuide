# 聊天地址管理界面请求 CRUD 契约

## 状态与依据

- 状态：设计、契约、技术方案与代码实施已完成；自动化测试和登录态浏览器验收暂缓。
- 最后更新：2026-11-16。
- 资源：当前聊天运行中的地址管理页面导航请求；不创建持久化资源。
- 所属模块：`chat-records` 聊天工具编排；地址 CRUD 仍归 `user-addresses` 模块。
- 设计：[对话地址管理界面请求设计](../llm/chat-tool-address-form-design.md)。
- 领域依据：[收货地址 CRUD 契约](./user-address-crud-contract.md)。

本文只定义受限的 UI 导航请求，不扩展地址资源 CRUD，也不授予模型任何地址读写或用户确认权限。

## 权限与操作范围

`request_address_form` 仅允许请求当前登录用户打开本人现有地址管理页面。服务端从认证聊天上下文绑定用户和会话，不接受模型提供：

- `userId`
- `conversationId`
- `addressId`
- `requestKey`
- 目标 URL、路由名称、API 路径或脚本
- 姓名、手机号、完整地址、标签或默认标志

工具不能读取地址详情、选择地址、创建地址、修改地址、删除地址或设置默认地址。所有地址写入继续由用户在账号页面明确操作，并经过既有认证地址 API。

## 工具输入

### 推荐首版

工具输入为严格空对象：

```json
{}
```

空对象表示请求打开固定地址管理页，不表示新增、编辑或保存任何地址。

### 不支持的模式

首版不接受任何模式提示。若未来需要受限模式，必须另行设计并确认：

| 字段   | 类型       | 规则                                                       |
| ------ | ---------- | ---------------------------------------------------------- |
| `mode` | 当前不支持 | 首版仅接受空对象；不得据此自动打开新增弹窗或指定地址编辑器 |

工具使用严格空对象 schema；未知字段、`null`、数组、字符串、数字和嵌套任意对象均拒绝。工具参数不是 HTTP Controller 参数，不新增 Nest 路由或 Swagger DTO。

## 运行时事件

推荐首版沿用已有 SSE UI 请求协议，事件为：

```json
{
  "type": "address-form"
}
```

事件规则：

- 只在 SSE 工具集中注册；JSON 聊天首版不注册该工具。
- 事件只表达一次性导航意图，不表达页面已成功打开。
- 前端只能将事件映射到固定命名路由 `account-addresses`，不得执行模型提供的 URL 或路由。
- 同一轮只处理第一次有效请求，后续调用不再次发送或覆盖首次事件。
- 事件不写入聊天消息、公开展示 envelope、activity 自由 payload、长期记忆或数据库。
- 事件接收后必须检查当前活动会话和账号身份；会话切换、账号切换、页面卸载或事件过期时丢弃。

## 工具结果

工具结果只允许以下固定结构：

```json
{
  "ok": true,
  "code": "requested"
}
```

或：

```json
{
  "ok": false,
  "code": "unavailable"
}
```

结果字段白名单：

| 字段   | 类型    | 规则                                |
| ------ | ------- | ----------------------------------- |
| `ok`   | boolean | 固定成功/失败标志                   |
| `code` | 枚举    | 仅允许 `requested` 或 `unavailable` |

若后续确认携带 `mode`，结果最多附带已校验的 `mode` 枚举；不得附带地址内容或内部标识。`requested` 仅表示服务端接受请求，客户端导航成功或失败以浏览器实际结果和 Toast 为准。

## 错误行为

| 状态                                       | 行为                                                   |
| ------------------------------------------ | ------------------------------------------------------ |
| 非法输入、未知字段或未确认模式             | 工具拒绝，不设置 pending，不发 SSE                     |
| 认证/聊天上下文不可用                      | 返回 `unavailable`，不导航、不读写地址                 |
| SSE payload 未知字段、非法枚举或 JSON 损坏 | 前端丢弃，不导航                                       |
| 路由导航被取消或失败                       | 客户端固定失败反馈，不回传模型，不执行地址 CRUD        |
| 用户已切换会话或账号                       | 丢弃请求，不在新会话恢复                               |
| 同一轮重复调用                             | 仅首次有效调用生效                                     |
| 地址页面自身加载失败                       | 由地址页面按既有契约处理，导航工具不伪造数据或成功状态 |

工具错误不得泄露内部异常、用户身份、地址是否存在或地址页面 API 详情。

## 与地址 CRUD 的边界

- 地址列表、详情、新增、编辑、删除和默认地址设置完全复用[收货地址 CRUD 契约](./user-address-crud-contract.md)。
- 导航工具不调用地址 Repository、Entity、完整地址 DTO 或地址读取服务。
- 地址 `requestKey` 幂等、默认地址唯一性、并发冲突、订单收货快照和删除语义不因本工具改变。
- 用户在地址页面输入的任何字段只在本人认证前端和地址 API 之间流转，不进入模型上下文、通用聊天表单结果、导航事件或工具 trace。
- 地址工具不能从聊天自然语言自动创建、修改、删除地址，也不能将模型文字当作用户确认。

## 追踪、历史与生命周期

- trace 只允许记录工具名称和固定结果状态；首版不记录模式或原始工具参数。
- activity 输入和输出沿用现有安全投影，不保存原始参数或地址数据。
- 工具调用和结果如需在历史恢复时隐藏，应加入与其他内部 UI 请求工具一致的成对隐藏白名单；具体文件和实现方式留到技术阶段。
- pending 事件、前端 request id、路由结果和 Toast 只存在当前运行时，不跨刷新、会话切换或应用重启持久化。
- 地址导航请求不产生长期记忆来源、不改变偏好、不创建地址草稿或数据库记录。

## 不新增的接口与数据

- 不新增 HTTP 路由、Controller、DTO、Swagger schema 或公开 API。
- 不新增 Entity、字段、索引、Migration、Seeder、队列任务或外部依赖。
- 不新增地址动态表单注册类型，不复用 `request_dynamic_form` 绕过本阶段决策。
- 不改变 `/account/addresses` 页面现有加载、保存、删除、默认地址和错误处理。
