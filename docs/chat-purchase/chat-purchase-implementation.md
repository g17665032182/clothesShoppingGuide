## 交付范围

交付商品卡“购买”入口、本人会话持久化草稿、聊天补齐信息、服务端确认卡、显式按钮创建待支付订单、模拟支付和“我的订单”列表/详情/动作。

保持以下边界：单商品单 SKU、每会话至多一份活跃草稿、有效修改后 24 小时失效、订单 30 分钟支付期、账号和会话隔离。模型只能读改或放弃草稿；创建、支付、取消订单、确认收货均通过用户按钮。收货信息不进入长期记忆、新购买默认地址或结构化工具日志副本。

不交付真实支付、外部代购、购物车、地址簿、退款售后或前端多 SKU 合单。不增加运行时依赖，不安装前端测试框架，不新增前端测试脚本，不部署到外部环境。

## 子代理分工与文件所有权

实施采用三组子代理加主代理，最多四个角色同时活动。各代理负责其所属模块的生产代码和对应测试；主代理做独立集成复核与跨模块验收，不另设与模块测试文件冲突的并行测试作者。

仅在实施获批且协作工具可用时启动子代理；协作能力不可用时由主代理按相同边界分阶段串行完成，保留全部审查与验证要求，并在交付中说明实际执行方式，不因工具限制扩大权限或遗漏模块。

所有子代理必须阅读 AGENTS、PRD、设计、购买契约、技术文档和本文；额外阅读自己修改的订单、聊天或记忆契约。只能编辑分配范围，不自行扩大需求、修改已确认文档、安装依赖或操作普通开发数据库。必要注释使用中文，Native ESM 保留 `.js` 相对导入。

### A：订单和商品公开能力

**独占文件：**

- `apps/api/src/orders/**`，含订单模块内部接线、公开导出和测试。
- `apps/api/src/product-catalog/**`，含新增公开购买规格端口、模块导出和测试。

**任务与验收：**

- 新确认入口加入调用方事务，锁后、写入前检查价格/规格/商品身份、库存和草稿截止；新路径用实际数据库时间计算支付期。
- 保持既有幂等锁→SKU 升序→订单升序的顺序和派生预占，不新增预占表/计数，不从订单路径反向锁会话。
- 提供完整购买规格投影，测试超过默认分页大小时仍能正确判断单一/多个可售 SKU。
- 补充共享事务回滚、确认条件失败无订单写入、期限跨锁等待、旧 API/库存动作回归测试。

## 实施阶段与退出条件

### 阶段 0：基线与接口对齐

- 用户确认本文后，主代理记录工作区基线、现有测试状态及文件归属，明确隔离库命名。
- A 先提交订单/商品端口类型；B 提交展示引用与来源读取的内部类型；主代理提交草稿公开响应及会话访问入口；C 对齐前端响应类型。
- 主代理审阅依赖图、调用方事务传递及锁顺序后固定接口，再开始依赖实现。端口未实现期间可使用明确测试替身，不交付假成功占位接口。

退出条件：输入、输出、事务所有权、失败判别和公共导出一致，无模块循环依赖。

### 阶段 1：基础能力与独立开发

- A 完成订单共享创建核心和商品完整规格投影，并跑对应回归。
- B 完成投影/trace/历史/来源隔离及各自测试；与主代理对齐 ChatMessage 字段和消息保存入队条件。
- C 以冻结的响应类型实现 API 适配器、共用订单组件、购买页面交互和本人订单页。
- 主代理实现购买 schema、Entity、草稿生命周期、报价投影与工具工厂；确认服务只调用 A 的公开端口。

退出条件：各组局部验证通过，业务端口可集成；无越界修改、重复类型或私有 Entity 导入。

### 阶段 2：迁移与原子确认

- 汇总草稿 Entity 与消息资格字段后，主代理生成增量 Migration，审查活跃部分唯一索引、orderId 唯一/外键、状态 CHECK 和删除方向。
- 在隔离库验证完整迁移链，以及现有结构/旧消息/订单/幂等数据升级；保留正式订单，不使用清库替代升级。
- 接入会话锁→草稿→订单幂等→SKU→订单的确认路径，验证变价或到期只提交失效状态，不产生订单或预占。
- 覆盖 201/200、提交中断、原 submittedVersion 重试和成功后商品/期限变化；失败事务外恢复幂等，不在中止事务里继续查询。

退出条件：真实 PostgreSQL 证明单草稿至多一单、失败全回滚、业务失效可提交；迁移 SQL 与快照经审阅。

### 阶段 3：聊天、删除与前端集成

- 主代理接入购买每轮上下文与工具、JSON 最终 trace 序号、消息/引用同事务保存及 purchase→done 事件顺序。
- 购买轮次双消息写入不可提取标志并跳过记忆入队；在会话锁内复核轮次期间草稿变化，覆盖生成与购买竞争。
- 会话公开删除保留偏好用户锁前缀，再锁会话；内部取消清理不删除已开始购买的会话；旧内存对象不得复活已删除会话。
- 集成 `/account/orders` 懒加载路由及导航，复核新增路由下记忆/偏好导航不会错误高亮，保持全局鉴权规则。
- 接通卡片购买→询问→确认→订单动作，验证页面不依赖全部历史加载，网络未知结果只核实或重试原确认。

退出条件：带鉴权 API 与 fake 模型完成完整闭环，JSON/SSE/历史引用一致，账户/会话切换无旧响应污染。

### 阶段 4：回归、Smoke Test 与交付

- 执行自动化检查、指定数据库套件和带登录的 HTTP 主流程。
- 用可控测试账号和商品进行桌面/移动浏览器验证，覆盖刷新恢复、切路由、各异步状态和明确按钮动作。
- 复查日志与 trace、混合工具历史和记忆任务来源，核实收货信息没有新增结构化副本。
- 主代理更新实施结果与契约交叉说明，明确通过、失败、跳过、未执行及剩余缺口；不将计划清单批量标为完成。

退出条件：以下验收矩阵有实际证据；未完成项如实报告，不以构建通过代替浏览器/数据库验证。完成实现后启动本地开发服务并给出实际 URL；端口占用时另选端口。

## 验证命令与数据库隔离

```bash
pnpm format:check
pnpm --filter @clothes-shopping-guide/api typecheck
pnpm --filter @clothes-shopping-guide/api test
pnpm --filter @clothes-shopping-guide/api build
```
