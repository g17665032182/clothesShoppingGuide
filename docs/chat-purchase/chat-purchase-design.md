## 当前能力与复用

| 能力     | 已有事实                                                           | 本轮设计                                       |
| -------- | ------------------------------------------------------------------ | ---------------------------------------------- |
| 商品卡片 | 商品级 externalId，没有 skuId，仅支持外链和更多分页                | 增加购买事件，以商品标识发起草稿，再查真实规格 |
| 规格查询 | 有效 SKU 分页，返回颜色、尺码、精确单价及有货状态                  | 复用公开查询能力，不以卡片最低价作为下单价     |
| 订单     | 事务下单、幂等、库存、快照及本人动作均已存在                       | 复用订单规则，补充确认价格条件的原子核对能力   |
| 聊天     | 支持工具、流式结果与持久化展示投影                                 | 接入草稿查询与更新，展示结构化购买状态         |
| 用户页面 | 现有订单页面仅供管理员使用                                         | 增加本人列表与详情入口                         |
| 本地依赖 | 已有 Vue、Pinia、Axios、shadcn-vue、Zod、Nest、MikroORM、LangGraph | 优先复用；本阶段不决定增加新依赖               |

当前 `POST /api/orders` 不接受报价条件，锁定 SKU 后按当时价格创建订单。单纯“提交前再 GET 一次价格”不能保证用户确认后没有变价；本轮必须在正式订单事务内核对确认价格条件。

## 范围与角色

购买以当前账号、当前会话、单个商品和单个 SKU 为边界。普通用户及管理员都只能管理本人草稿和本人购买订单；管理员履约继续使用原独立入口。

访客和禁用账号禁止访问。草稿及引用的会话、订单必须分别校验归属，客户端不能指定 userId。不存在或越权统一为 404。

助手只能查询规格和草稿，更新已明确的信息，以及放弃未提交草稿。创建订单、模拟支付、取消正式订单和确认收货没有模型可调用的写工具，只由用户按钮触发业务接口。

## 商品选择与询问

1. 点击“购买”传递明确的商品 externalId 与会话标识，不通过模型解析商品名称来确定购买对象。
2. 历史卡片和“查看更多”追加卡片均可发起购买，服务端始终检查当前真实商品状态。
3. 查询全部当前有效规格，不能只读取默认第一页就宣称唯一规格。
4. 展示真实可选的颜色、尺码组合，禁止把颜色数组与尺码数组任意拼接成不存在的 SKU。
5. 一个可售规格可自动列入草稿，多个可售规格需要用户明确选择。数量初始为 1，用户可修改为 1–99。
6. 收货字段只能取用户在本次购买中明确提供或明确指定复用的信息。服装偏好可以帮助推荐，不能直接授权规格或收货信息选择。
7. 模糊描述不能唯一匹配规格、多个收货人不明确或字段非法时继续询问，不标记为可提交。
8. 无货时入口显示不可购买；历史有货但当前无货或下架时，服务端拒绝或返回阻止原因。

点击同商品且已有活跃草稿时恢复原草稿，不清空用户已填写信息。点击不同商品时先询问是否放弃原草稿；确认替换才在同一操作中终止旧草稿并创建新草稿。

## 草稿状态与有效期

| 状态         | 语义                               | 后续                             |
| ------------ | ---------------------------------- | -------------------------------- |
| `collecting` | 规格或收货信息不完整，或当前需修正 | 修改、准备确认卡、放弃、到期     |
| `ready`      | 信息完整，已形成当前版本确认快照   | 用户提交、修改、放弃、到期或失效 |
| `submitted`  | 已关联唯一正式订单                 | 查询订单，不再编辑或另建订单     |
| `cancelled`  | 用户放弃或确认替换                 | 终止，不恢复                     |
| `expired`    | 最后有效修改后满 24 小时           | 终止，提示重新发起               |

进行中仅包含 `collecting` 和 `ready`。每个账号的每个会话最多一份进行中草稿，不同会话独立。

时间均由服务端判定，`now >= expiresAt` 即失效。只有用户引起的有效信息修改才续期；恢复、轮询、重复同值更新、重新查询库存和报价均不续期。创建订单后使用订单自己的 30 分钟期限，草稿失效不能关闭已关联订单。

草稿必须独立持久化，不能只放在浏览器或依赖聊天文字、模型上下文及压缩摘要重建。服务端重启后可恢复。到期表示业务不可使用，不代表删除历史聊天或订单。

每次有效修改和确认条件变化都会推进草稿版本，旧版本确认卡立即失效。草稿部分收货字段允许尚未填写，但已写入字段须满足对应订单边界。

## 确认卡、价格与库存

确认卡展示商品、颜色、尺码、数量、真实 SKU 单价、CNY 商品总价、零运费、应付金额、收件人、手机号和完整地址。金额由服务端精确计算，页面不自行累计浮点金额。收货信息仅本人购买视图展示，界面应避免无意义重复回显。

用户点击“确认下单”必须提交当前草稿标识及确认版本。服务端读取本人草稿和已展示确认快照，再在正式创建事务中：

- 校验草稿状态、版本及有效期；
- 校验所选 SKU 仍有效，且商品、规格、币种和已确认单价一致；
- 校验数量与可售库存，按已有订单规则整单预占；
- 创建本人单 SKU 订单，并将草稿标记为 submitted、关联订单。

任意前置条件失败不得创建订单或预占库存。变价后刷新确认快照并要求重新点击；库存不足返回阻止原因，用户自行修改数量或规格；商品下架提示重新选择商品。不自动降数量、选替代规格或换商品。商品规格内容发生变化也必须重新确认。

价格及库存查询不构成锁价或库存承诺。只有成功创建订单才开始既有 30 分钟锁价与预占。

## 并发、重试与未知结果

- 草稿修改、放弃、替换及提交采用版本条件，过期请求返回 409，并提示重新读取当前状态。
- 下单幂等由服务端绑定草稿及本次已确认内容，客户端不能通过生成新键绕过同草稿只创建一单。
- 相同提交的成功重试返回关联订单当前状态；submitted 草稿不因超过草稿有效期而重新创建订单。
- 修改和提交竞争时，只能有一个依据原版本成功；不得订单已创建但草稿继续可编辑。
- 多标签页或并行聊天更新不能覆盖新版本，迟到的模型工具更新也受版本约束。
- 超时、断网、取消 HTTP 或缺少聊天 done 不能证明订单失败；先读取草稿与关联订单或重试同一次确认，不能换键重下。
- 聊天持久化和订单成功结果分别核实。模型回复、SSE done 或提示文本不能代替订单事务结果。

## 聊天展示与恢复

购买草稿、当前确认卡和关联订单通过独立业务投影展示。模型只负责自然语言询问和解释，不能生成可信的按钮参数、金额或成功状态。

流式生成期间和相同草稿的操作进行中，前端禁止互相冲突的提交。结构化卡片只有经服务端确认持久化后才显示为可操作；JSON、历史消息及 SSE 通过购买引用关联业务状态，字段见契约，不把完整收货快照复制到通用展示投影。

恢复会话时独立读取最新草稿及关联订单，重查当前商品与规格。历史确认卡只作为历史展示，不能直接提交旧版本；历史订单卡重新读取本人订单后按最新状态显示动作。购买流程不依赖完整历史均已加载。

2026-11-09 根据用户反馈，购买表单、确认信息和关联订单改用 shadcn-vue Dialog 交互。点击商品“购买”时打开弹框，聊天顶部保留“本次购买”入口；关闭后重开保留当前会话未保存的输入。切换会话或账号时关闭弹框并隔离输入，查看订单时由订单详情弹框接替。弹框内容独立滚动，覆盖移动端、加载、提交及失败重试状态。

非购买聊天继续正常使用。生成中切换会话或路由沿用现有后台任务行为，购买结果只能更新所属账号、会话及草稿。账号变化清理前端缓存，不能把上一账号收货信息显示给下一账号。

## 我的订单与操作

在账号导航增加“我的订单”，支持分页、状态筛选、订单号精确查询、详情和物流快照。列表使用已有摘要；详情再加载商品明细与收货信息，不为展示修改订单列表泄露范围。

| 状态           | 可见业务操作                                     |
| -------------- | ------------------------------------------------ |
| 待支付且未到期 | 模拟支付、取消订单                               |
| 待支付但已到期 | 禁用支付，重新读取状态，按服务端到期处理结果展示 |
| 待发货         | 查看详情                                         |
| 待收货         | 确认收货、查看物流快照                           |
| 已完成或已关闭 | 查看详情与关闭原因                               |

模拟支付始终明确标注不真实扣款。取消订单和确认收货通过明确确认交互执行，不能从普通“取消本次购买”聊天意图调用正式订单取消。

各页面及业务卡片覆盖 idle、loading、success、empty、error 和提交中/提交失败；请求取消、过期响应保护、按钮防重、键盘操作、移动端布局沿用项目规范。

## 数据、隐私与删除

- 收货信息只用于当前草稿和订单快照，不写入结构化服装偏好、记忆 Markdown 或新购买默认地址。
- 用户主动发出的聊天文本按现有规则保存；不承诺草稿到期或放弃会擦除已发送聊天。
- 工具活动、结构化内部工具 trace 和普通请求日志不得新增明文收货字段副本；草稿工具参数及结果必须按专属白名单处理，后续模型从本人当前草稿取得所需状态。用户原始聊天文本仍按既有聊天及 trace 规则保存。
- 管理员原聊天只读权限和订单管理权限保持现状，不新增管理员读取草稿接口。
- 删除本人会话时移除该会话购买草稿与展示关联；已创建订单及订单幂等记录保留，仍能在“我的订单”访问。
- 会话删除与确认提交竞争时必须串行确定结果；先删除则不能再下单，先提交则保留订单。
- 本轮不新增到期后归档或定期清理策略，不改变既有聊天和订单保存规则。

## 模块边界与兼容性

- 购买编排能力所有草稿状态、版本、确认条件和订单关联，通过公开入口组合聊天归属、商品规格和订单能力。
- `orders` 仍所有正式订单、金额、库存协作、幂等和状态转换；确认价格检查必须处于订单创建一致性边界中。
- `product-catalog` 仍所有商品、SKU 和库存事实；购买模块不直接引用其 Entity 或 Repository。
- `chat-records` 所有会话权限、消息、公开展示和删除协作；`llm` 保持通用，不直接操作订单数据库。
- 前端 API 适配器、类型与页面解耦；购买卡片和订单共用组件按实际复用范围放置，遵守页面 `index.vue`、`page.ts`、`components/` 结构。
- 复用现有 Zod、Nest 参数校验、JWT 和角色机制；不增加第二套验证或认证。
- 旧订单创建 API、空 Body 动作、商品搜索及分页保持兼容；聊天购买确认入口独立，不把历史商品卡片当作 SKU 订单输入。
- 现有系统上下文“不能下单”边界将在实施阶段收窄为“只能协助准备草稿，正式订单动作由用户按钮执行”；售后仍未接入。
- 持久化需增量 Migration，保留全部历史商品、聊天、订单及幂等记录；不执行清库验证。
