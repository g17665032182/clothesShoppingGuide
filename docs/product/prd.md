## 2. 产品概述

服装购物指南是一款帮助用户更高效完成服装选择、搭配和购买决策的产品。产品后端采用 NestJS、MikroORM 和 PostgreSQL，当前优先建设账户、认证和可扩展的服务端模块边界。

本 PRD 只定义产品目标和第一阶段可执行范围，不将尚未确认的商品、推荐、穿搭或大模型能力视为已交付功能。

## 3. 用户问题

### 3.1 核心问题

- 用户面对大量服装商品时，难以快速判断是否适合自己的需求。
- 商品信息、个人偏好和购买决策之间缺少统一的组织方式。
- 后续如果引入智能推荐，产品需要可靠的账户、权限和服务端能力作为基础。

### 3.2 当前阶段要解决的问题

第一阶段先解决账户和访问控制问题：

- 用户可以安全注册和登录。
- 已登录用户可以查看和维护自己的资料。
- 管理员可以管理用户状态和角色。
- 被禁用的用户无法继续使用已有 Token 访问受保护接口。

## 4. 产品目标与非目标

### 4.1 产品目标

1. 建立稳定的用户身份和权限基础。
2. 为后续商品、穿搭和推荐模块提供清晰的模块边界。
3. 保证核心 API 具备一致的输入校验、错误响应和安全行为。
4. 在产品需求确认后，逐步接入面向服装购物决策的业务能力。
5. 在用户明确可控和隐私边界下，为后续服装导购提供跨会话的个性化记忆能力。

### 4.2 本阶段非目标

- 商品库、品牌库和库存同步。
- 个性化推荐算法和排序策略。
- 穿搭方案生成和图片识别。
- 订单、支付、物流和售后。
- 邮箱验证、密码找回、多因素认证、刷新 Token 和第三方登录。
- RAG、Agent、多模型路由和流式输出。

## 7. 关键用户流程

### 7.1 注册与登录

```text
访客
  -> 提交注册信息
  -> 服务端校验并创建用户
  -> 返回 JWT 和用户信息
  -> 使用 JWT 访问受保护资源
```

登录失败时不得泄露邮箱是否存在等额外账户信息；邮箱重复返回冲突错误，非法凭据返回未认证错误。

### 7.2 个人资料维护

```text
登录用户
  -> 获取当前资料
  -> 修改昵称或密码
  -> 服务端校验
  -> 返回更新后的脱敏资料
```

密码只保存哈希值，响应中不得返回明文或哈希。

### 7.3 管理员禁用用户

```text
管理员
  -> 查看用户
  -> 修改用户状态为 disabled
  -> 用户下一次受保护请求重新校验状态
  -> 原有 JWT 立即失效
```

## 8. 功能需求

### 8.1 认证需求

| 编号     | 需求                           | 验收标准                               |
| -------- | ------------------------------ | -------------------------------------- |
| AUTH-001 | 用户可使用邮箱、密码和昵称注册 | 合法请求返回 `201`、JWT 和脱敏用户信息 |
| AUTH-002 | 邮箱必须唯一且统一转为小写     | 重复邮箱返回 `409`                     |
| AUTH-003 | 用户可使用邮箱和密码登录       | 成功返回 `200`；非法凭据返回 `401`     |
| AUTH-004 | 受保护接口必须校验 Bearer JWT  | 缺失、无效或过期 Token 返回 `401`      |
| AUTH-005 | 禁用用户不能继续访问受保护接口 | 禁用后使用旧 Token 返回 `401`          |

### 8.2 用户资料需求

| 编号     | 需求                             | 验收标准                               |
| -------- | -------------------------------- | -------------------------------------- |
| USER-001 | 用户可查看自己的资料             | 仅返回允许公开的用户字段               |
| USER-002 | 用户可更新昵称或密码             | 非法输入返回 `400`，省略字段表示不修改 |
| USER-003 | 普通用户不能修改角色和状态       | 尝试越权返回 `403` 或被拒绝            |
| USER-004 | 管理员可查看用户列表和详情       | 非管理员访问返回 `403`                 |
| USER-005 | 管理员可更新用户角色、状态和昵称 | 目标用户不存在返回 `404`               |

### 8.3 通用大模型需求（后续 P1）

| 编号    | 需求                                       | 验收标准                                        |
| ------- | ------------------------------------------ | ----------------------------------------------- |
| LLM-001 | 登录用户可发起一次文本调用并保存当前轮记录 | `POST /api/llm/chat` 返回统一内容结构及会话信息 |
| LLM-002 | 客户端不能覆盖模型、温度、超时或 API Key   | 模型配置只从服务端环境变量读取                  |
| LLM-003 | 模型错误统一转换                           | 配置缺失、超时和上游错误分别返回约定状态码      |
| LLM-004 | 用户可回看自己的聊天会话，管理员可分页查询 | 用户接口按归属隔离，管理员接口只读              |

### 8.4 用户长期记忆需求（规划）

| 编号       | 需求                                               | 验收标准                                     |
| ---------- | -------------------------------------------------- | -------------------------------------------- |
| MEMORY-001 | 登录用户可以跨会话使用自己的服装长期记忆           | 其他用户、游客和管理员无法读取该用户记忆原文 |
| MEMORY-002 | 系统从文本聊天中静默提取明确、稳定、服装相关的信息 | 临时意图、低置信度推测和敏感内容不落库       |
| MEMORY-003 | 用户可以查看、手动新增、修改和删除记忆             | 管理页展示结构化内容、更新时间和来源状态     |
| MEMORY-004 | 用户可以在聊天中用自然语言修改或删除记忆           | “忘记某偏好”等明确指令只影响本人记忆         |
| MEMORY-005 | 用户可以关闭记忆功能或删除全部记忆                 | 关闭停止提取和注入；删除全部不删除聊天记录   |
| MEMORY-006 | 当前消息优先级高于长期记忆                         | 临时要求覆盖本轮推荐且不污染长期记忆         |
| MEMORY-007 | 记忆提取异步执行且支持幂等重试                     | 模型或任务失败不阻断当前聊天，不产生重复记忆 |
| MEMORY-008 | 账号删除清理全部长期记忆                           | 删除后不能通过任何普通接口恢复               |

## 10. 数据与安全要求

- 用户邮箱建立唯一约束。
- 密码使用 `bcryptjs` 哈希后保存，禁止返回密码字段。
- JWT 密钥只从服务端环境变量读取，生产环境必须替换默认值。
- 认证和授权职责分离：`auth` 负责身份认证，`authorization` 负责角色授权。
- 用户禁用采用逻辑状态，不物理删除用户。
- 后端输入统一使用 Zod schema 校验并拒绝未声明字段。
- 日志和错误响应不得暴露 API Key、密码、完整供应商响应或敏感凭据。
- 数据库迁移和 Seeder 必须可重复执行，Seeder 管理员配置由环境变量控制。
- 用户长期记忆按用户隔离，管理员和客服默认不能读取记忆原文。
- 记忆只保存服装相关、明确表达的结构化数据，不复制完整聊天原文。
- 关闭记忆停止新的提取和注入；删除账号时同步清理该账号的长期记忆。

## 11. 非功能需求

### 11.1 可维护性

- 应用放在 `apps/`，共享能力放在 `packages/`。
- 模块按认证、授权、用户和后续业务域拆分，避免跨模块引用私有实现。
- 新增业务逻辑必须补充所属包测试。

### 11.2 可验证性

- 提交前执行 `pnpm check`。
- 认证、授权、非法输入和禁用 Token 行为必须有自动化测试或可复现的 HTTP 验证记录。
- LLM 自动化测试使用 Fake Chat Model，不依赖真实 API Key 和外部网络。
- 用户长期记忆必须补充合法/非法输入、未知字段、默认值或转换、越权、来源删除、提取失败和幂等重试验证。

### 11.3 可扩展性

- 商品、穿搭、推荐和 LLM 模块不得直接耦合用户 Entity 的内部实现。
- 后续扩展优先通过公开 Service 接口和稳定 DTO 接入。
- 第一阶段不为尚未确认的业务提前建立数据库表。
- 用户长期记忆作为独立业务模块建设，不直接写入聊天记录模块的 Entity 或内部 trace。

以下问题会影响后续产品设计，当前不做默认假设：
