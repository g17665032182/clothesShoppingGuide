# 服装导购体系设计文档

## 状态与上下文

- 状态：待用户确认。
- 业务目的：帮助消费者根据场合和个人需求，从本地商品目录中找到适合购买决策的服装与鞋类。
- 所属应用：后端 `apps/api`；聊天交互位于 `apps/web`。
- 最后更新：2026-11-05。
- 关联契约：[商品目录 CRUD 契约](../contracts/product-catalog-crud-contract.md)。

## 目标与范围

首期围绕“特定场合穿什么”提供从需求澄清到真实商品推荐的聊天体验：

1. 用户通过聊天描述场合、预算、尺码或其他需求。
2. 系统复用用户已保存的服装偏好；缺少影响筛选的条件时，优先追问一个关键问题。
3. LLM 将当前对话和偏好转换为结构化查询，通过商品查询工具调用后端商品服务。
4. 商品服务基于本地 PostgreSQL 目录执行确定性筛选和排序。
5. 聊天中最多展示三件真实有效商品及结构化匹配理由；用户可以查看详情、换一批或查看更多。
6. 严格条件没有结果时，说明结果为空并询问用户是否放宽指定条件，不自动降低条件。

首期目录包含成人服装和鞋类。商品按商品主记录与 SKU 分离，SKU 承载颜色、尺码、价格、库存和图片 URL。

## 用户角色和权限

| 角色             | 能力                                     |
| ---------------- | ---------------------------------------- |
| 已登录消费者     | 查询可推荐商品；通过聊天发起推荐         |
| 开发或运营维护者 | 准备商品 JSON 文件并在服务端运行导入命令 |
| 未登录访客       | 不使用商品查询及个性化推荐能力           |

首期不提供商品管理后台、商品写入 API 或管理员商品操作 API。商品写入只通过内部 CLI 进行。

## 推荐规则

- 明确提出的预算上限/下限、尺码和有货要求作为硬筛选条件。
- 颜色、风格、场合、版型及已有偏好作为排序信号；用户明确要求必须满足时才转成硬筛选。
- 服务端返回有限、结构化的匹配标签。LLM 可以改写解释，但不得增加查询结果中不存在的商品属性或匹配事实。
- 每次最多返回三件；“更多”和“换一批”保持原筛选条件，使用同一查询的游标继续取数。
- 用户改变条件时创建新的查询。
- “比较商品”、收藏、购物清单、购买和售后不在首期范围。

## 商品展示

聊天商品卡片包含商品图片、名称、当前价格、匹配理由和详情入口。详情入口使用导入数据中的商家商品 URL；URL 缺失或无效时不展示入口。无可用图片时使用前端已有的空图展示方式，不伪造图片地址。

“更多/换一批”应由服务端可验证的查询游标承载，不信任客户端提交的商品过滤条件变更。查询是否跨请求持久化以及游标的具体生命周期在技术阶段确定。

## 数据与导入行为

- 使用项目当前 PostgreSQL 连接，新建独立商品模块和商品、SKU 数据表。
- 使用版本化 JSON 作为导入格式。
- `externalId` 在数据源中唯一；`externalSkuId` 在商品内唯一。
- 再次导入同一标识时更新对应记录，不存在时新增。
- 商品和 SKU 下架后保留记录，但不可参与推荐。
- 一个文件必须先完整校验；任何错误都使整批写入失败。校验通过后通过数据库事务导入。
- 仓库提供开发/测试 fixture；生产启动和普通 seed 不自动导入 fixture。
- 图片保存为可访问 URL，首期不接对象存储。

文件缺少已有商品、下架字段默认值、SKU 被省略时的处理等增量导入语义，在确认前不得按静默删除或清空实现；具体默认规则列于 CRUD 契约待确认项。

## 模块边界

- `product-catalog` 所有商品和 SKU 的持久化、导入、可售状态、查询、筛选、排序与匹配标签生成。
- LLM 模块保持通用，通过现有工具注册入口注入由商品模块公开提供的查询工具。
- 聊天模块负责组合用户上下文、调用 LLM 工具链和保存可展示的商品卡片投影，不直接访问商品 Entity 或 Repository。
- 用户偏好模块通过公开查询入口读取偏好，不导入其 Entity 或 Repository。
- 前端通过现有聊天消息公开展示结构渲染商品卡片，不请求或依赖后端 Entity。

禁止跨模块引用私有 Entity、Repository、DTO 或实现目录。商品查询工具只返回允许公开的商品字段、可用 SKU 状态、匹配标签和合法详情 URL。

## 明确非目标

- 第三方平台商品抓取或同步。
- 订单、支付、物流、真实购买操作或库存扣减/锁定。
- 商品运营后台或管理员写入 API。
- 配饰、儿童商品、收藏、比较、购买清单。
- 图像识别、RAG、向量数据库或生成式商品属性。
- 自动放宽预算、尺码或库存硬条件。

## 验收标准

- 已登录用户可通过聊天触发真实目录查询，未登录请求受现有认证保护。
- CLI 导入严格校验 JSON，任何无效记录都不产生部分写入；重复导入稳定更新。
- 推荐结果只包含有效商品及满足硬条件的可用 SKU，不编造价格、库存、图片和链接。
- 匹配排序确定且返回结构化理由；聊天一次最多展示三件。
- “更多/换一批”沿用原查询条件且不重复已展示商品；改变条件产生新查询。
- 无结果时保持硬条件并请求用户明确放宽。
- 商品 Entity 不跨模块泄漏，迁移、导入、查询、权限和聊天工具链均有自动化测试。
- fixture 仅用于开发/测试，不会被生产自动导入。
