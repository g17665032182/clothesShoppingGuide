# 模块文档模板

以下是通用起始模板。根据仓库和模块实际情况调整，不要为了匹配模板保留空章节。

## 设计文档

```markdown
# <模块名称>设计文档

## 状态与上下文

- 状态
- 业务目的
- 所属应用和负责人
- 最后更新

## 范围

- 包含的操作
- 明确不包含
- 用户角色和权限

## API 或事件契约

- 输入
- 输出
- 错误
- 认证方式

## 数据和行为

- 实体或外部资源
- 校验规则
- 幂等和并发
- 删除或重试语义

## 模块边界

- 模块职责
- 依赖关系
- 禁止耦合

## 验收清单
```

## 技术文档

```markdown
# <模块名称>技术文档

## 实现目标

## 包和目录结构

## 依赖和官方文档

## 接口和依赖注入

## 状态、流程或持久化

## DTO、校验和错误映射

## 安全和可观测性

## 测试方案

## 验证命令
```

## 实施文档

```markdown
# <模块名称>实施文档

## 开发流程总览

## 子代理角色和文件所有权

## 子代理开始前检查

## 子代理完成报告

## 主代理集成任务

## 按顺序排列的实施阶段

## 验收标准

## 风险和停止条件
```

## 命名和位置

同一个业务的所有文档放在一起：

```text
docs/<业务名>/
```

三份文档之间使用相对链接。设计、技术和实施决策分开记录，方便在正确的层级审查和修改。
